# OHT 위치 계산 가이드

## 1. 왜 위치 계산이 필요한가?

MCS에서 보내주는 OHT 데이터에는 **좌표(x, y)가 없습니다.**

MCS가 알려주는 것:
```
"V00795 차량이 12340번지에서 12341번지로 이동 중, 1.4m 진행"
```

화면에 OHT를 표시하려면 **"12340번지가 FAB 어디에 있는지"** 알아야 합니다.
이 정보가 바로 `layout.xml` (레일 지도)에 들어있습니다.

```
layout.xml (레일 지도)          OHT 데이터 (MCS)
┌─────────────────────┐      ┌──────────────────────┐
│ 12340번지 = (500,200) │      │ 현재번지: 12340       │
│ 12341번지 = (600,200) │  +   │ 거리: 14 (1.4m)      │
│ 12342번지 = (700,200) │      │ 다음번지: 12341       │
└─────────────────────┘      └──────────────────────┘
           │                            │
           └──────────┬─────────────────┘
                      ▼
              위치 계산 결과
           OHT 좌표: (501.4, 200)
           → 화면에 이 위치에 표시
```

## 2. 위치 계산 원리

### 2.1 노드(번지)란?

OHT 레일 위에 일정 간격으로 설치된 **위치 기준점**입니다.

```
[12340] ────────── [12341] ────────── [12342]
   │                  │                  │
   번지               번지               번지
   (x:500, y:200)    (x:600, y:200)    (x:700, y:200)
```

- FAB 전체에 약 **9,400개** 노드가 있습니다
- 각 노드는 **고유 번호**와 **좌표(x, y)**를 가집니다
- 노드와 노드는 **레일로 연결**되어 있습니다

### 2.2 OHT 위치 = 두 노드 사이 보간

OHT는 항상 **두 노드 사이 레일 위**에 있습니다.

```
현재번지(12340)              다음번지(12341)
   ●━━━━━━━━●━━━━━━━━━━━━━━━━━●
   |← 1.4m →|
   |  거리=14 |
   |         |
   여기가 OHT 위치
```

**계산 방법:**
```
1. 현재번지 좌표 조회:  12340 → (500, 200)
2. 다음번지 좌표 조회:  12341 → (600, 200)
3. 두 노드 사이 거리:   100m
4. 이동 비율 계산:      1.4m ÷ 100m = 1.4%
5. 보간(Interpolation):
   x = 500 + (600-500) × 1.4% = 501.4
   y = 200 + (200-200) × 1.4% = 200.0

결과: OHT 위치 = (501.4, 200.0)
```

### 2.3 시간에 따른 이동

0.5초마다 MCS에서 새 데이터가 오면 거리가 변합니다:

```
시간   현재번지  거리   다음번지   계산좌표         화면
─────────────────────────────────────────────────────
0.0초  12340    14    12341    (501.4, 200)    ●
0.5초  12340    19    12341    (501.9, 200)     ●
1.0초  12340    24    12341    (502.4, 200)      ●
  :                                              :
47초   12340    949   12341    (600.0, 200)              ●  ← 12341 도착
47.5초 12341    5     12342    (600.5, 200)               ●  ← 다음 엣지 시작
```

**거리가 증가 → 좌표가 변함 → 화면에서 OHT가 이동하는 것처럼 보임**

## 3. 필요한 파일

### 3.1 layout.xml (필수)

MCS(다이후쿠)에서 관리하는 **레일 지도 파일**입니다.

- **위치**: MCS 서버의 layout 폴더 또는 `A.layout.zip` 안에 포함
- **내용**: 노드 좌표 + 노드 연결 정보 (약 240만 줄)
- **용도**: 번지 번호 → 좌표(x, y) 변환에 사용

```
MAP/
  M14A/                  ← FAB 이름
    A.layout.zip         ← 이 파일을 받으면 됩니다
    A.layout/
      layout.xml         ← 핵심 파일 (zip 풀면 나옴)
```

### 3.2 layout_cache.json (자동 생성)

layout.xml은 240만 줄이라 매번 읽으면 느립니다 (6초).
최초 1회 JSON으로 변환하면 **이후 0.06초**만에 로드됩니다.

```bash
# layout.xml → layout_cache.json 변환 (최초 1회)
python oht_position.py convert A.layout.zip

# 또는
python oht_position.py convert MAP/M14A/A.layout/layout.xml
```

## 4. 사용 방법

### 4.1 명령어로 확인

```bash
# 특정 번지 좌표 확인
python oht_position.py node 12340
  → 번지: 12340
  → 좌표: (11227.86, 1205.86)
  → 연결: [12341] (거리 949 = 94.9m)

# OHT 위치 계산
python oht_position.py calc 12340 14 12341
  → 계산 위치: (11227.86, 1204.46)

# 실제 OHT 메시지로 위치 계산
python oht_position.py parse "2,OHT,V00795,1,1,0000,1,12340,14,12341,..."
  → 차량: V00795
  → 계산 위치: (11227.86, 1204.46)
  → 목적지: 4ANZ19-701
```

### 4.2 코드에서 사용

```python
from oht_position import OHTPosition

# 초기화 (layout_cache.json 로드)
pos = OHTPosition()

# 위치 계산
x, y = pos.calc(현재번지=12340, 거리=14, 다음번지=12341)
print(f"OHT 위치: ({x}, {y})")

# OHT 메시지에서 바로 계산
result = pos.calc_from_message("2,OHT,V00795,1,1,0000,1,12340,14,12341,...")
print(f"차량 {result['vehicleId']}: ({result['x']}, {result['y']})")
```

## 5. OHT 메시지 포맷

MCS에서 보내는 VHL_STATE_REPORT 메시지 (콤마 구분, 21개 필드):

```
2,OHT,V00795,1,1,0000,1,12340,14,12341,4,4,4PDMV608,36073,00000000,0000,4ABL3301A_OUT04,4ANZ19-701,90,0,0
```

| 위치 | 필드명 | 예시 | 설명 |
|------|--------|------|------|
| [0] | MessageId | 2 | 메시지 타입 (항상 2) |
| [1] | McpName | OHT | 장비 타입 (항상 OHT) |
| [2] | VehicleId | V00795 | 차량 ID |
| [3] | State | 1 | 상태 (아래 표 참조) |
| [4] | IsFull | 1 | 적재 여부 (0=빈차, 1=적재) |
| [5] | ErrorCode | 0000 | 에러 코드 |
| [6] | IsOnline | 1 | 온라인 여부 |
| **[7]** | **CurrentAddress** | **12340** | **★ 현재 번지 (위치 계산 핵심)** |
| **[8]** | **Distance** | **14** | **★ 이동 거리 (100mm 단위, 14=1.4m)** |
| **[9]** | **NextAddress** | **12341** | **★ 다음 번지 (위치 계산 핵심)** |
| [10] | RunCycle | 4 | 운행 사이클 |
| [11] | VhlCycle | 4 | 실행 사이클 |
| [12] | CarrierId | 4PDMV608 | 캐리어(FOUP) ID |
| [13] | Destination | 36073 | 목적지 노드 |
| [14] | EMState | 00000000 | EM 상태 |
| [15] | GroupId | 0000 | 그룹 ID |
| [16] | SourcePort | 4ABL3301A_OUT04 | 출발 스테이션 |
| [17] | DestPort | 4ANZ19-701 | 도착 스테이션 |
| [18] | Priority | 90 | 우선순위 |
| [19] | DetailState | 0 | 상세 상태 |
| [20] | RunDistance | 0 | 누적 이동 거리 |

### 차량 상태 코드 (State)

| 코드 | 상태 | 설명 |
|------|------|------|
| 1 | RUN | 운행 중 |
| 2 | STOP | 정지 |
| 3 | ABNORMAL | 이상 |
| 4 | MANUAL | 수동 |
| 6 | OBS_BZ_STOP | 장애물 정지 |
| 7 | JAM | 정체 |

## 6. 데이터 전송 방법

### 방법 1: HTTP API (권장)

MCS 시스템에서 직접 HTTP로 전송:

```
POST http://서버IP:10003/api/oht-raw
Content-Type: application/json

{
  "messages": [
    "2,OHT,V00795,1,1,0000,1,12340,14,12341,4,4,...",
    "2,OHT,V00564,6,1,0000,1,2115,9,2116,4,4,..."
  ]
}
```

### 방법 2: 붙여넣기

```bash
python data_sender.py → 2번 선택 → OHT 메시지 붙여넣기 → 엔터
```

### 방법 3: UDP 수신

```bash
python data_sender.py → 3번 선택 → UDP 포트 대기
```
MCS에서 UDP로 전송하면 자동 수신.

## 7. 요약

```
고객이 준비할 것:
  1. layout.xml (또는 A.layout.zip)  ← MCS에서 받기
  2. OHT 데이터                      ← MCS에서 자동 출력

우리 시스템이 하는 것:
  1. layout.xml → JSON 변환 (최초 1회)
  2. OHT 데이터 수신
  3. 번지 번호 → 좌표(x,y) 자동 계산
  4. 화면에 OHT 표시 + CSV 저장
```
