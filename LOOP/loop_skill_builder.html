"AI한테 매번 시키지 말고, AI를 시키는 시스템을 짜라." — 프롬프트를 짜던 자리에서 빠져나와 루프(트랙)를 설계한다.

① 스킬 정체성 — 인수인계 노트(③ 스킬)

세션이 바뀌면 맥락은 백지가 된다. 스킬은 도메인 지식을 파일에 박아두고 루프가 매번 다시 읽게 한다.

② 자율성 슬라이더 — Karpathy: "Iron Man 슈트, 로봇이 아니라"

사람이 매 스텝 엔터 누르는 쪽 ↔ 완전 자율 사이를 미끄러뜨린다. 한 번에 한 칸씩, 검증이 따라올 수 있는 만큼만 자율을 올린다.
수동보조부분자율감독완전
L3 · 부분자율

③ 루프 사양 (LoopSpec)

실전 트릭: closed 하드체크를 바닥으로 깔고 그 위에 open 지시 하나 → 기준 밑으론 안 떨어지는 탐색.

④ Verifier — 루프의 병목 = reward function

generator는 거의 공짜로 반복된다. 결과가 가치 있는지 판정하는 verifier가 루프의 전부다. 여기에 당신의 도메인 지식을 박는다.
+ 체크 추가

⑤ 모델 — 짓는 AI vs 검사하는 AI

자기채점은 부풀려진다(실측 9.04 vs 7.43). generator와 verifier를 다른 모델 계열로 분리하라.
⚠ self-bias: generator와 verifier가 같은 모델 계열이다. 점수가 부풀려질 수 있다 — 평가자를 분리하라.

이 빌더의 설계 축은 Andrej Karpathy의 "Software Is Changing (Again)" 논지와 loop_engine 6부품을 1:1로 엮은 것이다.


        
1. Software 3.0 — "영어가 가장 핫한 프로그래밍 언어"

        
코드(1.0) → 신경망 가중치(2.0) → 프롬프트(3.0). 이제 자연어 프롬프트가 프로그램이다.

        
→ 빌더 매핑: goal·rubric·SKILL.md 본문이 곧 "코드". 그래서 goal을 측정 가능하게 쓰는 게 컴파일 조건이다.


        
2. LLM = 새로운 운영체제/컴퓨터

        
LLM은 CPU, 컨텍스트 윈도우는 RAM. 매번 비싼 부팅(맥락 재설명) 대신 디스크에 상태를 남겨라.

        
→ 매핑: ⑥ 상태/기억(ArtifactStore·WorkLog·Signal). "에이전트는 잊어도 저장소는 안 잊는다."


        
3. 자율성 슬라이더 — "Iron Man 슈트지 로봇이 아니다"

        
완전 자율을 한 방에 주지 마라. 증강(슈트)에서 시작해 자율을 한 칸씩 올린다.

        
→ 매핑: 위 자율성 슬라이더가 mode/max_rounds/트리거를 함께 움직인다. L1=사람이 엔터, L5=cron 완전자율.


        
4. generation ↔ verification 루프를 빠르게, AI를 목줄에 묶어라

        
생성은 싸다. 병목은 검증이다. 검증 루프를 빠르게 돌리고, 큰 diff를 통째로 삼키지 말고 작게 끊어 검증하라.

        
→ 매핑: ④ Verifier = reward function. 하드 체크(즉답 yes/no) + 루브릭(품질 바). verifier가 약하면 루프는 쓰레기를 자신있게 수백 번 만든다.


        
5. 부분 자율 앱 — GUI로 감사 속도를 높여라

        
사람이 빠르게 검증하도록 결과를 시각화하고, 자율 범위를 조절 가능한 앱을 만든다.

        
→ 매핑: 바로 이 HTML 빌더 + 러너의 run_dir/report(). 라운드별 산출물·평결이 파일로 남아 사람이 감사한다.


        
냉정한 현실 (Addy Osmani, README)

        
검증은 여전히 사람 몫이다. 산출물을 안 읽으면 이해도는 떨어진다. 가장 큰 위험은 인지적 항복이다.
