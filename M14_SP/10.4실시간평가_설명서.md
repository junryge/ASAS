# V10.4 실시간 예측 시스템 - 코드 설명서

## 개요

`10.4실시간평가.PY`는 M14 TOTALCNT 1700+ 돌파를 10분 전에 예측하는 실시간 시스템이다.
V10.4 모델(XGBoost 회귀 + LightGBM 분류 + 투표)과 UI 급증/상태 분석을 결합했다.


## 실행 방법

```bash
python 10.4실시간평가.PY
```

### 필요 파일

| 파일 | 경로 | 설명 |
|------|------|------|
| 모델 | `models/v10_4_m14_model.pkl` | V10.4 학습 모델 (XGB+LGBM+스케일러) |
| 데이터 | `data/2025_DATA.CSV` | 실시간 CSV (8.3.1과 동일) |


## 출력 형식

```
prediction: 1,685
status: CRITICAL
status_Th: BOTTLENECK_EXPECTED
prediction_time: 2026-03-03 14:30
1700+ danger_probability: 75%
spike_info: D:M14AM14B +65, D:M14AM14BSUM +72
danger_count: 2, warning_count: 1
```


## 출력 필드 설명

| 필드 | 설명 |
|------|------|
| `prediction` | 10분 후 TOTALCNT 예측값 (앙상블 평균) |
| `status` | **기존 판정** - 10.4평가 투표+규칙 기반 (LOW / NORMAL / CAUTION / CRITICAL) |
| `status_Th` | **심층 판정** - UI 급증+현재값+예측값 종합 (NORMAL=양호예상 / OBSERVATION=관찰 / DANGER_EXPECTED=위험예상 / BOTTLENECK_EXPECTED=병목예상 / BOTTLENECK(1700_PREDICT-10min)=병목(1700예측-10분)) |
| `prediction_time` | 예측 대상 시점 (현재 + 10분) |
| `danger_probability` | 1700+ 돌파 위험 확률 (0~100%) |
| `spike_info` | 급증 컬럼 정보 (D=danger, W=warning) |
| `danger_count` | danger 급증 컬럼 수 |
| `warning_count` | warning 급증 컬럼 수 |

## status (기존 판정) - 10.4평가 투표+규칙 방식

V10.4 모델의 투표 결과와 5가지 규칙으로 판정한다.

### 투표 구성

- XGB 타겟 예측 >= 1700 → 1표
- XGB 중요 예측 >= 1700 → 1표
- XGB 보조 예측 >= 1700 → 1표
- LGBM 타겟 분류 결과 (0 or 1)
- LGBM 중요 분류 결과 (0 or 1)
- LGBM 보조 분류 결과 (0 or 1)
- (PDT 모델 있으면 +2표 추가)

### 최종 판정 규칙 (하나라도 충족 시 danger=1)

| 규칙 | 조건 |
|------|------|
| rule1 | 투표 합계 >= 3 |
| rule2 | LGBM 중요 확률 >= 0.50 AND 현재값 >= 1450 |
| rule3 | XGB 중요 예측 >= 1680 AND 현재값 >= 1500 |
| rule4 | 현재값 >= 1600 AND 투표 합계 >= 2 |
| rule5 | XGB 중요 예측 >= 1700 |

### status 판정

| status | 조건 |
|--------|------|
| `CRITICAL` | final_pred_danger == 1 (위 규칙 중 하나 이상 충족) |
| `CAUTION` | 앙상블 예측 >= 1600 또는 (현재값 >= 1500 AND 투표 2+) |
| `NORMAL` | 앙상블 예측 >= 900 |
| `LOW` | 그 외 |


## status_Th (심층 판정) - UI 급증 로직

현재 TOTALCNT + 급증 컬럼 danger 수 + 10분 예측값을 종합해서 판정한다.

### 급증 분석 컬럼 (14개)

```
M14AM10A, M10AM14A, M14AM10ASUM
M14AM14B, M14BM14A, M14AM14BSUM
M14AM16, M16M14A, M14AM16SUM
M14.QUE.ALL.CURRENTQCREATED
M14.QUE.ALL.CURRENTQCOMPLETED
M14.QUE.OHT.OHTUTIL
M14.QUE.ALL.TRANSPORT4MINOVERCNT
M14B.QUE.SENDFAB.VERTICALQUEUECOUNT
```

### 급증 임계값 (10분 전 대비 변화량)

| 컬럼 | warning | danger |
|------|---------|--------|
| CURRENTQCREATED, CURRENTQCOMPLETED | >= 60 | >= 70 |
| 나머지 12개 | >= 50 | >= 60 |

### status_Th 판정 (2단계)

**1단계: 현재값 + 급증 기반**

| status_Th | 한글 | 조건 |
|-----------|------|------|
| `BOTTLENECK_EXPECTED` | 병목예상 | 현재값 >= 1650 AND danger 급증 >= 3개 |
| `DANGER_EXPECTED` | 위험예상 | 현재값 >= 1550 AND danger 급증 >= 2개 |
| `OBSERVATION` | 관찰 | 현재값 < 1550 AND danger 급증 >= 2개 |
| `NORMAL` | 양호예상 | 그 외 |

**2단계: 양호(NORMAL)일 때 예측값 추가 체크**

| status_Th | 한글 | 조건 |
|-----------|------|------|
| `BOTTLENECK(1700_PREDICT-10min)` | 병목(1700예측-10분) | 10분 예측 >= 1700 |
| `BOTTLENECK_EXPECTED` | 병목예상 | 10분 예측 >= 1650 |


## danger_probability (위험 확률) 계산

6단계로 누적 계산되며, 각 단계는 확률을 올릴 수만 있다 (내릴 수 없음).

### 1단계: 앙상블 예측값 기반 (기본)

| 예측값 | 확률 |
|--------|------|
| >= 1750 | 100% |
| >= 1700 | 95% |
| >= 1680 | 75% |
| >= 1650 | 50% |
| >= 1620 | 30% |
| >= 1600 | 15% |
| < 1600 | 5% |

### 2단계: 투표 비율 보정

| 투표 비율 | 추가 |
|-----------|------|
| >= 75% | +25% |
| >= 50% | +15% |
| >= 30% | +5% |

### 3단계: LGBM 확률 보정

| LGBM 중요 확률 | 추가 |
|----------------|------|
| >= 0.80 | +20% |
| >= 0.60 | +15% |
| >= 0.50 | +10% |

### 4단계: 최종 판정 보정

| 조건 | 최소값 |
|------|--------|
| final_pred_danger == 1 | 최소 80% |

### 5단계: 현재값 보정

| 현재 TOTALCNT | 최소값 |
|---------------|--------|
| >= 1700 | 최소 85% |
| >= 1650 | 최소 60% |
| >= 1600 | 최소 30% |

### 6단계: 심층 판정(status_Th) 보정

| status_Th | 한글 | 최소값 |
|-----------|------|--------|
| BOTTLENECK(1700_PREDICT-10min) | 병목(1700예측-10분) | 최소 90% |
| BOTTLENECK_EXPECTED | 병목예상 | 최소 70% |
| DANGER_EXPECTED | 위험예상 | 최소 55% |
| OBSERVATION | 관찰 | 최소 30% |


## 피처 생성 (create_sequence_features)

10.4평가와 동일하게 각 컬럼에서 280분 시퀀스 기반 20개 통계를 추출한다.

| # | 피처 | 설명 |
|---|------|------|
| 1 | mean | 평균 |
| 2 | std | 표준편차 |
| 3 | min | 최솟값 |
| 4 | max | 최댓값 |
| 5 | current | 현재값 |
| 6 | change | 처음-끝 변화량 |
| 7 | p25 | 25% 백분위 |
| 8 | p75 | 75% 백분위 |
| 9 | momentum | 최근10 평균 - 초기10 평균 |
| 10 | max_30 | 최근 30분 최대 |
| 11 | diff_10 | 현재 - 10분전 |
| 12 | diff_30 | 현재 - 30분전 |
| 13 | diff_60 | 현재 - 60분전 |
| 14 | rate_10 | 10분 변화율 |
| 15 | rate_30 | 30분 변화율 |
| 16 | range_10 | 최근 10분 범위 |
| 17 | range_30 | 최근 30분 범위 |
| 18 | gap_to_limit | 1700 - 현재값 |
| 19 | over_1500 | 1500 이상 여부 (0/1) |
| 20 | over_1600 | 1600 이상 여부 (0/1) |


## 없는 컬럼 처리

모델의 `FEATURE_GROUPS`나 `ANALYSIS_COLS`에 있는 컬럼이 CSV에 없으면 자동으로 0으로 생성한다.
스케일러 차원을 유지하기 위해 컬럼을 제거하지 않고 0으로 채우는 방식이다 (10.4실시간.PY 동일).

```python
if col not in df.columns:
    df[col] = 0
df[col] = pd.to_numeric(df[col], errors='coerce').fillna(0)
```


## 데이터 흐름

```
data/2025_DATA.CSV (실시간 CSV)
    ↓
CURRTIME 파싱 + 정렬
    ↓
QUEUE_GAP 파생 (CREATED - COMPLETED)
    ↓
없는 컬럼 → 0 생성
    ↓
최근 280분 추출
    ↓
┌─────────────────────────┐
│  10.4 모델 예측          │
│  XGB 타겟/중요/보조      │
│  LGBM 타겟/중요/보조     │
│  (+PDT 있으면 추가)      │
│  → 투표 + 규칙 판정      │
│  → 앙상블 평균           │
└─────────┬───────────────┘
          ↓
┌─────────────────────────┐
│  급증 분석 (UI 로직)     │
│  14개 컬럼 × 10분전 대비  │
│  → danger/warning 카운트 │
└─────────┬───────────────┘
          ↓
┌─────────────────────────┐
│  결과 생성               │
│  status: 투표+규칙 판정   │
│  status_Th: 급증 심층판정 │
│  danger_probability: 6단계│
└─────────────────────────┘
```
