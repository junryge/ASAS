# risk_factors 운영 가이드

> 룰베이스 발동이벤트 CSV 의 `risk_factors` 컬럼 — 운영자가 한눈에 봐야 할 위험 신호 12개 정리

---

## 0. 개요

`risk_factors` 컬럼에는 그 시점에 발동된 모든 위험 신호가 **세미콜론(;)** 으로 연결되어 들어갑니다. 각 신호마다 위험도 점수(`risk_score`)가 누적되어 최종 위험 레벨(`risk_level`)로 분류됩니다.

```
정상      : 0점
관심      : 1~24점
주의      : 25~44점
위험      : 45~69점   ★ 즉시 대응
매우위험  : 70점 이상  ★★ 긴급 조치
```

---

## 1. risk_factors 키워드 전체 목록 (12개)

| 키워드 | 점수 | 의미 | 임계값 | 운영자 행동 가이드 |
|---|---|---|---|---|
| `ra_sustained` | +25 | T1MIN 6분 이상 5분창 3회+ | 6.0분 × 3회 | 슬로우다운 지속 → 모니터링 |
| `ra_count=N` | +20 | T1MIN ≥9분이 10분창 N회 | ≥9.0분 × 2회+ | 명백한 정체 시작 |
| `ra=X.X분` | +15 | T1MIN 7.5분 이상 (임계 직전) | ≥7.5분 | 임계 진입 직전 |
| `rb_fast` | +25 | M14→M16 큐 10분에 +30 폭증 | +30/10분 | **빠른 폭주 — 위험** ★ |
| `rb=+N` | +15 | M14→M16 30분간 큐 +100 누적 | +100/30분 | 큐 누적 진행 |
| `rc_rev=N` | +20 | 리프터 역증가 2개+ | ≥2개 | 한 쪽으로 큐 몰림 |
| `rev=N(준위험)` | +10 | 역증가 3개+이지만 추세 양수 | ≥3 | 쏠림 시작 신호 |
| `rd=N%` | +25 | FAB 저장률 ≥25% | ≥25% | **공간 막힘 — 위험** ★ |
| `rd=N%(준위험)` | +10 | FAB 저장률 15~25% | ≥15% | 저장 압박 시작 |
| `re(HUB저장부족)` | +15 | HUB STB 가용 ≤60% | ≤60% | HUB 자체 막힘 |
| `rf=N(인플로↑)` | +10 | HUB 들어올 인플로 ≥700 | ≥700 | 전체 부하 큼 |
| `rf_fast` | +10 | 인플로 10분에 1.5배 폭증 | ×1.5 | 인플로 급증 |

## 2. 4축 분류 — 어느 축에서 문제?

### 시간축 (R-A' 계열) — "OHT 가 느려졌나?"
- `ra_sustained`, `ra_count=N`, `ra=X.X분`
- 원천: `M16HUB.QUE.TIME.AVGTOTALTIME1MIN`

### 양축 (R-B 계열) — "큐가 쌓이나?"
- `rb_fast`, `rb=+N`
- 원천: `M16HUB.QUE.M14TOM16.MESCURRENTQCNT`

### 위치축 (R-C' 계열) — "한쪽으로 쏠리나?"
- `rc_rev=N`, `rev=N(준위험)`
- 원천: `M16HUB.LFT.*.TOTAL_CURRENTQCNT` (리프터 10대)

### 공간축 (R-D 계열) — "저장공간이 막혔나?"
- `rd=N%`, `rd=N%(준위험)`
- 원천: `M16HUB.STRATE.ALL.FABSTORAGERATIO`

### 보조 신호 (v3.1 신규) — HUB 자체 + 인플로
- `re(HUB저장부족)` — HUB STB 자체 막힘
- `rf=N(인플로↑)`, `rf_fast` — 다른 fab 에서 몰리는 부하

## 3. 실제 예시

### ① 5/14 10:08 — 매우위험 80점 (R-A' 단독)

```
risk_factors = "ra_sustained;ra_count=2;ra=10.1분"
```
- **해석**: 시간 신호만 강하게 발동
- **상황**: R-A' 단독 발동. 운영자가 미리 선제 조치 (MAX CAPA 변경) 해서 R-B 가 안 잡힌 케이스
- **운영자 행동**: OHT 가동률 / 알람 확인. M14 쪽 부하 조절

### ② 5/7 7시 SFA 정체 — S3 사건 (4축 동시)

```
risk_factors = "ra_sustained;ra=8.6분;rb=+74;rc_rev=6;rd=29%"
```
- **해석**: 시간 + 양 + 위치 + 공간 4축 모두 발동
- **상황**: 진짜 데드락 (S3 확정)
- **운영자 행동**: 즉시 현장 대응. 어느 리프터 몰림인지 `rev_lids` 컬럼 확인

### ③ 일반 단발성 — 관심 10점

```
risk_factors = "rev=3(준위험)"
```
- **해석**: 리프터 쏠림만 약간
- **상황**: 곧 해소될 가능성 높음 (위치만 살짝 변동)
- **운영자 행동**: 로그만 기록, 별 조치 불필요

### ④ HUB 자체 막힘형 — 위험 60점

```
risk_factors = "ra=8.2분;re(HUB저장부족);rf=820(인플로↑)"
```
- **해석**: HUB 가 차고 있고 인플로도 많이 들어옴
- **상황**: HUB Room 자체 포화 임박
- **운영자 행동**: HUB STB 상태 점검, 인플로 차단 검토

### ⑤ 빠른 폭주형 — 매우위험 75점

```
risk_factors = "ra=8.5분;rb_fast;rb=+118;rc_rev=4"
```
- **해석**: 10분 만에 +30 큐 급증 + 시간 임계 직전
- **상황**: 폭주형 정체 (M14에서 큐 빠르게 쌓임)
- **운영자 행동**: M14→M16 큐 흐름 즉시 확인

## 4. 운영자 한 눈에 보는 패턴 가이드

| risk_factors 패턴 | 무엇이 문제? | 어디 봐야? |
|---|---|---|
| `ra_*` 만 있음 | **OHT 자체 느려짐** | OHT 가동률, 알람 확인 |
| `rb_*` 있음 | **큐 누적 진행** | M14→M16 큐 흐름 |
| `rc_rev=*` 있음 | **위치 쏠림** | 어느 리프터에 몰리는지 (`rev_lids` 컬럼) |
| `rd=*` 있음 | **저장공간 가득참** | FAB STK / ZFS 상태 |
| `re(HUB저장부족)` | **HUB 자체 막힘** | HUB STB 사용율 |
| `rf=*` 있음 | **인플로 폭주** | 다른 fab 에서 몰림 |

## 5. 위험도 조합 매트릭스

### 가장 위험한 조합 (즉시 대응)

```
ra_sustained + rb_fast + rc_rev=N + rd=N%
→ 4축 다 발동 = 진짜 데드락 임박
→ risk_score 95+ = 즉시 대응 (S3 진행 확률 매우 높음)
```

### 위험 조합 (15~30분 내 대응)

| 조합 | 점수 | 의미 |
|---|---|---|
| `ra_sustained + rc_rev` | ~45 | 시간+위치 → 곧 큐 쌓일 위험 |
| `rb_fast + rd=%` | ~50 | 양+공간 → 저장 막힘+폭주 |
| `ra_count + rb_fast` | ~45 | 시간+양 → 폭주형 정체 시작 |

### 주의 조합 (모니터링 강화)

| 조합 | 점수 | 의미 |
|---|---|---|
| `ra=*분 + rev=*(준위험)` | ~25 | 시간 임계 직전 + 쏠림 시작 |
| `ra_count=2 + re` | ~35 | 정체 시작 + HUB 압박 |

## 6. risk_score 점수 산정 공식

```python
risk_score = 0
risk_score += 25 if ra_sustained
risk_score += 20 if ra_count >= 2
risk_score += 15 if ra_value >= 7.5
risk_score += 25 if rb_fast
risk_score += 15 if rb_trig (rb_diff ≥ 100)
risk_score += 20 if rc_trig (역증가 ≥ 2 AND 추세 감소)
risk_score += 10 if rev_count >= 3 (트리거 미충족이지만 많음)
risk_score += 25 if rd_trig (FAB ≥ 25%)
risk_score += 10 if fabstorage_ratio >= 15 (임계 직전)
risk_score += 15 if re_trig (HUB 저장 ≤ 60%)
risk_score += 10 if rf_trig (인플로 ≥ 700)
risk_score += 10 if rf_fast (인플로 1.5배 폭증)

# 위험 레벨 분류
if risk_score >= 70: "매우위험"
elif risk_score >= 45: "위험"
elif risk_score >= 25: "주의"
elif risk_score > 0:  "관심"
else: "정상"
```

## 7. 운영 의사결정 흐름

```
1) risk_level 확인
   ├─ 매우위험 → 즉시 대응 (S3 임박)
   ├─ 위험     → 15~30분 내 조치
   ├─ 주의     → 모니터링 강화
   ├─ 관심     → 로그만
   └─ 정상     → 무시

2) risk_factors 분해
   → 어느 축인지 (시간/양/위치/공간/HUB/인플로) 파악

3) 원인 분석
   → 패턴 가이드(4번 표) 따라 해당 컬럼 확인
   → 운영 조치 (MAX CAPA 변경, AI Close 등) 결정
```

## 8. 주의사항

### 점수가 임계값에 가까울 때

- `risk_score = 23` (관심 → 주의 직전) 같은 경우 주의 깊게 모니터링
- 짧은 시간 안에 추가 신호 1개 발동 시 곧바로 "주의" 진입

### 점수 합산은 단순 합

- 같은 축의 여러 신호 동시 발동 시 점수가 빠르게 누적됨
- 예: `ra_sustained + ra_count + ra=*분` 동시 발동 → +60점 (시간축만으로도 위험 진입)

### risk_level 만 보지 말고 risk_factors 도 같이

- 점수 같아도 원인 다르면 대응 방법 다름
- 예: 75점 = `ra_sustained + rb_fast + rc_rev` 또는 75점 = `rd=% + rb_fast + re` — 대응 다름

## 9. 발동이벤트 CSV 컬럼 참조

`risk_factors` 와 함께 봐야 할 컬럼:

| 컬럼 | 용도 |
|---|---|
| `risk_score` | 정량 점수 (0~170) |
| `risk_level` | 분류 (정상/관심/주의/위험/매우위험) |
| `risk_factors` | 발동 신호 목록 (이 문서) |
| `reason` | 룰베이스가 판정한 한 줄 사유 |
| `relation` | R-A'/R-B/R-C' 풀텍스트 근거 |
| `hub_storage_util` | HUB 저장 사용율 % |
| `inflow_total` | 인플로 총합 (M14+M14B+M16A+M16B) |
| `rev_lids` | 역증가 리프터 ID 목록 (R-C' 발동 시) |
