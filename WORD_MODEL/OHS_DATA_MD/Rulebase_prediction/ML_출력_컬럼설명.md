| score | 의미 | 대응 |
|---|---|---|
| < 0.30 | 정상 (LOW) | 통과 |

## 🎯 룰베이스 + ML 결합 SOP (운영자 수동 판단)

> 하이브리드 자동 융합 모듈은 아직 미구축. 운영자가 두 결과를 같이 보고 판단.

### 룰 (test_table3) vs ML (test_table4) 동시 조회

| 룰 `stage` | ML `ml_score_30m` | 결합 판단 | 대응 |
|---|---|---|---|
| 3 | ≥ 0.7 | **확정 위험 (양방향 일치)** | 즉시 현장 출동 |
| 3 | 0.3 ~ 0.7 | 룰 확정 + ML 약신호 | 즉시 대응 (룰 우선) |
| 3 | < 0.3 | 룰 확정 + ML 미동의 | 위양성 의심, 현장 확인 |
| 0~2 | ≥ 0.85 | **ML 선행 알람** ★ | 룰 곧 발동 예상 — 사전 대응 |
| 0~2 | 0.7 ~ 0.85 | ML 주의 | 모니터링 강화 |
| 0~2 | < 0.7 | 정상 | 통과 |

### 핵심 케이스

#### Case A: 룰 stage=3 + ml_score_30m ≥ 0.7 — **확정 위험**
- 두 시스템 일치 → 신뢰도 최상
- 즉시 hot_area (룰) 로 현장 출동

#### Case B: 룰 stage<3 + ml_score_30m ≥ 0.85 — **ML 선행 알람** ★
- 룰베이스 임계 직전 상태를 ML 이 패턴으로 감지
- 30분 이내 룰 S3 발동 예상
- **하이브리드 핵심 가치 — 사전 대응 가능**

#### Case C: 룰 stage=3 + ml_score_30m < 0.3 — **룰 위양성 의심**
- ML 학습 데이터엔 비슷한 패턴 없음
- 룰 발동 사유 (`reason` 컬럼) 확인 후 대응 강도 조절

#### Case D: 두 시스템 모두 정상
- 통과

## ⏱ 운영자 1분 SOP

```
1) test_table4 의 ml_score_30m 확인
   ├─ ≥ 0.85 → test_table3 의 stage 확인 (Case B 가능)
   ├─ 0.7 ~ 0.85 → 모니터링 강화
   └─ < 0.7 → 통과

2) test_table3 의 stage = 3 이면:
   ├─ ml_score_30m 같이 확인 (Case A/C 판단)
   └─ hot_area + reason 확인 → 현장 대응

3) ml_score 와 룰 score 시계열 추이 같이 추적
   (ml_score 가 0.5 → 0.8 → 0.9 상승하면 룰 곧 발동)
```

## 🔧 ML 모델 정보

| 항목 | 값 |
|---|---|
| 라이브러리 | XGBoost (`xgboost.Booster`) |
| 모델 파일 | `model_v41_15m.json` / `model_v41_30m.json` / `model_v41_60m.json` |
| 학습 데이터 | 2026-03-24 ~ 2026-05-31 (~68일) |
| 라벨 | 룰베이스 S3 사건 (incidents_A_s3.json) |
| 피처 수 | ~700 (raw 265 + 시계열 통계 + 룰 컨텍스트) |
| 평가 지표 | PR-AUC, 사건 탐지율, 평균 사전인지 시간 |

### 임계값 튜닝 (선택)
`ml/ml_predictor.py` 의 `level()` 함수에서 OK/INFO/WARNING/CRITICAL 임계 조정 가능.
- WARNING: 0.70 (기본) — 너무 자주 발동 시 0.75 등으로 상향
- CRITICAL: 0.85 (기본) — 위양성 많으면 0.90 으로 상향

### 재학습 시점
- 운영자 메신저 사건 누적 **50건마다**
- 또는 매주 일요일 자동 (선택)
- 명령: `python ml/train_xgboost.py --features features_v41.csv --incidents incidents_A_s3.json --out model_v41_30m.json --lead_min 30`
