# FAB 위험 룰 v1.2 산식

원천. = 입력 지표, 파생. = 계산된 관측값, 룰. = 위험 기여값, 점수. = 합성 점수, 기여. = 한 룰 안의 세부 후보값. 기여값을 최종 점수에 별도로 더하지 않는다. 원본 CSV 컬럼은 변경하지 않는다.

## 기본 정규화

각 파생값 x에 `S(x)=clip((x-L)/(H-L),0,1)`을 적용한다. 일반적으로 L=설계구간 P90, H=P99이며 PIO는 H=P99.5다. 전체 구간을 정상 정답이라고 가정한 것이 아닌 경험적 참조 분포다. 따라서 지속 장애나 운영 방식 변경이 기준을 높일 수 있다.

물량증가율 L≥4%, H≥15%; 완료감소/부족률 L≥6%, H≥22%; 5분 PIO L≥2건, H≥8건이며 H−L≥5건; ALT L≥2, H≥10 및 차이≥5를 적용한다. 정확한 FAB·경로별 수치는 `derived_thresholds.csv`/`rule_config.json`에 고정되어 있다. 결측을 0으로 채워 기준을 계산하지 않는다. 상수·전부 결측 지표는 기준에서 비활성화한다.

## 파생 및 룰 계산식

기호: D=시간/SLA 지연 심각도의 큰 값, Q=현재물량 심각도, G=10분 증가율 심각도, F=최근10분 생성대비 완료부족률 심각도, L=과거처리수준 대비 완료감소 심각도. 이 심각도는 모두 0~1이다.

1. **반송 지연 지속 (최대45점)**: 완료 반송시간의 최근3분 중앙값(양수만, 유효2개 이상)과 4분 초과율의 최근3분 중앙값 각각을 S로 변환한 뒤 최대값을 사용. `45×D`. 시간·SLA를 따로 더하지 않는다. HUB의 상수0 SLA는 비활성화.
2. **미완료 물량 누적 (최대40점)**: `G=S(max(0,(Qraw(t)-Qraw(t-10))/max(Qraw(t-10),20)))`; `F=S(max(0,(생성10−완료10)/생성10))`. `B=max(0.65Q+0.35G, min(G,max(F,D)))`, 점수 `40B`. M16A는 전체 MCS 물량이라 `B×(0.25+0.75max(D,G×F))`로 지역 근거 없는 상승을 제한. HUB는 아래 v1.1 HUB 분기를 사용한다. STB행 CMD는 직접 배점하지 않는다.
3. **처리 감소와 대기 증가 (최대85점)**: 기준 완료량은 t−39~t−10의 최근10분 완료값 중앙값(유효20개 이상). `L=S(max(0,1−현재완료10/기준완료10))`. `85×min(L,max(G,F,D))`. FAB MCS JOB 기반이며 HUB 생성·완료는 사용자 지시로 제외. 완료 10분값을 다시 합산하거나 차분해 1분 건수로 오해하지 않는다.
4. **연결구간 지연·반입 실패 (최대55점)**: 방향별 최근5분 PIO 합 S와 발생분수≥2 조건. `P경로=S(PIO5)×(0.6+0.4max(S(경로물량),S(ALT),D,G))`. 방향 점수들을 합하지 않고 MAX로 묶음. M14A의 남북 CNV는 `min(S(CNV향 3분 시간중앙값),S(같은 방향 현재물량))`도 P와 MAX 결합. 최종 `55P`. HUB MLUD는 MLUD AI로 향하는 적재 OHT 수와 해당 PIO를 연결.
5. **OHT 가동률 급락·Queue 급증 (40~70점)**: 현재를 제외한 직전5분 중앙값 대비 가동률이 8%p 이상 하락하고 Queue가 5% 이상 증가할 때만 발동. 강도 `u=clip((하락폭−8)/12,0,1)`, `q=clip((증가율−0.05)/0.10,0,1)`, 점수 `40+30min(u,q)`. 단독 가동률 하락은 가점 없음. 특정 사건 날짜를 코드에 넣지 않음. 설계구간 원시 조건 발동은 총 4분이며, 8/26 M16A는 사용자에 의해 해당 시간대 OHT STOP 작업이 확인되었다. 실제 정지 경계는 미확정이며 작업 정보는 점수 입력이 아니다.
6. **적재 상태의 완료 공백 (HUB 최대80점)**: 최근3분 중 시간0인 분≥2일 때 `80×min(max(Q,G),S(적재OHT/운용OHT))`. 미완료 CMD를 직접 세는 규칙이 아니라 간접 의심 규칙이다. 이 설계자료에는 HUB 시간0이 없어 실제 정답 사례 검증은 미완료. 사용 여부를 평가자료로 확인해야 한다.
7. **최근5분 위험 급상승 (최대10점)**: 보정 전 기본점수의 t−5 대비 증가가 15점을 넘고 15점 이상 룰이 두 개 이상이면 `min(10,0.25×max(기본점수(t)−기본점수(t−5)−15,0))`. 보정된 최종점수를 다시 변화량 입력으로 넣지 않는다.

기본점수는 룰 기여값을 큰 순으로 r1,r2,r3라 할 때 `min(100,r1+0.30r2+0.15r3)`이다. 모든 원천과 연결 FAB 점수를 합산하지 않는다. 기본점수+추세보정에 최근3분 중앙값(유효2개 이상)을 적용한다. 처리감소 기여≥70 또는 급락·급증 기여≥40이면 즉시 상승을 허용한다. 하락은 분당 최대5점으로 완화한다. 필수값이 없으면 판단불가로 내보내며 하락 상태도 초기화한다. 이 절차는 미래 값 없이 작동한다.

`품질.파생값관측률`은 활성 파생값의 관측 비율이다. 결측 구성요소를 계산상 가점0으로 처리해도 관측품질과 필수값 판단불가를 별도로 표시한다. 이는 결측이 정상이라는 뜻이 아니다.


## HUB 대기 분기 — v1.1

- U: `M16HUB.STRATE.ALL.FABSTORAGERATIO` (Reserved 포함 저장률, 0~100).
- U3: 현재 포함 3분 중앙값. 3개 모두 유효해야 한다. 현재 결측이면 U3도 미사용.
- n: U≥5%가 연속 관측된 분 수. 5% 미만 또는 결측이면 끊는다. 개별 FOUP 체류시간이나 타이머 실제 실행 횟수가 아니다.
- 수준 강도: `R=clip((U3−5)/15,0,1)`.
- 지속 강도: n<5이면 0, n≥5이면 `min(n/10,1)`.
- 최근5분 U가 2%p 이상 감소하면 저장 후보 강도 W=0. 그 외 `W=R×지속 강도`. n=5에서 0.5, n≥10에서1이다. 과거5분이 없으면 해소 판정을 하지 않는다.
- 실제 반송영향 `E=max(D,P,Z)` (0~1). D=시간/SLA 지연, P=연결 Port 위험, Z=적재 상태의 완료 공백 강도. 각각 기존 룰 기여를 배점 전 정규화한 값이다.
- 확인 계수 `C=0.25+0.75E`.
- 내부JOB 후보 `Bq=max(0.65Q+0.35G,min(G,D))`. HUB 생성·완료 지표는 쓰지 않는다.
- 최종 HUB 대기 룰 `40×max(Bq×C,W×C)`. 내부JOB와 Storage, STB행 CMD를 각각 더하지 않는다.

E=0이면 대기 룰의 기여는 최대10점, E=1이면 최대40점이다. 이는 대기 룰의 상한이지 다른 원인으로 발생한 최종 FAB 점수의 상한이 아니다. STB행 CMD 증가 또는 저장률 상승만으로 높은 경고를 만들지 않는다. 저장률이 결측이어도 내부JOB·PIO·시간의 다른 유효 관측은 사용하고 `품질.HUB 저장률 유효`를 거짓으로 표시한다. 결측을 0이나 빈 공간 비율의 역수로 채우지 않는다.

`3F_STORAGE_UTIL`은 빈 공간 참고값으로만 출력한다. `100−3F_STORAGE_UTIL`을 예약 포함 저장률로 대체하지 않는다. HUB STK는 존재하지 않아 제외한다. 다른 FAB에는 이 HUB 분기를 적용하지 않는다.

## 후보값 선정과 한계

5%/20%, 5분/10분, 해소2%p, 영향없는 기여25%는 동작 원리를 반영한 후보값이다. 설계기간의 예약포함 저장률 P90=0.59%, P99=14.2%를 참고해 작은 정상 변동에 바로 포화하지 않게 설정했으나 최적값으로 검증한 것은 아니다. 사건마다 파라미터를 반복 탐색하지 않았다. 정확한 설정은 rule_config.json에 고정한다. 1분 재확인은 해소 보장이 아니다.

## 일반 Sorter 전용 점수 — v1.2

일반 Sorter와 CU Sorter는 다른 장비다. 이번 버전은 일반 Sorter만 계산하고 CU는 미평가로 둔다. 일반/CU 간 MAX 연산을 하지 않는다.

원천: 각 FAB의 `.SORTER.ABN.SORTERWAITCOUNTOVER`. 최근5분 중앙값(유효3개 이상)에 `100×clip((x−L)/(H−L),0,1)` 적용. 임계값은 v1.1 일반 Sorter 설정을 유지한다. 결과 컬럼은 `점수.일반Sorter대기`, `등급.일반Sorter대기`. 기존 `점수.Sorter대기` 컬럼과 이름이 달라 후속 화면 매핑을 수정해야 한다. HUB에는 Sorter가 없어 미평가다.

FAB 반송위험 산식은 v1.1 유지. 일반 Sorter 점수는 FAB 반송점수에 합산하지 않는다. CU 관련 실제 반송 영향이 시간/PIO 등 일반 지표에 나타나면 반송점수에 반영될 수 있으나 CU 장비 자체 위험을 평가한 것은 아니다. 100점은 산식 상한이며 장애확률이 아니다.
