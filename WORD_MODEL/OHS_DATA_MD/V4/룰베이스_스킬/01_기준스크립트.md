# 01. 기준 스크립트 — 룰 평가 알고리즘

> raw CSV (CRT_TM + 265 IDC 컬럼) 가 주어지면, 본 알고리즘을 그대로 적용해서 분당 평가하라.
> 임계값은 `04_임계값.md` 의 표를 그대로 인용. 자체 임계 만들지 말 것.

---

## 입력 데이터 구조

- 첫 컬럼: `CRT_TM` ('YYYY-MM-DD HH:MM:SS' 또는 'YYYY-MM-DD HH:MM')
- 나머지 265 컬럼: 영역.카테고리.메트릭 (예: `M16HUB.QUE.TIME.AVGTOTALTIME1MIN`)
- 영역 8종: M16HUB, M14, M14B, M16A, M16B, M16, M16_PKT, M16_WT

---

## 룰별 평가 (분당, 매 행)

### R-A (반송시간 절대 임계, 10분 윈도우 1회 이상)
```
영역별 컬럼:
  M16HUB → M16HUB.QUE.TIME.AVGTOTALTIME1MIN
  M14    → M14.QUE.LOAD.AVGLOADTIME1MIN
  M14B   → M14B.QUE.TIME.AVGTOTALTIME1MIN
  M16A   → M16A.QUE.LOAD.AVGLOADTIME1MIN
  M16B   → M16B.QUE.LOAD.AVGLOADTIME1MIN

판정:
  최근 10행 (10분) 중 1회 이상 ≥ TH_RA[영역] → RA 발동
```

### R-A_sus (지속 정체, 5분 윈도우)
```
판정:
  최근 5행 중 N회 이상 ≥ (TH_RA × RATIO) → RA_sus 발동
  추천: 5분 중 4회 이상 ≥ (TH_RA × 0.90)
  v4.1: 5분 중 3회 이상 ≥ (TH_RA × 0.67)
```

### R-B (큐 누적, 30분/10분)
```
영역별 컬럼:
  M16HUB → M16HUB.QUE.M14TOM16.MESCURRENTQCNT
  M14    → M14.QUE.ALL.3F_TO_HUB_JOB
  M14B   → M14B.QUE.ALL.7F_TO_HUB_JOB
  M16A   → M16A.QUE.ALL.6F_TO_HUB_JOB
  M16B   → M16B.QUE.ALL.10F_TO_HUB_JOB

판정:
  R-B:      현재 - 30분 전 ≥ TH_RB_30[영역] → RB 발동
  R-B_fast: 현재 - 10분 전 ≥ TH_RB_10[영역] → RB_fast 발동
```

### R-C (M16HUB 리프터 역증가, 20분 트렌드)
```
M16HUB 리프터 10대:
  6ABL6011, 6ABL6012, 6ABL6021, 6ABL6022, 6ABL6031, 6ABL6032,
  6ABL0111, 6ABL0112, 6ABL0121, 6ABL0122

각 리프터 컬럼: M16HUB.LFT.{ID}.TOTAL_CURRENTQCNT

판정:
  trend = (현재 10대 합) - (20분 전 10대 합)
  rev_count = (개별 리프터 중 20분 전보다 증가한 개수)
  trend < 0 AND rev_count ≥ TH_RC_REVERSE → RC 발동
```

### R-D (Fab 적체 / OHT 가동률)
```
M16HUB:
  FAB ≥ TH_RD_FABSTORAGE  → RD 발동
  OR STB ≥ TH_RD_HUB_STB_UTIL  → RD 발동
  컬럼: M16HUB.STRATE.ALL.FABSTORAGERATIO, M16HUB.STRATE.STB.3F_STORAGE_UTIL

다른 영역 (M14/M14B/M16A/M16B):
  *.QUE.OHT.OHTUTIL ≥ TH_RD_OHT_UTIL  → RD 발동
```

### SLA (4분 초과율)
```
영역별 컬럼:
  M16HUB → M16HUB.QUE.ALL.TRANSPORT4MINOVERRATIO
  M14    → M14.QUE.ALL.TRANSPORT4MINOVERRATIO
  M16A   → M16A.QUE.ALL.TRANSPORT4MINOVERRATIO
  M16B   → M16B.QUE.ALL.TRANSPORT4MINOVERRATIO

판정:
  ratio ≥ TH_SLA_RATIO[영역] → SLA 발동
```

### Sorter (대기 LOT 카운트)
```
영역별 컬럼:
  M14    → M14.SORTER.ABN.SORTERWAITCOUNTOVER
  M14B   → M14B.SORTER.ABN.SORTERWAITCOUNTOVER
  M16A   → M16A.SORTER.ABN.SORTERWAITCOUNTOVER
  M16B   → M16B.SORTER.ABN.SORTERWAITCOUNTOVER
  M16HUB → M16HUB.SORTER.ABN.SORTERWAITCOUNTOVER

판정:
  count ≥ TH_SORTER_WAIT[영역] → SORT 발동
```

---

## 영역 점수 (50 캡)

```
점수 = (RA?10) + (RA_sus?5) + (RB?10) + (RB_fast?5)
     + (RC?8) + (RD?7) + (SLA?5) + (SORT?3)
     + (MAXCAPA 변경 수 × 10)

영역 점수 = min(50, 합계)
```

---

## 통합 단계 판정

```
any_ra        = 어느 영역이든 RA 또는 RA_sus 발동
any_rb        = 어느 영역이든 RB 또는 RB_fast 발동
any_rd_or_sla = 어느 영역이든 RD 또는 SLA 발동
any_rc        = M16HUB RC 발동
flow_severe   = flow_score ≥ 15 (위험/심각 등급)

S3 확정: any_ra AND (any_rd_or_sla OR any_rc) AND (any_rb OR flow_severe)
S2 주의: any_rb
S1 조기경보: any_ra OR any_ra_sus
```

---

## 통합 위험도 점수 / 등급

```
unified_risk_score = layer1_total + flow_score + sla_score + sorter_score + mc_score
(상한 500)

등급:
  ≥ 250: 매우위험
  ≥ 150: 위험
  ≥  80: 주의
  ≥  65: 경계
  ≥  30: 관심
  <  30: 정상
```

---

## 평가 순서 (LLM 따라할 것)

1. 행마다 영역별 R-A/R-A_sus/R-B/R-B_fast/R-C/R-D/SLA/Sorter 판정 (위 룰)
2. 영역 점수 계산
3. 통합 단계 (S1/S2/S3) 판정
4. 통합 위험도 점수 계산
5. 결과를 `03_일반스킬.md` 의 형식으로 출력

**임계값은 반드시 `04_임계값.md` 의 표를 인용.** 자체 값 생성 금지.
