## 2. 점수 산정 (영역별 → 통합)

### 2.1 영역 점수 (0~50)

| 시그널 | 점수 | 트리거 |
|---|---|---|
| **RA** | +10 | `ra_trig` |
| **RA_sus** | +5 | `ra_sustained` |
| **RB** | +10 | `rb_trig` |
| **RB_fast** | +5 | `rb_fast` |
| **RC** | +8 | `rc_trig` |
| **RD** | +7 | `rd_trig` |
| **SLA** | +5 | `sla_trig` |
| **SORT** | +3 | `sorter_trig` |
| **MAXCAPA*n** | +10 × n | `maxcapa_changed_n` |

→ 최대 50점.

### 2.2 통합 점수 `unified_risk_score` (0~500)

```
unified_risk_score =
    Σ area_score (모든 8 영역)         ← layer1_total
  + Σ flow_score (주의+5, 위험+15, 심각+30)
  + Σ sla_score (영역별 +5)
  + Σ sorter_score (영역별 +3)
  + Σ maxcapa_score (변경 1개당 +10)
```

→ 최대 500점.

### 2.3 위험도 등급 (6단계)

| 등급 | score |
|---|---|
| **매우위험** | ≥ 250 |
| **위험** | ≥ 150 |
| **주의** | ≥ 80 |
| **경계** | ≥ 65 |
| **관심** | ≥ 30 |
| **정상** | < 30 |

### 2.4 Stage 판정

```
unified_s1 = any_ra OR any_ra_sustained                          (조기경보)
unified_s2 = any_rb                                              (주의보)
unified_s3 = any_ra AND (any_rd_or_sla OR any_rc)                ★ 확정
              AND (any_rb OR any_flow_severe)
```

**STAGE_LABEL**:
- 0: 이벤트없음
- 1: 1단계 조기경보
- 2: 2단계 주의보
- 3: **3단계 ⭐확정**

## 3. 정체 유형 — 7가지 + 운영자 변경

### 유형 1: R-A 반송시간 정체

**증상**: AVGTOTALTIME1MIN/AVGLOADTIME1MIN ≥ 임계.
**대표 영역**: M16HUB (9.0분), M14B (5.0분).

**원인 후보**:
- M16HUB OHT 처리량 한계 (`HUB_OHT_QCNT` ↑)
- Bridge OHT Error
- 리프터 다운으로 인플로 정체

**대응 SOP**:
1. `M16HUB.QUE.OHT.CURRENTOHTQCNT` 30분 추세 확인
2. Bridge OHT 알람 확인 (`6FIOB` 시리즈)
3. 필요 시 M14 ZT MAXCAPA 50% 변경

### 유형 2: R-B 큐 누적 (느린/FAST)

**증상**: `M14TOM16.MESCURRENTQCNT` 가 30분 +100 (느린) 또는 10분 +30 (FAST).

**원인**:
- M14 → M16HUB 인플로 폭증
- M16HUB → M16A/B 아웃플로 막힘

**대응 SOP**:
1. M14 측 인플로 확인 (3F_TO_HUB_JOB, 4AFC CNV)
2. 출구 (6ABL 리프터) 상태 확인
3. FAST 면 즉시 M14 ZT AI Close 또는 MAXCAPA

### 유형 3: R-C 반전 흐름

**증상**: M16HUB 리프터 10대 중 2대+ 가 평소 흐름 반대.

**원인**: 특정 층 STB 적체로 역송출.

**대응**:
1. `rev_lids` 컬럼으로 반전 리프터 확인 (6ABL60~ 또는 6ABL01~)
2. 해당 층 (3F/6F) STB 회수 가능 풉 점검
3. 필요 시 한 방향 일시 정지

### 유형 4: R-D Fab 적체

**증상**: `FABSTORAGERATIO ≥ 25.0` 또는 `STB_UTIL ≥ 99.0` 또는 `OHTUTIL ≥ 95.0`.

**대응**:
1. STB/STK 회수 가능 풉 → 공정 호출
2. MLUD 출고 가능량 확인
3. M14/M16A/M16B 인풋 일시 차단

### 유형 5: R-Flow 영역간 폭증

**증상**: 10개 노드 중 어느 하나 ratio ≥ 1.5 (주의) / 2.0 (위험) / 3.0 (심각).

**대표 시나리오**:
- `M14B_LFT_4ABLD_TO_HUB_SUM` ↑ → M14B → HUB 하강 리프터 정체 ★
- `M14_CNV_TO_HUB` ↑ → 4AFC3201/3301 CNV 폭주
- `HUB_OHT_QCNT` ↑ → M16HUB OHT 큐 과다

**대응**:
1. `flow_signals` 컬럼에서 해당 노드 식별
2. 노드 영역 점검 (리프터/CNV/OHT)

### 유형 6: SLA 위반

**증상**: `TRANSPORT4MINOVERRATIO ≥ 임계` 또는 `OVERCNT` 10분 +20.

**대응**:
1. 영역별 SLA ratio 확인 (M16HUB 5%, M14 25%, M16A 13%, M16B 18%)
2. 반송 지연 풉 추적

### 유형 7: Sorter 대기/실패

**증상**: `SORTERWAITCOUNTOVER ≥ 임계` (M14=100, M14B=75, M16A=180, M16B=90, M16HUB=30) 또는 `SORTERTRANSFERFAIL ≥ 1` (M16A/B).

**대응**:
1. 해당 영역 OHT 가동률 확인
2. 소터 → 다음 단계 흐름 막힘 점검

### 운영자 변경 감지: MAXCAPA*n

**증상**: 위 6개 MAXCAPA 컬럼 중 N개가 정상값 이하.

**대응**: 변경 사유 확인 (사전 공지 / 긴급 조정) → 후속 모니터링.

## 6. 평가 사이클 — 매분 1행

```
1. 발동이벤트.csv 의 unified_risk_score 확인
2. unified_risk_score < 30 → '정상' → 통과
3. ≥ 30 → 유형 분류:
   a. stage (0~3) 확인
   b. hot_area 확인
   c. signals 컬럼 확인 (RA/RB/RC/RD/SLA/SORT/MAXCAPA*n)
   d. flow_signals 확인 (10 노드 중 위반)
4. 유형 1~7 매핑 → 대응 SOP 실행
5. 운영자 메신저 보고
```
