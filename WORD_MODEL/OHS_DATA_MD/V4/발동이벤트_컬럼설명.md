## 🔴 [1] 최우선 컬럼 (5개)

### 1.1 `stage` ★ 가장 중요
- **의미**: 통합 단계 — 시스템 전체의 위험 진행 상태
- **값**: `0` / `1` / `2` / `3`
- **산출**:
  - `s3 = unified_s1 AND (어느 영역 R-D OR SLA OR M16HUB R-C') AND (unified_s2 OR 흐름룰 위험/심각)`
  - `s2 = 어느 영역 R-B OR R-B_fast 발동`
  - `s1 = 어느 영역 R-A' OR R-A_sus 발동`
- **운영**: `3` 이면 즉시 대응. `2` 주시. `1` 로그. `0` 통과.

### 1.2 `stage_name`
- **의미**: stage 한글 표시
- **값**:
  - `0` → `이벤트없음`
  - `1` → `1단계 조기경보`
  - `2` → `2단계 주의보`
  - `3` → `3단계 ⭐확정`

### 1.3 `transition` ★ 단계 변화 추적
- **의미**: 직전 단계 → 현재 단계 변화 표시
- **형식**: `prev→cur` 예: `0→1`, `2→3`, `3→1`
- **공란**: 단계 변화 없을 때
- **중요 케이스**:
  - `→3` = **사건 시작** ⭐
  - `3→1`, `3→2`, `3→0` = 사건 종료 (10분 무발동)
  - `0→1` = 정상에서 신호 시작
  - `1→2` = 악화

### 1.4 `hot_area`
- **의미**: **최고 점수 영역 1개** (발원지 / 가장 위험한 곳)
- **산출**: 8개 영역의 `area_score` 중 최댓값 영역. 점수 0 이면 빈 값.
- **값**: `M16HUB` / `M14` / `M14B` / `M16A` / `M16B` / `M16` / `M16_PKT` / `M16_WT` / 빈값
- **주의**: 여러 영역이 위험해도 1개만 표시됨 → 같이 봐야 할 것: `affected_areas`, `{area}_score` 개별

### 1.5 `reason`
- **의미**: 한 줄 요약 사유 (운영자 즉시 판단용)
- **형식**: `hot_area=X; 단계명; 발동: 영역[룰리스트]; 영역[룰리스트]; ...`
- **예시**:
  ```
  hot_area=M16HUB; S1조기경보; 발동: M16HUB[R-C'(역증가5개:6ABL6011,6ABL6012,6ABL6031,6ABL0121,6ABL0122)]; M14[R-A_sus]; M16A[R-A_sus]; M16B[R-A_sus]
  ```

## 🟡 [2] 위험도 / 전파 (7개)

### 2.1 `unified_risk_score`
- **의미**: 통합 위험 점수 0 ~ 500
- **산출**: 5종 룰 점수 합산
  | 항목 | 최대 |
  |---|---|
  | 영역별 4축 (영역마다 0~50점) × 8영역 | 300 |
  | 흐름 룰 9노드 (주의 5 / 위험 15 / 심각 30) | 90 |
  | SLA (4영역 × 5점) | 20 |
  | Sorter (5영역 × 3점) | 15 |
  | MAXCAPA (6컬럼 × 10점) | 60 |
- **운영**: `unified_risk_level` 과 함께 봄

### 2.2 `unified_risk_level`
- **의미**: 6단계 위험 등급
- **임계**:
  | 등급 | score | 사건단위 기록 | 대응 |
  |---|---|---|---|
  | 정상 | 0 ~ 29 | ❌ | 통과 |
  | 관심 | 30 ~ 64 | ❌ | 로그만 |
  | **경계 ★** | **65 ~ 79** | ✅ | 모니터링 강화 |
  | **주의** | **80 ~ 149** | ✅ | 추세 관찰 |
  | **위험** | **150 ~ 249** | ✅ | 사전 대응 |
  | **매우위험** | **250 ~ 500** | ✅ | 즉시 출동 |

### 2.3 `affected_areas`
- **의미**: 점수 ≥ **15** 인 영역들 (사건 규모 판단용)
- **형식**: `;` 구분 — 예: `M16HUB;M14;M16A`
- **공란**: 모든 영역 점수 < 15

### 2.4 `propagation_chain` ★ 전파 경로
- **의미**: 시간순 영역별 첫 발동 시점 정렬 = **전파 경로 추적**
- **형식**: `영역1(시각, 발동룰들) → 영역2(시각, 룰들) → ...`
- **추적 기간**: 최근 **60분** (PREDICT_LOOKBACK_MIN)
- **예시**:
  ```
  M16B(11:19, RA_sus+RB_fast+SLA) → M16HUB(11:25, RC+RD) → M14(11:35, RA_sus+RB_fast+SLA)
  ```
  → 11:19 M16B 에서 시작 → 6분 뒤 M16HUB → 10분 뒤 M14 로 번짐

### 2.5 `flow_signals`
- **의미**: 흐름 룰 9개 노드 중 발동된 것 (현재값 / 30분평균 비율 표시)
- **형식**: `노드명=비율x(등급)` — 예: `M14_CNV_TO_HUB=2.9x(심각); HUB_OHT_QCNT=1.7x(주의)`
- **등급**: 1.5x 주의 / 2.0x 위험 / 3.0x 심각

### 2.6 `maxcapa_signals`
- **의미**: 운영자가 메신저에서 변경한 MAXCAPA 컬럼 감지
- **형식**: `컬럼명=현재값(<=임계)` — 예: `3F_LFT_MAXCAPA=80(<=100)`
- **중요**: 운영자가 이미 정체를 인지하고 조치한 직접 신호 ★

### 2.7 `prev_stage`
- **의미**: 직전 분의 stage
- **용도**: `transition` 과 같이 단계 변화 추적

## 📢 [5] 영역별 발동 룰 (5개)

각 영역에서 어떤 룰이 발동했는지 텍스트로 표시.

### 5.1 ~ 5.5 `{영역}_signals`
- **컬럼**: `M16HUB_signals`, `M14_signals`, `M14B_signals`, `M16A_signals`, `M16B_signals`
- **형식**: 발동된 룰 코드를 `+` 로 결합
- **공란**: 그 영역 모든 룰 미발동

### 룰 코드 상세
| 코드 | 풀네임 | 의미 | 잡는 패턴 |
|---|---|---|---|
| `RA` | R-A' 메인 | 1MIN ≥ 임계 (10분창 1회 이상) | 갑작스런 슬로우다운 |
| `RA_sus` | R-A' 지속 | 1MIN ≥ 임계×0.67 (5분창 3회 이상) | 만성적 슬로우 |
| `RB` | R-B 메인 | 30분간 +임계 이상 증가 | 느린 큐 누적 |
| `RB_fast` | R-B 빠른폭주 | 10분간 +임계×0.3 이상 증가 | 빠른 큐 폭증 |
| `RC` | R-C' | 리프터/CNV 합 감소 + 개별 역증가 ≥ 2 | 구조적 데드락 |
| `RD` | R-D | FAB/STB/OHTUTIL ≥ 임계 | 공간 막힘 |
| `SLA` | 4분초과 | TRANSPORT4MINOVERRATIO ≥ 임계 | 정체 직접 결과 |
| `SORT` | Sorter | SORTERWAITCOUNTOVER ≥ 임계 | LOT 적체 |
| `MAXCAPA` | 운영자 변수 | MAXCAPA ≤ 임계 (정상값에서 감소) | 운영자 인지 신호 |

### 조합 예시
- `RA+RC+RD` = R-A' + R-C' + R-D 동시 (= S3 조건 만족)
- `RA_sus+SLA` = 지속신호 + 4분초과 동시
- `RB_fast+SORT` = 빠른 폭주 + Sorter 적체

```
                   ↓
┌──────────────────────────────────────────────┐
│  2. transition 확인 (사건 시작/종료 시점)     │
│     ├─ →3       = 사건 시작                   │
│     ├─ 3→0/1/2 = 사건 종료                    │
│     └─ 1→2, 2→3 = 악화 진행                   │
└──────────────────┬───────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│  3. hot_area + affected_areas                 │
│     hot_area     = 발원지                     │
│     affected     = 영향 영역 (15점 이상)      │
└──────────────────┬───────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│  4. propagation_chain                         │
│     예: M14(11:35) → M16HUB(11:40) → ...     │
│     → 어느 방향으로 번지고 있는지            │
└──────────────────┬───────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│  5. {hot_area}_signals + reason               │
│     어떤 룰이 발동? 왜?                       │
└──────────────────┬───────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│  6. 해당 영역 상세값 확인                     │
│     - {area}_ra        시간                  │
│     - {area}_rb_diff30 양 증가                │
│     - M16HUB_rev_count / rev_lids  위치       │
│     - M16HUB_rd_fab / stb_util     공간       │
│     - sla_{area}       4분초과                │
│     - sorter_{area}    Sorter                 │
└──────────────────────────────────────────────┘
```

## 🎯 [12] 한 줄 요약 — 운영자 SOP

| 우선순위 | 컬럼 | 보는 이유 |
|---|---|---|
| **1순위** | `stage` | 3 = 사건 확정 (즉시 대응) |
| **2순위** | `transition` | `→3` (시작) / `3→1` (종료) 인지 |
| **3순위** | `hot_area` + `affected_areas` | 어디 위험? |
| **4순위** | `reason` + `{hot_area}_signals` | 왜 위험? 어떤 룰? |
| **5순위** | `unified_risk_level` | 얼마나 위험? (점수 기반) |
| **6순위** | `propagation_chain` | 어디로 번지나? |
| 7순위 | 영역 상세값 | 임계 얼마나 초과? |

**핵심: `stage=3` 이면 무조건 대응. 나머지는 참고.**

### 13-1. 영역별 룰 점수 (30 컬럼) — `{area}_pts_{rule}`

5 핵심 영역 × 6 룰 = 30 컬럼. 각 영역의 룰별 가산 점수.

| 영역 | RA | RA_sus | RB | RB_fast | RC | RD |
|---|---|---|---|---|---|---|
| **M16HUB** | `M16HUB_pts_RA` | `M16HUB_pts_RA_sus` | `M16HUB_pts_RB` | `M16HUB_pts_RB_fast` | `M16HUB_pts_RC` | `M16HUB_pts_RD` |
| **M14** | `M14_pts_RA` | `M14_pts_RA_sus` | `M14_pts_RB` | `M14_pts_RB_fast` | `M14_pts_RC` | `M14_pts_RD` |
| **M14B** | `M14B_pts_RA` | `M14B_pts_RA_sus` | `M14B_pts_RB` | `M14B_pts_RB_fast` | `M14B_pts_RC` | `M14B_pts_RD` |
| **M16A** | `M16A_pts_RA` | `M16A_pts_RA_sus` | `M16A_pts_RB` | `M16A_pts_RB_fast` | `M16A_pts_RC` | `M16A_pts_RD` |
| **M16B** | `M16B_pts_RA` | `M16B_pts_RA_sus` | `M16B_pts_RB` | `M16B_pts_RB_fast` | `M16B_pts_RC` | `M16B_pts_RD` |

**가산값**:
- RA = 10 / RA_sus = 5 / RB = 10 / RB_fast = 5 / RC = 8 / RD = 7
- 미발동 = 0

**활용 예 (SQL)**:
```sql
-- 룰 카테고리별 전체 합산 (일별)
SELECT date,
  SUM(M16HUB_pts_RA + M14_pts_RA + M14B_pts_RA + M16A_pts_RA + M16B_pts_RA) AS RA_total,
  SUM(M16HUB_pts_RB + M14_pts_RB + M14B_pts_RB + M16A_pts_RB + M16B_pts_RB) AS RB_total
FROM event_table
GROUP BY date;
```

### 13-2. 통합 점수 분해 (5 컬럼)

`unified_risk_score` 가 어떻게 구성됐는지 분해.

| 컬럼 | 의미 | 계산식 |
|---|---|---|
| `layer1_total` | 8 영역 점수 합산 | Σ area_score |
| `flow_score` | 10 흐름 노드 점수 | 주의×5 + 위험×15 + 심각×30 |
| `sla_score_total` | SLA 발동 영역 점수 | 발동 영역 수 × 5 |
| `sorter_score_total` | Sorter 발동 영역 점수 | 발동 영역 수 × 3 |
| `mc_score_total` | MAXCAPA 변경 점수 | 변경 컬럼 수 × 10 |

**검산식**:
```
unified_risk_score = min(500,
    layer1_total + flow_score + sla_score_total + sorter_score_total + mc_score_total)
```

### 13-3. 활용 시나리오

**A. 룰별 기여도 분석**
- "지난 1개월 사건 중 R-B 점수 비중이 평균 몇 %?"
- "R-C 발동이 R-D 보다 사전 알람으로 더 가치 있나?"

**B. 영역별 핫스팟 추적**
- "M14B 의 RD 점수가 평소보다 자주 발동 → 영역 임계 재조정 검토"
