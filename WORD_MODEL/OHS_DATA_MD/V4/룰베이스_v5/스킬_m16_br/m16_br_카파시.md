# m16_br 카파시 (왜/개념 설명)

M16A HUBROOM 이벤트 예측 룰베이스 v6 의 **목적·구조·해석 기준**. 분석 스킬들이 만든 결과를 "왜 이런가" 설명할 때 이 지식을 쓴다.

## 1. 이 시스템이 하는 일
반도체 FAB AMHS(자동 물류) 의 **반송 정체를 메신저 등록보다 평균 30~60분 먼저 예측**. 8개 영역(M16HUB/M14/M14B/M16A/M16B/M16/M16_PKT/M16_WT) 의 센서 데이터를 매분 룰로 평가해 위험 점수를 매김.

## 2. 두 개의 출력
| 파일 | 단위 | 언제 기록 |
|---|---|---|
| **발동이벤트.csv** | 매분 1행 (135컬럼) | 즉시 (실시간 모니터링) |
| **사건단위.csv** | 사건당 1행 (170컬럼) | 사건 종료 + 60분 후, **점수 100+ 만** |

→ 발동이벤트 = 매분 스냅샷, 사건단위 = 끝난 사건 요약.

## 3. 점수가 어떻게 만들어지나
```
unified_risk_score = layer1_total + flow_score + sla_score + sorter_score + mc_score
```
- **layer1_total**: 8영역 각 area_score 합 (룰별 점수 누적)
- **flow_score**: 흐름 비율 정체 (1.5x=+5, 2.0x=+15, 3.0x=+30)
- **sla_score**: SLA 4분초과 영역당 +5
- **sorter_score**: Sorter 대기 영역당 +3
- **mc_score**: MAXCAPA 변경 영역당 +10

**중요**: 사건단위의 `max_*` 컬럼들은 각자 다른 분(分)의 최고값이라 더하면 max_risk_score 와 안 맞음. 매분 합이 정확히 더해지는 건 발동이벤트.csv.

## 4. 9개 룰
| 룰 | 의미 | 본 컬럼 |
|---|---|---|
| R-A | 반송시간 초과 | AVGTOTALTIME1MIN / AVGLOADTIME1MIN |
| R-A_sus | 반송 지연 지속 | (R-A 가 여러 분 지속) |
| R-B | 30분 큐 누적 | 6F/10F_TO_HUB_JOB 등 |
| R-B_fast | 큐 급증 | 10분 변화량 |
| R-C | 리프터 역증가 (M16HUB) | rev_count |
| R-D | FAB/STB 저장 정체 / OHT 가동률 | FABSTORAGERATIO, STB_STORAGE_UTIL, OHTUTIL |
| SLA | 4분초과 비율 | TRANSPORT4MINOVERRATIO |
| Sorter | LOT 대기 폭증 | SORTERWAITCOUNTOVER |
| MAXCAPA | 운영자 CAPA 조치 | 3F_CNV_MAXCAPA |

S3(확정) = `any_RA AND (any_RD or any_SLA or any_RC) AND (any_RB or 흐름심각)`.

## 5. 5단계 등급 (v6, 한국 경보 체계)
| 점수 | 등급 | 의미 |
|---|---|---|
| 0~99 | 정상 🟢 | 알람 X (사건단위 기록 안 됨) |
| 100~119 | 관심 🔵 | 약한 신호, 참고용 (정밀도 41%) |
| 120~129 | 주의 🟡 | 모니터링 시작 |
| 130~159 | 경계 🟠 | 원인 확인 |
| 160~219 | 위험 🔴 | 즉시 조치 (정밀도 75%) |
| 220+ | 발동 ⚫ | 즉시 개입 |
**점수가 높을수록 정확하고 더 일찍 잡음** (위험 등급은 평균 +64분 사전 예측).

## 6. v6 핵심 변경 (왜 이렇게 했나)
1. **사건 묶기 gap 60분** — 점수가 잠깐 떨어졌다 다시 올라도(진동) 같은 사건으로. 60분이 검증상 최적(정밀도 52%).
2. **점수 100 미만 사건 제외** — 노이즈 알람 차단. 100 미만은 발동이벤트에서 모니터링만.
3. **장애 유형 라벨** (predicted_fault_type) — HUB-FAB정체 / HUB-리프터역증가 / M14-Sorter대기 등 hot_area+증상으로 즉시 이해.
4. **지속성/재발생 컬럼** — continuity_min(몇 분째), refire_count(재발 횟수). 점수/등급엔 영향 X, **참고용**.

## 7. 평가(검증) 기준
- **정답지**: 운영로그_파서_v2 가 메신저 채팅을 Episode 로 묶은 것 (orphan/CAPA변경 제외).
- **매칭**: 사건 [predict-30분, end+60분] 안에 메신저 발생하면 TP. MAX_LEAD 120분, 1:1 최근접.
- **리드타임** = 메신저시각 - 룰베이스 predict. 양수면 사전 예측 성공.
- **한계**: 룰베이스는 시스템 전체 정체에 강하고 개별 장비 고장엔 약함. 메신저 정답지도 불완전(운영자 채팅한 것만) → FP 가 다 헛알람은 아님.

## 8. 결과 해석 팁 (분석 스킬 출력 읽을 때)
- **점수 79인데 룰 4개 🔴 초과** → 세부는 초과지만 통합점수 100 미만이라 알람 X. 자주 헷갈리는 지점.
- **hot_area** = 그 순간 가장 센 영역. predicted_fault_type 의 접두사.
- **continuity_min 큼 + 점수 낮음** → 작은 정체가 오래 지속. 저절로 풀릴 수 있음.
- **STB 100% / FAB 높음** → 창고 가득 = 물류 받을 곳 없음 = 실제 정체 신호.

이 맥락을 바탕으로 m16_br_한줄분석 / m16_br_점수분석 / m16_br_reason찾기 결과를 해석해준다.
