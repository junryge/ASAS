# 방향별 밀림 감지 — 사용법 (남측/북측/허브 XGBoost)

**설계:** 통합 XGBoost(876피처, 밀림 2번만 발동 → 실패) 대신, **방향마다 그 방향 큐만
집중 학습**하는 작은 모델 3개. CUSUM을 피처로 흡수(통계+ML). 룰베이스와 병행.

**방향 = 어느 컨베이어:**
- 남측 = **4AFC3201** (6/22·6/24 밀림)
- 북측 = **4AFC3301** (6/11 정체)
- 허브 = ZT/리프터/HUB 몰림·저장 (6/29 VHL 몰림)

---

## 실행 (회사 PC, CMD) — features.csv 는 이미 있는 것 재사용

### 1) 방향별 라벨 (메신저 episode → 남/북/허브)
```cmd
python 밀림_방향라벨.py --features .\out_ml\features.csv ^
    --episodes ..\운영로그_분석_v2\output\생긴episode.csv --out .\out_ml\방향라벨.csv
```
- 확인: `남측 34 / 북측 11 / 허브 105건` (1~5월 기준)

### 2) 방향별 학습 (남/북/허브 × 10분/30분 = 모델 6개)
```cmd
python 밀림_방향학습.py --features .\out_ml\features.csv --labels .\out_ml\방향라벨.csv
```
- 출력: `out_ml\밀림방향\model_남측_pre10.json` … 6개 + feature_cols

### 3) 6월 추론 (어느 컨베이어가 밀리는지)
```cmd
python 밀림_방향추론.py --features .\out_ml_june\features.csv --model .\out_ml\밀림방향 ^
    --out .\out_ml\밀림방향_결과.csv
```

## 결과 보는 법 (`밀림방향_결과.csv`)

| 컬럼 | 뜻 |
|---|---|
| `남측_10분% / 30분% / 등급` | 남측(4AFC3201) 밀림 확률·등급 |
| `북측_… / 허브_…` | 북측(4AFC3301) / 허브 동일 |
| **`밀림방향`** | 최고등급 방향 = **"남측(4AFC3201)"** 처럼 어느 컨베이어인지 |
| **`밀림등급`** | 경계/위험/초위험 |

**게이트(오탐컷) 자동 적용:** 초위험=밤낮 항상 / 위험=주간(08~19시)만 / 경계=참고.

## 룰베이스와 병행 (하이브리드)
```
룰베이스(주력)  — 광역정체·SLA·장비·저장, 해석가능, 60분 리드
      +
밀림방향(보조)  — 룰이 조용(50미만)한데 밀림방향 뜨면 = 국소밀림 (6/24형)
                 → "남측 4AFC3201 밀림" 처럼 어느 컨베이어인지 짚어줌
```

## 재학습 주기
- 새 메신저 로그 생기면 → 파서 v2.5로 episode 만들고 → 1)~2) 재실행.
- 피처(RAW)와 라벨(episode)은 **같은 기간**이어야 함.

## 특징
- 학습 피처 방향당 6~7개(+롤링/델타/CUSUM) → 통합모델 876개보다 가볍고 해석 쉬움
- 북측은 사건 11건으로 얇음 → 재현율 낮을 수 있음(scale_pos_weight로 보정). 데이터 쌓이면 개선.
