# 하이브리드 정체 30분 사전예측 시스템 — 설계서

> 작성 2026-07-02 · M16A Hubroom 반송 정체 예측
> **핵심: 룰베이스 + 정상 TSPulse + 비정상 TSPulse → 하이브리드 판정으로 3중 교차검증**

---

## 0. 한 줄 정의

```
운영자가 메신저에 정체를 보고하기 30분 전에,
서로 다른 3개 탐지기(룰·정상ML·비정상ML)가 합의하여 '정체 전조'를 미리 알린다.
```

기존 룰베이스 하나만으로는 (1) 규칙에 없는 미묘한 전조를 놓치고, (2) 30분 선행이 어렵다.
ML 하나만으로는 (1) 정체 아닌 이상(설비작업·센서)까지 오탐하고, (2) 해석이 어렵다.
→ **셋을 합쳐 서로의 약점을 덮는다.**

---

## 1. 왜 3층인가 — 각 모델의 강점과 약점

| 탐지기 | 원리 | 강점 | 약점 | 약점을 누가 덮나 |
|--------|------|------|------|------------------|
| **룰베이스** | 도메인 임계 규칙 | 확실·설명가능·검증됨 | 경직(규칙 밖 못 봄), 선행 약함 | 정상 TSPulse |
| **정상 TSPulse** | 정상 재구성 이상탐지 | 미묘한 전조 포착, 30분 선행 | 정체 아닌 이상도 띄움(오탐) | 비정상 TSPulse |
| **비정상 TSPulse** | 정체 재구성 확인 | "진짜 정체?" 오탐 제거 | 정체 데이터 적음·파편화 | 룰베이스 |

> 세 개가 원형으로 서로를 보완한다. 어느 하나도 단독으론 완전하지 않다.

---

## 2. 3개 탐지기 상세

### 2-1. 룰베이스 (상위) — `hubroom_predictor.py` (기존)
- 9개 룰(R-A 반송시간, R-B 큐누적, R-C 리프터, R-D 저장/OHT, SLA, Sorter 등) × 8영역
- 통합 위험점수 0~100 → **등급: 경계 50~70 / 위험 71~84 / 초위험 85~100**
- 출력: `unified_risk_score`, `unified_risk_level`
- 성격: **현재~사후** 정체를 확실하게. 설명 가능(어느 컬럼이 왜 위험한지).

### 2-2. 정상 TSPulse — `ml/tspulse_train.py`, `ml/tspulse_infer.py`
- **정상 데이터만** 학습 (작업일정·정체 구간 제거 → `정상데이터_생성.py`)
- 재구성(reconstruction) 학습 → 추론 시 **재구성오차 = 이상점수 [0~1]**
- 평소와 다른 급증(정체 전조) → 오차 큼 → 이상
- 출력: `anomaly_score`, `ml_level`
- 성격: **30분 선행 조기경보**. 룰이 아직 조용할 때 전조를 먼저 잡음.

### 2-3. 비정상 TSPulse — (신규, 정상 TSPulse 대칭)
- **정체 구간만** 학습 → 정체 패턴을 재구성
- 후보 입력이 들어오면: **정체모델 재구성오차가 낮으면 = 정체 패턴에 가까움 = 정체 확정**
- 출력: `jam_match_score` (정체 유사도)
- 성격: **확인관(verifier)**. 정상모델이 띄운 이상이 "진짜 정체"인지 판정.
- ⚠️ 주의: 정체 데이터가 적고(56건) 종류가 파편화(정체/리프터/CNV/Deadlock)
  → 단일 모델이 어설플 위험. 안 되면 **정체 종류별 분리 학습** 또는 XGBoost 백업.

> **왜 XGBoost 아니고 TSPulse?** 대칭 구조(같은 파이프라인 재활용) + 시계열 네이티브 +
> 롤링/델타 수작업 불필요. 단 데이터 파편화가 크면 판별모델(XGBoost)이 유리할 수 있어 Phase에서 비교.

## 3. ★ 하이브리드 판정 — `ml/하이브리드_판정.py` (신규 핵심)

매분 3개 탐지기 출력을 받아 **합의 로직**으로 최종 판정.

### 판정 테이블
| 룰베이스 | 정상TSPulse (이상?) | 비정상TSPulse (정체?) | → 최종 판정 | 신뢰도 |
|:---:|:---:|:---:|---|:---:|
| 위험🔴 | 이상 | 정체 | **확실 정체 — 즉시 대응** | ★★★ |
| 위험🔴 | 정상 | — | **정체 (룰 근거)** | ★★ |
| **정상** | **이상** | **정체** | 🟡 **전조 경보 — 30분 선행!** ⭐ | ★★ |
| 정상 | 이상 | 정체아님 | ⚪ 무시 (설비작업·센서튐) | — |
| 정상 | 정상 | — | ✅ 안전 | — |

### 이 시스템의 진짜 가치 = 3번째 줄
> 룰은 아직 조용한데(정상), 정상TSPulse가 전조를 잡고(이상), 비정상TSPulse가 "정체 맞다" 확인.
> → **룰보다 30분 먼저 경보.** 그리고 4번째 줄로 **오탐(정체 아닌 이상)을 걸러냄.**

### 신뢰도 = 합의 수
- 3개 중 몇 개가 "정체"에 동의하는지로 신뢰도 등급 (★★★ / ★★ / ★)
- 운영 초기엔 **★★★(3개 합의)만 알람** → 신뢰 쌓이면 점차 ★★로 확대

## 5. 구현 순서 (Phase)

| Phase | 작업 | 산출물 | 게이트 |
|---|---|---|---|
| 1 | 정상 데이터 생성 + 31피처 | `정상데이터.csv`, `features.csv` | 데이터 준비 ✅ |
| 2 | 정상 TSPulse 학습·추론 | `anomaly.csv` | 점수 나옴 ✅(진행) |
| **3** | **정상모델 선행성 검증** | 검증 리포트 | **★ 30분 선행 확인** |
| 4 | 비정상 TSPulse 학습 (정체 구간) | `jam_match.csv` | 정체 유사도 나옴 |
| 5 | **하이브리드 판정 구현** | `하이브리드_판정.py` | 판정 테이블 동작 |
| 6 | 룰 + ML 병행 운영 | 운영 적재 | 실측 신뢰 |

## 6. 위험요소 & 대비

| 위험 | 대비 |
|------|------|
| 정상 TSPulse가 정체에 선행 안 함 | Phase 3 게이트 — 미달 시 피처/윈도우 튜닝 |
| 비정상 TSPulse 데이터 부족·파편화 | 정체 종류별 분리 학습 / XGBoost 백업 / 룰로 대체 |
| 3개 불일치 시 판정 모호 | 신뢰도 등급 + 초기엔 3개 합의만 알람 |
| 이상 ≠ 정체 (설비작업 FP) | 비정상모델 + 작업일정 제거로 이중 차단 |
| 폐쇄망 모델 반입 | TSPulse 초경량(1M) 오프라인 반입 |

## 7. 요약 — 한 장

- **문제**: 룰만으론 전조를 놓치고, ML만으론 오탐이 많다.
- **해법**: 룰 + 정상ML + 비정상ML **3중 교차검증 → 하이브리드 판정**
- **가치**: 정체 **30분 사전 경보** + **오탐 제거** + **해석 가능**
- **핵심 문장**: *"세 개가 합의하면 진짜다."*
