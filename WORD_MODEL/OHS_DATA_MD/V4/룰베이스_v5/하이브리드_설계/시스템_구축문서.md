# M16A HUBROOM 반송 정체·밀림 사전예측 시스템 — 구축 문서

> **작성**: 2026-07-08 · **제작**: John Forest
> **목표**: 정체·병목·몰림·밀림을 **10분/30분 전** 사전 예측
> **최종 성과 (6월 홀드아웃, 운영자 전수 채점)**: 목표 4개 사건 **4/4 탐지 (13~44분 전)** + 6/2·6/5·6/19 정탐
> **실측 경보 적중률**: 30분 **54%** (40/74구간) · 10분 **56%** (37/66구간) — 오탐 41%/36%

---

## 1. 시스템 개요

### 1.1 무엇을 예측하나
M16A HUBROOM(M16↔M14 Bridge)의 **반송 정체/병목/몰림/밀림**을 발생 10분/30분 전에 경보한다.
정답 기준 = **운영 메신저에서 운영자가 실제 확인·조치한 사건** (예: "16>14 밀림현상 지속되어 A_IN 차단").

### 1.2 최종 아키텍처 (한눈에)

```
[원본 RAW 265컬럼/분]
      │
      ▼
① features_31.py ──────────── 핵심 43피처
      │   RA 반송시간(7) · RB 큐(6) · RD 저장(7,STK포함) · SLA(5)
      │   SORTER(5) · AUX(2) · BR Bridge-SOP 방향큐(4) · DIR M16→M14 국소(7)
      ▼
② 피처병합_발동이벤트.py ──── +hubroom 전문가 30컬럼 = 73피처
      │   unified_risk_score · 영역점수 5 · ra_count 5 · rb_diff10/30 10
      │   rc_trend · cnv_skew · 리프터역증가 · score_raw 5
      ▼
③ xgb_비정상_train.py 내부 파생 ── 73 × 12 = 876피처
      │   롤링평균/표준편차(15·30·60분) · 60분최대 · 델타(15·30·60분)
      │   ★ CUSUM(누적상승) — 서서히 밀리는 조짐 포착
      ▼
④ XGBoost 2모델 (y_pre10 / y_pre30)
      │            ┌─ 저장룰: STK≥10 하드 / (FAB≥25 or STB≥99) AND 4분초과≥5
      ├─ 병렬 룰 ──┤
      │            └─ CUSUM 밀림룰: 남큐/북큐 CUSUM≥600 · 저장 CUSUM≥300
      ▼                (임계 배수로 경계/위험/초위험)
⑤ 최종판정 = max(XGBoost등급, 저장룰, 밀림룰) + 사유 표기
      ▼
⑥ 경보요약.py ── 경보 구간만 압축 (10분/30분 2파일, 사람이 보는 것)
```

### 1.3 정답(라벨) 파이프라인 — 이 시스템의 심장

```
운영 메신저 TXT ──운영로그_파서_v2.py──▶ episode.csv (사건 시각·유형·장비)
                                              │
hubroom 발동이벤트 (점수≥50) ────────────────┤ 합집합
수동 확인 사건 (--manual) ───────────────────┘
                                              ▼
                              xgb_라벨_통합.py ──▶ y_pre10 / y_pre30
                              (t+1~t+P분 안에 사건 있으면 1)
```

**핵심 설계 결정**: hubroom 점수만으로 라벨하면 국소 밀림(점수 12~47=정상)을 영원히 못 배운다.
**고객이 실제 확인한 메신저 사건**을 정답에 합쳐야 ML이 몰림 클래스를 학습한다. (§3 참조)

## 2. 핵심 기술 상세

### 2.1 피처 (입력 X)

| 그룹 | 개수 | 내용 | 왜 필요한가 |
|---|---|---|---|
| RA 반송시간 | 7 | 영역별 평균 반송/적재 시간 | 정체의 결과 지표 |
| RB 큐 | 6 | HUB향 Job 큐 | 정체의 원인 지표 |
| RD 저장 | 7 | FAB저장률·STB·**STK**·OHT가동률 | 저장Full형 정체 |
| SLA | 5 | 4분초과 반송비율 | "실제 막힘" 확인 |
| SORTER | 5 | 소터 대기초과 | 소터발 정체 |
| BR (SOP) | 4 | **방향별 ZT큐 합**(3F→6F/6F→3F)·HUB총큐·방향불균형 | 고객 SOP 발동기준 그대로 |
| DIR (국소) | 7 | **M16→M14 방향 큐·남/북측 컨베이어 큐·시간** | 4AFC 국소 밀림 = 목표 사건 |
| 전문가 (발동이벤트) | 30 | hubroom 룰엔진의 계산 신호 | 수년치 도메인 지식 재활용 |

### 2.2 파생 — 시간의 흐름을 보는 눈 (피처당 12개)

| 파생 | 잡는 것 |
|---|---|
| 롤링평균 15/30/60분 | 수준(level) 변화 |
| 롤링표준편차 15/30/60분 | 불안정성 |
| 60분 최대 | 급증 피크 |
| 델타 15/30/60분 | 추세 방향 |
| **CUSUM** | **누적 상승 = 서서히 밀리는 조짐** ★ |

**CUSUM 공식** (밀림 탐지의 핵심):
```
C(t) = max(0, C(t-1) + [x(t) − 직전120분 중앙값 − 0.5×표준편차])
```
- 순간 스파이크: 한 번 튀고 끝 → 누적 안 됨 → 무시
- 지속 상승: 조금씩이라도 계속 높음 → **쌓여서 폭발** → 경보
- 절대 임계로는 노이즈에 묻히던 국소 밀림(큐 66→108)이 CUSUM으론 뚜렷해짐 (270→1007)

### 2.3 모델 — XGBoost 2개

| | y_pre10 (10분 전) | y_pre30 (30분 전) |
|---|---|---|
| 용도 | 임박 경보 | 여유 경보 |
| PR-AUC (학습 내부검증) | 0.547 | 0.545 |
| 정밀도 p≥0.5 (학습 내부검증) | 82% | 87% |
| 신뢰 95% 지점 (학습 내부검증) | p≥0.85 | p≥0.60 |
| **6월 실측 경보 적중 (운영자 채점)** | **56% (37/66구간)** | **54% (40/74구간)** |

※ 위 3행은 4~5월 학습기간 내부검증 수치. **실전 성적의 기준은 6월 실측(마지막 행)** — §4.3 상세.

- `scale_pos_weight` 로 불균형(양성 5.8~10%) 보정
- 등급 = **정밀도(그 경보가 맞을 확률) 기반 캘리브레이션** — "위험=신뢰80%+" 처럼 근거 있는 등급

### 2.4 룰 안전망 (ML과 병렬, max 결합)

| 룰 | 조건 | 커버 |
|---|---|---|
| 저장룰 | STK≥10%(하드) / (FAB≥25 or STB≥99) **AND** SLA 4분초과≥5% | 저장Full형. AND 조건이 6/4형(저장만 튐·소화됨) 오탐 차단 |
| CUSUM 밀림룰 | 남/북큐 CUSUM≥600 · 저장 CUSUM≥300, 배수로 등급 | 국소 밀림. ML이 놓쳐도 잡는 안전망 |

### 2.5 누수(leakage) 차단 원칙

1. 모든 피처는 **t 이전 데이터만** (롤링·CUSUM 전부 과거창)
2. 라벨은 **t 이후** (y_preP = t+1~t+P분 내 사건)
3. 학습/검증 **시간 분할** (뒤쪽 25% 검증)
4. **6월은 완전 홀드아웃** — 학습에 단 1분도 안 씀. 날짜/사건 하드코딩 없음

## 3. 개발 여정 — 무엇을 시도했고 왜 그 결론에 도달했나

| 단계 | 시도 | 결과 | 배운 것 |
|---|---|---|---|
| 1 | **TSPulse R1** (정상 재구성 이상탐지) | 과탐지 25%/일 | 자기참조 정규화가 원인 |
| 2 | TSPulse + 고정 기준선(P95) | 과탐지 6%, 6/5 262분 전 탐지 | 큰 정체는 잡지만 국소밀림 못 봄, 512분 고정 한계 → **제외** |
| 3 | **XGBoost + hubroom 라벨** | 6/2·6/5 정탐(정밀도 77%), 국소밀림 0/4 | 라벨 문제 의심 시작 |
| 4 | 방향피처(DIR)·STK 추가 후 재학습 | 여전히 0/4 | 피처가 아니라 **정답이 문제** |
| 5 | **원인 확정**: 발동이벤트 원본 확인 | 4개 사건 hubroom 점수 12~47 = "정상" | **hubroom 라벨로는 영원히 못 배움** (증명) |
| 6 | SOP 분석 (Bridge Time 5분↑ 기준) | 4개 모두 BT 상승 확인, 但 절대임계는 노이즈(6월 BT 중앙값 5.85 만성 과부하) | 절대값 ✗ → **상대 누적** 필요 |
| 7 | **CUSUM 밀림룰** | **4/4 탐지 (13~30분 전)**, 오탐 8.8% | 누적상승이 정답 신호 |
| 8 | **메신저 정답 + 발동이벤트 피처 + CUSUM 피처로 재학습** | ML 자체가 6/29 몰림·6/2·6/5·6/19 직접 탐지, 30분 신뢰도 77%벽→99% 돌파 | **정답을 바꾸니 ML이 배웠다** |

**교훈 한 줄**: 실패의 원인은 모델이 아니라 **정답지**였다. hubroom(고정 임계)이 못 보는 사건을 hubroom 라벨로 가르칠 수는 없다.

## 6. 사용법

### 6.1 학습 (최초 1회 / 데이터 추가 시)

```cmd
:: 0. 피처 생성 (4~5월 RAW → 43피처)
python features_31.py --raw .\RAW --start 2026-04-01 --end 2026-05-31 --out .\out_ml

:: 0-1. hubroom 발동이벤트 (없으면)
for %f in (RAW\*.CSV) do python hubroom_predictor.py "%f" -o .\predict_tobe

:: 1. 메신저 → 사건 추출
python 운영로그_파서_v2.py 4월_5월.TXT --out .\ep45

:: 2. 전문가 피처 병합 (43→73)
python 피처병합_발동이벤트.py --features .\out_ml\features.csv --events .\predict_tobe --out .\out_ml\features_확장.csv

:: 3. 통합 라벨 (메신저 + hubroom)
python xgb_라벨_통합.py --features .\out_ml\features_확장.csv --episodes .\ep45\{생성된}_episode.csv --events .\predict_tobe --out .\out_ml\labels_통합.csv

:: 4. 학습 (10분/30분 2모델)
python xgb_비정상_train.py --features .\out_ml\features_확장.csv --labels .\out_ml\labels_통합.csv
```

**체크포인트**: ②매칭률 90%+ · ③`[메신저] episode N건` 필수 · ④top5에 전문가/CUSUM 피처

### 6.2 예측 (새 기간 평가 / 운영)

```cmd
:: 1. 새 기간 피처 (예: 7월)
python features_31.py --raw .\OUT_7 --start 2026-07-01 --end 2026-07-31 --out .\out_ml\july
for %f in (OUT_7\*.CSV) do python hubroom_predictor.py "%f" -o .\predict_tobe_7
python 피처병합_발동이벤트.py --features .\out_ml\july\features.csv --events .\predict_tobe_7 --out .\out_ml\july\features_확장.csv

:: 2. 추론 → 3. 요약
python xgb_비정상_infer.py --features .\out_ml\july\features_확장.csv --model .\out_ml\xgb --out .\out_ml\july_final.csv
python 경보요약.py --infile .\out_ml\july_final.csv
```

→ **`경보요약_10분.csv` / `경보요약_30분.csv`** 만 보면 됨 (경보 구간·등급·예측대상시각·최고확률·사유)

### 6.3 월별 갱신 (권장 운영 사이클)

1. 새 달 메신저 TXT → 파서 → episode 추가
2. 새 달 RAW → 피처·발동이벤트 추가
3. §6.1의 ③~④ 재실행 (episode 파일 쉼표로 여러 개: `--episodes ep45.csv,ep6.csv`)
4. 직전 달은 항상 홀드아웃으로 먼저 검증 후 편입

### 6.4 조정 손잡이

| 손잡이 | 위치 | 기본값 | 효과 |
|---|---|---|---|
| hubroom 라벨 임계 | 라벨 `--thr` | 50 | ↓민감 ↑엄격 |
| 사건 지속 간주 | 라벨 `--dur/--maxdur` | 10/60분 | 라벨 양성폭 |
| 큐 CUSUM 임계 | infer `TH_CUSUM_Q` | 600 | 밀림룰 민감도 |
| 저장 CUSUM 임계 | infer `TH_CUSUM_FAB` | 300 | **야간 오탐 줄이려면 450** |
| ML 등급컷 | infer `level()` | 캘리브레이션 근거 | 재학습 시 캘리브레이션 표 보고 갱신 |

## 7. 한계와 다음 단계

1. **오탐 ~40%** (대부분 야간 저장 CUSUM) → 임계 상향/야간 둔감화로 절반 감축 가능
2. **급발성 사건** (에러가 그 순간 터짐)은 물리적으로 30분 전 예측 불가 → 실시간 룰(hubroom)이 담당
3. **ML의 밀림 학습은 시작 단계** (6/29·6/19 직접 탐지) — 매달 메신저 사건이 쌓일수록 ML 비중↑, 룰 의존↓
4. 향후: 7월 데이터로 재검증 → 6월 편입 재학습 → LLM 진단 리포트(어디서·왜·SOP 조치) 연결
