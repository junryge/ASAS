# 룰베이스 사건 탐지 구조 요약

> S3 (사건단위 확정) = **R-A' AND R-C' AND (R-B OR R-D)**
> = 시간 AND 위치 AND (양 OR 공간)

---

## 1. 4가지 룰 — 잡는 패턴

| 룰 | 잡는 패턴 |
|---|---|
| **R-A'** | 반송이 비정상적으로 느려짐 (1MIN 9분+) |
| **R-B** | M14→M16 큐 누적 (느린 폭주) |
| **R-C'** | 특정 리프터에 큐 몰림 (구조적 데드락) |
| **R-D ★** | FAB 저장공간 가득참 (5/7 SFA 정체 같은 케이스) |

---

## 2. 구조적 흐름

```
                  ┌─── R-A' (반송 시간) ────── "OHT가 느려졌나?"
                  │
정체 발생   ──┼─── R-B  (M14→M16 큐) ──── "큐가 쌓이나?"
                  │
                  ├─── R-C' (리프터 몰림) ─── "한쪽으로 쏠리나?"
                  │
                  └─── R-D  (FAB 저장률) ──── "저장공간이 막혔나?"

      ▼
  S3 (사건단위 확정) = R-A' AND R-C' AND (R-B OR R-D)
                       └─시간─┘└─위치─┘└─양/공간─┘
```

---

## 3. 정체 유형별 대응

| 정체 유형 | 잡는 룰 | 예시 |
|---|---|---|
| 일반 데드락 (4/21 형식) | R-A' + R-B + R-C' | 검증 케이스 |
| 폭주형 (M14에서 큐 빠르게 쌓임) | R-A' + R-B-FAST + R-C' | 빠른 누적 |
| **공간 막힘형 (SFA/저장 가득) ★** | R-A' + R-D + R-C' | **5/7 7시** |
| 단순 트래픽 변동 | 1개만 발동 → S1/S2 | 사건단위 안 잡음 |

---

## 4. 룰별 사용 컬럼 (실제 신호)

### R-A' — 반송 시간

**컬럼**: `M16HUB.QUE.TIME.AVGTOTALTIME1MIN` (1분 평균 반송시간, 분 단위)

| 조건 | 임계값 | 예시 (5/7 7시) |
|---|---|---|
| R-A' 절대 | 최근 10분 중 1MIN ≥ **9.0분** 1회+ | 07:35 1MIN = 8.55분, 07:45 = 9.84분 |
| R-A' 지속 | 최근 5분 중 1MIN ≥ **6.0분** 3회+ | 07:00~07:30 1MIN 7~10분 지속 |

---

### R-B — M14→M16 큐 누적

**컬럼**: `M16HUB.QUE.M14TOM16.MESCURRENTQCNT` (M14→M16 브릿지 큐 수)

| 조건 | 임계값 | 예시 |
|---|---|---|
| R-B 느린 | 30분 전 대비 **+100 이상** | 4/21 정체 시 +112, +136 |
| R-B FAST | 10분 전 대비 **+30 이상** | 5/7 07:08 10분Δ=+37 |

---

### R-C' — 리프터 역증가 (10개 리프터)

**컬럼** (10개 합산):
```
M16HUB.LFT.6ABL6011.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL6012.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL6021.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL6022.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL6031.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL6032.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL0111.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL0112.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL0121.TOTAL_CURRENTQCNT
M16HUB.LFT.6ABL0122.TOTAL_CURRENTQCNT
```

| 조건 | 임계값 | 의미 |
|---|---|---|
| 합 감소 | 20분 전 대비 합 < 0 | 전체적으론 큐가 처리됨 |
| 개별 증가 | 큐가 늘어난 리프터 **2개 이상** | 특정 리프터로 몰림 |

**예시** (5/7 07:32):
- 4/21 정체 시: `6ABL6031`, `6ABL6032`, `6ABL0111`, ... 6개 역증가
- 즉 시스템 전체는 흐르는데 일부 리프터만 막힘 = 데드락

---

### R-D ★ — FAB 저장률

**컬럼**: `M16HUB.STRATE.ALL.FABSTORAGERATIO` (FAB 내부 저장 사용률 %)

| 조건 | 임계값 | 예시 (5/7) |
|---|---|---|
| 저장률 임계 | **25.0% 이상** | 07:00 = 10%, 07:30 = 24%, 07:40 = **31%** |

| 시점 | 5/7 FABSTORAGE | 5/8 정상 |
|---|---:|---:|
| 0시 | 0% | 0% |
| 6시 | 5% | 1% |
| **7:30** | **24%** ★ | 0.6% |
| **7:40** | **31%** ★ | 0.5% |
| 9시 | 26% | 1% |
| 12시 | 5% | - |

→ 5/7 7시 정체 시점에 명확히 spike. 5/8 정상시간은 거의 0.

> **핵심**: 시간(R-A') + 위치(R-C') + 양/공간(R-B 또는 R-D) **셋 다 동시에** 켜져야 진짜 데드락으로 인정.
> 한 가지만 켜지면 그냥 경고(S1/S2)로 남고 사건은 기록 안 함 → 위양성 적음.
