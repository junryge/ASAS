## 2. 핵심 개념 — 포트 식별과 명명 규칙

### 2.1 리프터 식별자
- 리프터 장비 = 포트명 prefix `*ABL*` (예: `6ABL0111`, `4ABL3304`)
  - `BL` = 리프터. `LF`(예: `4ALFA201`)도 리프터 계열.
- FAB 첫 자리 = 동/호기 계열 (M14 → `4ABL`, M16 → `6ABL`)

### 2.2 포트명 구조: `<리프터>_<방향><층><번호>`
```
6ABL0111_AI313
└──┬───┘ └┬┘└┬┘
 리프터   │  └ 층(3=3F) + 포트번호
          └ AI=Arrival In(입고), AO=Arrival Out(출고)
```
- `AI` = **IN** (OHT가 캐리어를 리프터에 **내려놓는** 곳)
- `AO` = **OUT** (OHT가 리프터에서 캐리어를 **집어가는** 곳)
- 첫 숫자 = 층 (`AI3xx`=3F, `AI6xx`=6F, `AI2xx`=2F)

### 2.3 🚨 함정: station_no ≠ address
`station.dat` 한 줄 구조:
```
STATION = <station_no>,"<타입>",1,"<포트명>",0x<flags>,1,<address>, ... ,<draw정보>, ...
            ^^^^^^^^^^                ^^^^^^^^              ^^^^^^^
            필드[0]                   필드[3]               필드[6] = 진짜 주소
```
예:
```
STATION = 1001,"DUAL_ACCESS",1,"6ABL0111_AI313",0x00000005,1,2357, ...
```
→ station_no `1001`, 포트 `6ABL0111_AI313`, **주소 `2357`**

**station_no(1001)를 주소로 착각하면 전부 틀린다.** 좌표 조인은 반드시 **주소(2357)** 로 한다.

## 3. 산출 절차 (4단계)

### STEP 1 — station.dat 파싱: 포트 → (station_no, 주소)
```python
import re
port_info = {}
for line in open("OHT_MAP/MAP/M16A/BR.station.dat", encoding="utf-8", errors="replace"):
    if "ABL" not in line:           # 리프터 포트만
        continue
    m = re.search(r'STATION\s*=\s*(.+)', line)
    if not m:
        continue
    parts = [p.strip().strip('"') for p in m.group(1).split(",")]
    st, port, addr = int(parts[0]), parts[3], int(parts[6])
    if "_AI" in port or "_AO" in port:
        port_info[port] = (st, addr)
```

### STEP 2 — layout.xml 파싱: 주소 → (X, Y)
`layout.xml`의 각 `Addr` 그룹(`class="...address.Addr"`)에서 `address`, `draw-x`, `draw-y` 추출.
```python
import re, zipfile
addr_class = re.compile(r'class="[^"]*\.address\.Addr"')
gopen = re.compile(r'<group\b')
key_re = re.compile(r'\bkey="([^"]+)"'); val_re = re.compile(r'\bvalue="([^"]*)"')

with zipfile.ZipFile("OHT_MAP/MAP/M16A/BR.layout.zip") as zf:
    xml = zf.read("layout/layout.xml").decode("utf-8", "replace")

node_xy, cur = {}, None
def commit(c):
    if c and "address" in c:
        a = int(c["address"])
        if a > 0:
            node_xy[a] = (float(c.get("draw-x", 0)), float(c.get("draw-y", 0)))
for line in xml.split("\n"):
    line = line.strip()
    if gopen.search(line) and addr_class.search(line):
        commit(cur); cur = {}; continue
    if cur is not None and line.startswith("<param"):
        k, v = key_re.search(line), val_re.search(line)
        if k and v: cur[k.group(1)] = v.group(1)
commit(cur)
```
> 속성 순서는 FAB마다 다를 수 있으니 key/value를 **개별 정규식**으로 뽑는다(순서 무관).

### STEP 3 — 조인: 포트 → 주소 → 좌표
```python
rows = []
for port, (st, addr) in sorted(port_info.items()):
    lifter, sub = port.split("_")
    direction = "IN" if sub.startswith("AI") else "OUT"
    floor = sub[2] + "F"
    x, y = node_xy.get(addr, ("", ""))
    rows.append([lifter, port, direction, floor, st, addr, x, y])
```

### STEP 4 — 출력 (CSV)
```
Lifter,Port,Direction,Floor,Station_No,Address,X,Y
6ABL0111,6ABL0111_AI313,IN,3F,1001,2357,9591.7,1913.1
6ABL0111,6ABL0111_AO311,OUT,3F,1015,2374,9494.3,1976.7
...
```

## 4. 검증 방법
1. **매칭율**: 모든 포트의 주소가 `layout.xml` 노드에 있어야 함 → `좌표 매칭 = N/N (miss 0)` 확인.
2. **유일성**: IN 포트 주소가 포트별로 분산되는지(같은 stub 공유는 정상이나 전부 동일하면 의심).
3. **공간 군집**: 같은 리프터의 포트 좌표가 서로 가깝게 모여야 함(리프터 footprint).
4. **층 일관성**: 포트명 층(`AI3xx`)과 실제 좌표가 같은 레벨 station.dat에서 나왔는지.

## 5. ❌ 하면 안 되는 방법 (로그 휴리스틱) — 왜 틀리나

LOGPRESSO `oht_data` / `ts_resource` 로그로 추정하면 **전부 빗나간다.**

| 시도 | 결과 | 실패 이유 |
|------|------|-----------|
| `DEST_RETURN_PORT` ↔ `DESTINATION` 최빈값 | station_no를 주소로 오인 | DESTINATION이 station_no거나 경유 waypoint |
| 도착시점(`ADDRESS==DESTINATION`) | 표본 1~40개, 값 흔들림 | 도착 순간 로그가 드묾 |
| `DISTANCE` 최소/최대 극단값 | 여러 포트가 같은 junction 주소로 뭉개짐(1057, 1916...) | 로그엔 **본선 레일 통과만** 찍히고 포트 stub은 안 찍힘 |

**근본 원인**: 운행 로그는 차량이 *지나가는 본선*을 기록할 뿐, 포트 stub의 고유 주소를 직접 남기지 않는다. 포트의 물리 주소·좌표는 **설계 데이터(station.dat/layout.xml)에만** 존재한다.

## 6. 범위 — M16_BR (3F) 만

본 방법은 **M16A_BR = 3F 레벨**만 대상으로 한다. `BR.station.dat`에는 3F 포트(`AI3xx/AO3xx`) **60개**(리프터 10기 × IN 3 + OUT 3)만 들어있고, 결과도 전부 3F다.

> 리프터가 물리적으로는 6F/2F까지 잇지만, 그 반대편 포트는 다른 레벨 패키지(`A.*`, `E.*`)에 있다. **이번 범위에서는 다루지 않는다.** 필요해지면 같은 절차를 그 파일에 반복하면 된다.
