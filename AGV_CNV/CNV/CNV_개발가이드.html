CNV (Conveyor) 개발 가이드

SK Hynix Fab 환경 — Atlas 서버 UDP 수신 기반 CNV 시스템 개발 레퍼런스

1. 시스템 아키텍처

CNV 시스템의 전체 구조는 다음과 같습니다:

┌──────────┐ SECS/GEM ┌──────────────┐ UDP/IP ┌───────────────┐ │ HOST │◄────────────►│ FabScope │◄──────────►│ STK MCP7 │ │ (MES/ERP)│ │ (SysView+MSS)│ 3600/3500 │ (CNV 제어) │ └──────────┘ └──────┬───────┘ └───────┬───────┘ │ │ UDP/IP│ TCP/IP │ AMP Remote.DLL │ │ ┌──────▼───────┐ ┌───────▼───────┐ │ Atlas 서버 │ │ CNV 설비 │ │ (UDP 수신) │ │ 프로그램 │ └──────────────┘ └───────────────┘

시스템은 크게 다음과 같이 구성됩니다:

  • HOST (MES/ERP): 상위 시스템
  • FabScope (SysView+MSS): 제어 및 모니터링 시스템
  • STK MCP7: CNV 제어 장비
  • Atlas 서버: UDP 패킷 수신 및 처리
  • CNV 설비 프로그램: AMP Remote.DLL을 통한 제어

5.2 CNV 데이터 수집 (MonitorGetData) ★ ▼ 
public void GetData(string EQPID, CRemoteObject Obj)
{
    // 필수: 상태
    Obj.ControlState = eControlState.ONLINE_LOCAL;
    Obj.SCState      = eSCState.RUN;
    Obj.EQMode       = eEqMode.OPERATOR;

    // 필수: Alarm
    Obj.AlarmInfo ??= new Dictionary<string, Alarm>();

    // 필수: Carrier / Transfer
    Obj.CarrierInfo ??= new Dictionary<string, Carrier>();
    Obj.TrInfo      ??= new Dictionary<string, Transfer>();

    // ★ CNV 전용: Conveyor 정보
    Obj.ConveyorInfo ??= new Dictionary<string, Conveyor>();
    // → 각 Conveyor Unit의 상태, CarrierID, ProcessStatus 등

    // 선택: Shelf, Port, Zone
    Obj.ShelfInfo ??= new Dictionary<string, Shelf>();
    Obj.PortInfo  ??= new Dictionary<string, Port>();
    Obj.ZoneInfo  ??= new Dictionary<string, Zone>();
}
5.3 CNV 전용 조작 명령 ★ ▼

CNV는 AGV와 달리 Home, StepClear, DataClear 명령이 추가로 있습니다.

eAckCode OperationHandler(IPAddress ip, eRemoteCommand cmd, string unitID)
{
    switch (cmd)
    {
        case eRemoteCommand.Run:        // 운전
        case eRemoteCommand.Stop:       // 정지
        case eRemoteCommand.AlarmClear: // 알람 해제

        // ★ CNV 전용 명령
        case eRemoteCommand.Home:       // Servo Home
        case eRemoteCommand.StepClear:  // Step Clear
        case eRemoteCommand.DataClear:  // Data Clear

        case eRemoteCommand.SetPMMode:  // PM 모드
    }
    return eAckCode.Ack; // 불가시 eAckCode.Nak
}

  • MonitorGetData: Conveyor, Alarm, Carrier, Transfer 수집
  • OperationEvent: Run/Stop/AlarmClear/Home/StepClear/DataClear/SetPMMode
  • TransferEvent: Creat/Cancel/Abort
  • CarrierEvent: Install/Remove
  • ControlStatusEvent / EQModeEvent

CNV 고유 관리

  • Conveyor Unit 상태 관리 (Kind=3,6,7)
  • Transfer.State=10 (Moving) 처리
  • Transfer.ArrivedTime 도착 시간 관리
  • Zone 정보 관리 (Text ID:21)
  • 재하 정보 관리 (Text ID:202)
  • 정체 감지 및 보고 (Text ID:203)
  • Buffer Full 상태 모니터링

  • OhtUdpListener 구현 (UDP 수신)
  • Message Parsing (CSV 토큰 분석)
  • CnvEdge 모델 구현 (평균 이동 시간)

  • Logpresso 쿼리 및 API 통합

8. Atlas Server — Java UDP 수신 및 Logpresso 저장

Atlas 서버에서 STK MCP가 보내는 UDP 패킷을 수신하여 CNV 트래픽 데이터를 Logpresso 데이터베이스에 저장합니다. 이 섹션에서는 UDP 리스너, 메시지 파싱, CnvEdge 모델, Logpresso 저장 및 배치 처리에 대해 설명합니다.

8.1 OhtUdpListener (UDP Socket Code) ▼

UDP 패킷을 수신하는 메인 리스너 클래스입니다. 별도의 스레드에서 실행되며, 수신된 메시지를 DataService 큐에 추가합니다.

public class OhtUdpListener implements Runnable {
    private DatagramSocket socket;
    private byte[] buffer = new byte[1500];

    public void run() {
        while (!Thread.currentThread().isInterrupted()) {
            DatagramPacket packet = new DatagramPacket(buffer, buffer.length);
            socket.receive(packet);
            String message = new String(packet.getData()).trim();

            Msg msg = new Msg();
            msg.setFabId(fabId);
            msg.setMcpName(mcpName);
            msg.setMsg(message);

            DataService.getInstance().queue.add(msg);
        }
    }
}

주요 특징:

  • 1500 byte MTU 버퍼로 UDP 패킷 수신
  • 수신 메시지를 Msg 객체로 래핑
  • DataService 큐에 추가 (비동기 처리)
  • Thread 인터럽션으로 안전한 종료
8.2 Message Parsing ▼

수신된 CSV 형식 메시지를 토큰으로 분석하고 Text ID별로 처리합니다.

String[] tokens = StringUtils.splitPreserveAllTokens(msg.getMsg(), ',');

switch (tokens[0]) {
    case "1":
        _processMcpOnline(tokens, msg);
        break;

    case "4":
        // ★ CNV 핵심: 기기 상태 보고
        _processDeviceStatus(tokens, msg);
        break;

    case "201":
        _processCarrierLocation(tokens, msg);
        break;

    case "202":
        _processCarrierReload(tokens, msg);
        break;

    case "203":
        _processTraffic(tokens, msg);
        break;
}

파싱 규칙:

  • StringUtils.splitPreserveAllTokens() 사용 (빈 필드 보존)
  • tokens[0]: Text ID (메시지 타입)
  • tokens[1]: MCP 명칭
  • tokens[2+]: 기종번호, 기기명, 상태 등
  • Text ID별 핸들러로 라우팅
8.3 CnvEdge Model (Conveyor-specific) ▼

컨베이어 간선의 이동 비용(평균 이동 시간)을 관리하는 모델입니다. 실시간 트래픽 데이터를 기반으로 동적으로 업데이트됩니다.

public class CnvEdge extends AbstractEdge {
    private long avgTransferIntervalT = 150; // 평균 이동 시간 (ms)

    public long getCost(String carrierId) {
        return avgTransferIntervalT;
    }

    public void addCost(long newCost) {
        // 범위 제한: 300ms ~ 30초
        newCost = Math.max(300, Math.min(newCost, 30000));

        // 가중 이동평균 적용
        double w = PredictionPara.getInstance().getLastHisWeight();
        setAvgTransferIntervalT(
            (long)((avgTransferIntervalT * w) + ((1.0 - w) * newCost))
        );
    }

    public void setAvgTransferIntervalT(long val) {
        this.avgTransferIntervalT = Math.max(300, Math.min(val, 30000));
    }

    public boolean isAvailable() {
        return getFromNode().isAvailable() && getToNode().isAvailable();
    }
}

주요 기능:

  • avgTransferIntervalT: 간선의 평균 이동 시간 (기본값 150ms)
  • getCost(): 경로 계산용 비용 반환
  • addCost(): 새로운 이동 시간 데이터로 평균 업데이트
  • 가중 이동평균(EMA) 적용으로 최신 데이터 반영
  • 범위 제한: 최소 300ms, 최대 30초
  • isAvailable(): 양쪽 노드 상태 확인

Logpresso 데이터베이스에 CNV 데이터를 저장하는 두 가지 방법입니다.

방법 1: 직접 삽입 (Direct Insert)

// ATLAS_HID_INFO 테이블에 데이터 삽입
Tuple tuple = new Tuple();

방법 2: 유틸리티 래퍼 (Utility Wrapper)

// TrafficBatch 또는 다른 Job에서 사용
Util.insertInLogpressoDatabase(

8.5 TrafficBatch (1분 배치) ▼

1분 주기로 실행되는 스케줄 Job입니다. 현재 Rail Edge 상태를 수집하여 Logpresso에 저장합니다.

public class TrafficBatch implements Job {
    @Override
    public void execute(JobExecutionContext ctx) {
        List<Tuple> logpressoData = new ArrayList<>();

        // 모든 Rail Edge 순회
        for (RailEdge edge : railEdges) {
            Tuple t = new Tuple();
            t.put("createTime", System.currentTimeMillis());
            t.put("railEdgeId", edge.getId());
            t.put("velocity", edge.getVelocity());
            t.put("maxVelocity", edge.getMaxVelocity());
            t.put("vhlCnt", edge.getVehicleCount());
            t.put("HID_ID", edge.getHIDId());

            logpressoData.add(t);
        }

        // Logpresso 테이블에 배치 삽입
        Util.insertInLogpressoDatabase(
            logpressoData,
            "ATLAS_RAIL_TRAFFIC",
            "TrafficBatch"
        );
    }
}

스케줄 설정:

// Quartz Scheduler에서 1분 주기로 실행
CronScheduleBuilder.cronSchedule("0 * * * * ?");  // 매 분 정각

주요 필드:

  • createTime: 데이터 수집 시점 (밀리초)
  • railEdgeId: 간선 고유 ID
  • velocity: 현재 속도
  • maxVelocity: 최대 속도
  • vhlCnt: 간선상 차량 수
  • HID_ID: 하드웨어 식별자
8.6 Logpresso Table Structure ▼

Atlas 서버에서 사용하는 Logpresso 테이블 구조입니다.

테이블 1: ATLAS_HID_INFO (HID 정보 - 마스터)

필드명 타입 설명 예시
FAB_ID String Fab 고유 ID FAB01
MCP_NM String MCP 명칭 STK_MCP01
HID_ID String 하드웨어 ID HID_001
START String 시작 주소 Port1
ADDRESS String 실제 주소 Zone_A_01

테이블 2: ATLAS_RAIL_TRAFFIC (철도 간선 트래픽 - 트랜잭션)

필드명 타입 설명 예시
createTime long 생성 시간 (밀리초) 1708929600000
fabId String Fab ID FAB01
railEdgeId String 간선 고유 ID EDGE_001
velocity double 현재 속도 (m/s) 1.5
maxVelocity double 최대 속도 (m/s) 2.0
vhlCnt int 간선상 차량 수 3
HID_ID int 하드웨어 ID 303

테이블 설계 원칙:

  • ATLAS_HID_INFO: 마스터 데이터 (정적, 설정)
  • ATLAS_RAIL_TRAFFIC: 트랜잭션 데이터 (동적, 1분마다 갱신)
  • HID_ID는 두 테이블의 조인 키
  • createTime 인덱싱으로 시계열 쿼리 성능 향상

예시 쿼리

간선별 최근 1시간 평균 트래픽 조회:

SELECT
    railEdgeId,
    AVG(velocity) AS avg_velocity,
    MAX(vhlCnt) AS max_vehicles,
    COUNT(*) AS sample_count
FROM ATLAS_RAIL_TRAFFIC
WHERE createTime >= now() - 3600000  // 1시간
GROUP BY railEdgeId
ORDER BY railEdgeId;

정체 감지 쿼리:

SELECT
    railEdgeId,
    velocity,
    maxVelocity,
    CASE
        WHEN velocity / maxVelocity < 0.5 THEN 'CONGESTION'
        WHEN velocity / maxVelocity < 0.8 THEN 'SLOW'
        ELSE 'NORMAL'
    END AS status
FROM ATLAS_RAIL_TRAFFIC
WHERE createTime = (
    SELECT MAX(createTime) FROM ATLAS_RAIL_TRAFFIC
)
ORDER BY railEdgeId;
