## 2. 데이터별 역할과 연관관계

### 2.1 데이터 7종 정리

| # | 데이터 | 출처 | 건수 | 핵심 정보 | 갱신 주기 |
|---|--------|------|------|----------|----------|
| 1 | M14_OHT (raw) | OHT_UDP | 534K~1.6M/일 | 개별 VHL 위치, 상태, 적재 | 0.5초 |
| 2 | oht_data_m14a | OHT_UDP (파싱) | 1.3M/일 | 위 데이터 컬럼 분리 + EDGE | 0.5초 |
| 3 | 스타 컬럼 (STAR) | 스타 | 1,350/일 | 큐, 반송시간, 가동 OHT수 | 1분 |
| 4 | ts_resource | 스타 | 3.3M/일 | **TRANSPORTCOMMANDID**, 작업 단계 | 이벤트 |
| 5 | oht_time_avg | 스타 | 8K/일 | TAT 분 단위 평균 | 1분 |
| 6 | HID_INOUT | 로그프레소 | 342K~871K/일 | HID 구간 속도, 통과량 | 이벤트 |
| 7 | RAIL_CUT | 로그프레소 | 16~19/일 | 레일 차단 구간, 영향 범위 | 이벤트 |

### 2.2 데이터 간 연관관계

```
  M14_OHT ←──── 개별 VHL 상태 ────→ ts_resource
  (VHL 위치/상태)     VehicleId       (작업 명령/단계)
       │                                    │
       │ 집계                          집계  │
       ▼                                    ▼
   스타 컬럼 ←─── 전체 집계값 ────→ oht_time_avg
  (큐, 가동률)      시간 매칭       (TAT 평균)
       │
       │ 큐↔속도 상관
       ▼
   HID_INOUT ←── 공간 관계 ────→ RAIL_CUT
  (구간 속도)     영향 구간        (차단 이벤트)
```

| 관계 | 연결 키 | 상관성 |
|------|---------|--------|
| M14_OHT ↔ ts_resource | VehicleId + 시간 | **개별 차량의 작업 추적** |
| M14_OHT ↔ 스타 | 시간(분) | 개별 상태 ↔ 전체 집계 |
| 스타 ↔ oht_time_avg | 시간(분) | 큐 ↔ TAT |
| 스타 ↔ HID_INOUT | 시간(분) | 큐 ↔ 구간 속도 |
| HID_INOUT ↔ RAIL_CUT | 주소(ADDR) | 차단 구간 ↔ 속도 영향 |
| M14_OHT ↔ HID_INOUT | VHL_ID | 개별 차량 경로 ↔ 구간 통과 |

## 3. 검증된 상관관계 (데이터 근거)

### 3.1 반송큐 → 반송시간 (약한 양의 상관)

| 큐 구간 | 반송시간 | 비고 |
|--------|---------|------|
| 1,000~1,200 | 2.49분 | 기준선 |
| 1,200~1,400 | 2.53분 | +0.04분 |
| 1,600~1,800 | 2.62분 | +0.13분 |

> 큐가 올라가면 반송시간도 약간 증가하지만, **큰 차이는 아님** (2.4~2.6분 범위)

### 3.2 반송큐 → OBS 정지 (거의 무관)

| 큐 구간 | OBS 정지 |
|--------|---------|
| 큐 < 1,300 | 154대 |
| 큐 > 1,600 | 157대 |

> OBS 정지는 큐와 거의 무관. **물리적 구간 혼잡(HID)이 원인**, 큐 크기가 아님

### 3.3 반송큐 → HID 속도 (무관)

| 큐 구간 | HID 평균속도 |
|--------|-----------|
| 1,000~1,200 | 92.0 |
| 1,200~1,400 | 91.9 |

> 큐가 올라가도 HID 구간 속도는 변하지 않음. **HID 속도는 물리적 구조에 의해 결정**

### 3.4 TAT는 24시간 균일

| 시간 | 평균 TAT |
|------|---------|
| 08:00 | 2.86분 |
| 09:00 | 2.87분 |
| 10:00 | 2.87분 |
| 11:00 | 2.71분 |

> 시간대와 무관하게 TAT 약 2.8분으로 안정적

### 3.5 작업량은 24시간 균일

| 구분 | 시간당 배차 |
|------|-----------|
| 주간 (08~16시) | ~20,000건 |
| 야간 (17~07시) | ~19,700건 |

> 주간/야간 차이 거의 없음. FAB 24시간 풀가동

## 4. 월드모델 구축 관점

### 4.1 각 데이터가 월드모델에서 담당하는 역할

```
  ┌──────────────────────────────────────────────────────────┐
  │                      월드 모델                             │
  │                                                          │
  │  ┌─────────────┐  개별 VHL 상태                           │
  │  │  M14_OHT    │  위치, 속도, 적재, 이동 방향              │
  │  │  oht_data   │  → "지금 각 차량이 어디서 뭘 하고 있나"    │
  │  └─────────────┘                                         │
  │         │                                                │
  │  ┌─────────────┐  작업 흐름                               │
  │  │ ts_resource │  배차→출발→도착→적재→하차                  │
  │  │  CommandId  │  → "어떤 작업이 진행 중인가"               │
  │  │  TAT=2.88분 │  → "작업 하나에 ~3분 소요"                │
  │  └─────────────┘                                         │
  │         │                                                │
  │  ┌─────────────┐  전체 부하                               │
  │  │ 스타 컬럼    │  큐, 가동률, 반송시간                     │
  │  │             │  → "시스템 전체가 얼마나 바쁜가"           │
  │  └─────────────┘                                         │
  │         │                                                │
  │  ┌─────────────┐  공간(구간) 상태                          │
  │  │ HID_INOUT   │  구간 속도, 통과량, 수용 한계              │
  │  │             │  → "어느 구간이 빠르고 느린가"             │
  │  └─────────────┘                                         │
  │         │                                                │
  │  ┌─────────────┐  이상 이벤트                              │
  │  │ RAIL_CUT    │  레일 차단, 영향 구간                     │
  │  │ (HIDOFF)    │  → "어느 길이 막혔나"                     │
  │  └─────────────┘                                         │
  └──────────────────────────────────────────────────────────┘
```

### 4.2 월드모델에 아직 없는 것

| 부족한 것 | 역할 | 대안 |
|-----------|------|------|
| **layout.xml** | 노드/엣지 공간 토폴로지 | EDGE 컬럼(oht_data)으로 부분 복원 가능 |
| **실시간 LineCost** | 경로 비용 | HID 속도 + 큐로 간접 추정 |
| **5일치 이상 데이터** | 패턴 반복 검증 | 현재 2일치, 3일 더 필요 |

## 5. 예측 관점

### 5.1 예측 가능/불가 최종 정리

| 예측 대상 | 가능 여부 | 근거 | 필요 데이터 |
|-----------|----------|------|-----------|
| 전체 물동량 (시간당) | **가능** | 24시간 균일 (~20,000건/시) | 스타 + ts_resource |
| TAT 범위 | **가능** | 2.88분 ± 1.8분으로 안정 | ts_resource |
| 큐 수준 예측 | **조건부** | 2일치로 부족, 5일 필요 | 스타 5일치 |
| 병목 구간 예측 | **가능** | HID 저속 구간 일정 | HID_INOUT |
| 개별 VHL 위치 (10분 후) | **불가** | TAT 2.88분 → 10분 내 3~4회 작업 전환 | - |
| 개별 VHL 경로 | **불가** | 경로 실시간 재계산 (카오스) | - |

### 5.2 TAT 2.88분이 예측에 미치는 영향

```
  1차 판단 (TAT 7.8분):
    "10분 후 대부분 현재 작업 수행 중" → 예측 가능성 있음

  2차 판단 (TAT 2.88분):
    "10분 후 대부분 현재 작업 완료, 3~4번째 작업 수행 중"
    → 개별 예측 더 어려움
    → 그러나 전체 물동량은 균일하므로 매크로 예측은 유효
```

### 5.3 예측에 가장 유용한 데이터 조합

| 순위 | 데이터 조합 | 예측 가능 항목 |
|------|-----------|--------------|
| 1 | **스타 컬럼 (5일치)** | 시간대별 큐 패턴, 정상 범위 |
| 2 | **ts_resource + 스타** | 작업 발생률 → 큐 증감 예측 |
| 3 | **HID_INOUT** | 구간별 혼잡도 패턴 |
| 4 | **M14_OHT + ts_resource** | 차량별 작업 효율 |
