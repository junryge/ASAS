## 1. 고객 피드백 반영 (1차 분석 수정)

| # | 피드백 | 1차 분석 (잘못) | 수정 |
|---|--------|---------------|------|
| 1 | R-Vehicle은 예비차량이 아님 | "R=예비차량" | **R=Reticle 반송 VHL** (반송물 종류만 다름) |
| 2 | 가동률 = 가동OHT수/전체OHT수 | 차량수 분포로 표현 | 전체 대비 비율로 수정 |
| 3 | Priority ≠ 속도 | Priority를 속도로 해석 | **MCP 일괄 50 부여**, 속도와 분리 |
| 4 | 평균 TAT = 3.x분 | 7.8분으로 계산 | **실제 TAT = 2.88분** (ts_resource 기준) |
| 5 | Dijkstra 알고리즘 상이 | 코드 기반 설명 | 현재 운영 알고리즘과 다를 수 있음 명시 |

## 6. 예측 가능성 재평가

### 6.1 1차 판단 vs 2차 판단

| 항목 | 1차 판단 | 2차 판단 (수정) |
|------|---------|---------------|
| TAT | 7.8분 (오류) | **2.88분** (ts_resource 기준) |
| 10분 후 차량 상태 | 대부분 현재 작업 수행 중 | **대부분 현재 작업 완료, 새 작업 수행 중** |
| 10~11시 큐 급증 | 반복 패턴 추정 | **04-14만의 일시적 현상** |
| 주간/야간 차이 | 알 수 없었음 | **차이 없음 (24시간 동일)** |
| 작업 발생 패턴 | CommandId 없어서 불명 | **시간당 ~20,000건 배차, 24시간 균일** |

### 6.2 10분/20분 예측 재평가

TAT 2.88분이면:
- 10분 안에 차량이 **3~4개 작업**을 완료
- 개별 차량 위치 예측은 여전히 불가 (작업이 너무 빠르게 바뀜)
- 그러나 **전체 물동량은 24시간 균일**하므로, 매크로 예측은 1차보다 더 유리

### 6.3 CommandId가 열어준 가능성

ts_resource에 TRANSPORTCOMMANDID가 99.6% 포함되어 있어:

| 가능해진 것 | 내용 |
|------------|------|
| 실제 TAT 계산 | 작업 시작~완료까지 정확한 시간 |
| 작업 발생 패턴 | 시간당 ~20,000건 배차 (균일) |
| 차량별 작업 이력 | 어떤 차량이 어떤 작업을 수행했는지 추적 |
| 작업 유형별 분석 | ASSIGNED→DEPARTED→ARRIVED→ACQUIRE→DEPOSIT 단계별 |
