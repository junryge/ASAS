================  회사(API/폐쇄망) 가서 확인할 것  ================
집(GGUF 32K) ↔ 회사(API 128K, CPU, 폐쇄망) 환경이 달라서 아래 확인 필요.

[1] 코드 적용 (★ 집에서 겪은 함정 회사서도 주의)
  - git pull  또는  데모스_전체코드.zip 으로 demos_v1 + rag_server 폴더 통째 교체
  - ★ 파일명 정확히(routes_chat.py 등), '복사본/새파일' 아님, 실행 폴더에 넣기
  - 데모스 재시작 → 콘솔에 "[routes_chat] ✅ 새 버전 로드됨" 떠야 적용된 것

[2] 기존 것 회귀 확인 (코드 바뀌었으니 한 번씩)
  - hubroom 예측 스크립트: 예전처럼 잘 도는지 (영향 없게 만들었지만 실제 확인)
  - 기존 지식문서/에이전트: 그대로 뜨는지

[3] M16 등록 & 실제 로그 테스트
  - 스크립트 m16-lifter-count 등록 (파일2 + 진입 + 실행인자 3줄)
  - 카파시톤.md 문서 등록 (산문형/표양식 중 택1)
  - ★ 실제 LOGPRESSO 로그로 테스트:
      · 헤더 줄(_time,FROM_HIDID,TO_HIDID,VHL_ID...) 포함해서 첨부/붙여넣기
      · 분단위 근처차량수 + 카파시톤 해석 나오는지
  - user_id 가 회사도 'ggg3g' 인지 (다르면 skills 폴더 경로 맞추기)

[4] 실제 로그 컬럼명 확인 (중요)
  - 회사 진짜 로그의 컬럼명이 _time / FROM_HIDID / TO_HIDID / VHL_ID 와
    정확히 같은지. 다르면 count_lifter_inout.py 의 컬럼 참조만 바꾸면 됨.

[5] API 128K 장점 (집과 다른 점)
  - 회사는 API 128K 라 컨텍스트보호 거의 안 걸림.
  - 집(32K)과 달리 스킬 켜도 잘 안 잘림 → 원하면 M16 + 스킬 같이 가능.
  - 그래도 권장: M16 전용 에이전트는 스킬 최소.

[6] RAG / bge-m3 (회사는 원래 잘 됨)
  - 새 embedder.py 는 구버전에서도 안 깨지게(폴백) 만듦 → 회사도 안전.
  - rag_server 재시작 → "모드=hybrid(bge-m3)" 뜨는지. (안 떠도 lexical 로 OK)
  - 폐쇄망이라 pip -U 안 되면 → 기존 그대로 두면 됨 (회사 잘 되니까).

[7] 환경 차이 요약
  | 항목      | 집            | 회사            |
  | 모델      | GGUF(32K), GPU| API(128K), CPU  |
  | 컨텍스트  | 작음→스킬0 권장| 큼→여유          |
  | 네트워크  | 인터넷 됨      | 폐쇄망          |
  | bge-m3    | 새 휠로 해결   | 원래 잘 됨       |

→ 핵심: 코드 폴더 통째 교체 + 배너 확인 → M16 등록 → 실제 로그(헤더 포함)로 테스트.
