## 답변할 때는 한글 이름을 쓴다

| 코드 | 현장 이름 | 뜻 |
|---|---|---|
| R-A′ | 반송지연 / 반송지연 지속 | 반송시간이 기준보다 길어짐 |
| R-B | Queue 누적 / Queue 상승 | 대기 물량이 쌓임 |
| R-C′ | 리프터 정체 | Storage 가 꽉 차 리프터가 Carrier 를 못 내려놓고 막혀 쌓임 |
| R-D | Storage FULL | STB / FAB Storage 가 FULL |
| SLA | 4분초과 (반송지연율) | 4분 넘는 반송 비율이 오름 |
| 소터 | 분류기 대기 / 반송 실패 | 분류기에서 대기가 쌓이거나 반송이 실패함 |
| MAXCAPA | 운영자 용량변경 | 운영자가 설비 한계치를 줄임 |

> '역증가'·'역류' 라는 말은 쓰지 않는다. **리프터 정체**, **Queue 밀림** 으로 말한다.

## 무엇을 잡나 · 왜 그렇게 봤나

### R-A′ — 반송지연 / 반송지연 지속

- **무엇을 잡나**: 물량이 안 빠지고 있다는 가장 이른 신호입니다. 아직 쌓이기 전에도 시간부터 늘어납니다.
- **왜 그렇게 봤나**: 짧게 튄 것과 진짜를 갈라야 해서 지속을 따로 둡니다 — 한 번 튄 값으로 알람을 울리면 사람이 알람을 꺼 버립니다. 그래서 10분 중 1회(민감) 와 5분 중 여러 회(확실) 를 나눠 둡니다.

### R-B — Queue 누적 / Queue 상승

- **무엇을 잡나**: 허브로 들어오는 쪽을 봅니다. 나가는 속도보다 들어오는 속도가 빠르면 결국 막힙니다.
- **왜 그렇게 봤나**: 절대량이 아니라 증가량을 봅니다. 영역마다 평소 물량이 달라서 '몇 개 이상' 으로는 같은 자로 못 잽니다. 30분(추세)과 10분(급증)을 둘 다 보는 것은, 천천히 차오르는 것과 갑자기 몰리는 것이 다른 일이기 때문입니다.

### R-C′ — 리프터 정체

- **무엇을 잡나**: 리프터에 물건이 걸려 있는 상태입니다. 내려놓을 자리가 없으면 리프터가 들고 서 있게 됩니다.
- **왜 그렇게 봤나**: 합은 줄었는데 개별로 늘어난 경우를 잡습니다. 전체가 늘면 그냥 물량이 많은 것이지만, 전체는 빠지는데 특정 호기만 늘면 그 호기가 막힌 것입니다. 합만 보면 이걸 놓칩니다.

### R-D — Storage FULL

- **무엇을 잡나**: 받을 자리가 없다는 뜻입니다. 자리가 없으면 그 앞이 전부 밀립니다.
- **왜 그렇게 봤나**: M16HUB 는 FAB 저장율과 STB 저장율을, 다른 영역은 OHT 가동률을 봅니다 — 영역마다 '포화' 가 드러나는 자리가 다릅니다.

### SLA — 4분초과 (반송지연율)

- **무엇을 잡나**: 고객이 체감하는 지표입니다. 앞의 룰들이 '왜' 라면 이건 '얼마나 아픈가' 입니다.
- **왜 그렇게 봤나**: 비율과 건수를 둘 다 봅니다. 물량이 적을 때는 비율이 쉽게 튀고, 물량이 많을 때는 비율이 안 움직여도 건수가 확 늡니다.

### 소터 — 분류기 대기 / 반송 실패

- **무엇을 잡나**: 분류기에서 막히면 그 뒤가 전부 밀립니다.
- **왜 그렇게 봤나**: 반송 실패는 1건만 있어도 켭니다 — 실패는 '조금 느림' 이 아니라 안 된 것입니다.

### MAXCAPA — 운영자 용량변경

- **무엇을 잡나**: 사람이 손을 댄 흔적입니다. 신호이자 원인입니다 — 뭔가 이상해서 줄였거나, 줄여서 막히기 시작했거나.
- **왜 그렇게 봤나**: 다른 룰과 달리 바뀐 컬럼 수만큼 곱합니다. 여러 곳을 동시에 줄였다면 그만큼 크게 손댄 것이라고 봅니다.

## 읽는 순서

**시간이 는다(R-A′) → 물량이 쌓인다(R-B) → 자리가 없다(R-C′·R-D) → 고객이 아프다(SLA).**

단계 판정 S3 가 이 셋을 모두 요구하는 것도 같은 까닭이다. 시간도 늘고, 자리도 없고, 물량도 몰릴 때가 진짜 막히는 때다.
