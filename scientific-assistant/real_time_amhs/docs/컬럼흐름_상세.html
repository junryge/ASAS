3. FAB 점수 area_score 가 만들어지는 과정

영역 하나에 대해 eval_area_rules(area, window) 가 룰 8종을 각각 판정하고, 켜진 룰의 배점을 더합니다. 아래 그림이 어느 컬럼이 어느 룰로 들어가는지 그대로 보여 줍니다 — 룰을 다 가진 M16HUB 를 예로 들었습니다.

3-0. 왜 이런 룰인가 — 무엇을 잡으려는 것인가

룰 이름과 뜻은 고객 답변용 스킬 문서에서 그대로 가져왔습니다 (m16_hub_skills/). 같은 것을 두 이름으로 부르면 현장에서 못 알아듣습니다.

룰현장 이름무엇을 잡나왜 이렇게 봤나
R-A′반송지연 / 반송지연 지속
반송시간이 기준보다 길어짐		물량이 안 빠지고 있다는 가장 이른 신호입니다. 아직 쌓이기 전에도 시간부터 늘어납니다.짧게 튄 것과 진짜를 갈라야 해서 지속을 따로 둡니다 — 한 번 튄 값으로 알람을 울리면 사람이 알람을 꺼 버립니다. 그래서 10분 중 1회(민감) 와 5분 중 여러 회(확실) 를 나눠 둡니다.
R-BQueue 누적 / Queue 상승
대기 물량이 쌓임		허브로 들어오는 쪽을 봅니다. 나가는 속도보다 들어오는 속도가 빠르면 결국 막힙니다.절대량이 아니라 증가량을 봅니다. 영역마다 평소 물량이 달라서 '몇 개 이상' 으로는 같은 자로 못 잽니다. 30분(추세)과 10분(급증)을 둘 다 보는 것은, 천천히 차오르는 것과 갑자기 몰리는 것이 다른 일이기 때문입니다.
R-C′리프터 정체
Storage 가 꽉 차 리프터가 Carrier 를 못 내려놓고 막혀 쌓임		리프터에 물건이 걸려 있는 상태입니다. 내려놓을 자리가 없으면 리프터가 들고 서 있게 됩니다.합은 줄었는데 개별로 늘어난 경우를 잡습니다. 전체가 늘면 그냥 물량이 많은 것이지만, 전체는 빠지는데 특정 호기만 늘면 그 호기가 막힌 것입니다. 합만 보면 이걸 놓칩니다.
R-DStorage FULL
STB / FAB Storage 가 FULL		받을 자리가 없다는 뜻입니다. 자리가 없으면 그 앞이 전부 밀립니다.M16HUB 는 FAB 저장율과 STB 저장율을, 다른 영역은 OHT 가동률을 봅니다 — 영역마다 '포화' 가 드러나는 자리가 다릅니다.
SLA4분초과 (반송지연율)
4분 넘는 반송 비율이 오름		고객이 체감하는 지표입니다. 앞의 룰들이 '왜' 라면 이건 '얼마나 아픈가' 입니다.비율과 건수를 둘 다 봅니다. 물량이 적을 때는 비율이 쉽게 튀고, 물량이 많을 때는 비율이 안 움직여도 건수가 확 늡니다.
소터분류기 대기 / 반송 실패
분류기에서 대기가 쌓이거나 반송이 실패함		분류기에서 막히면 그 뒤가 전부 밀립니다.반송 실패는 1건만 있어도 켭니다 — 실패는 '조금 느림' 이 아니라 안 된 것입니다.
MAXCAPA운영자 용량변경

3-2. 영역별 그림 — 어느 컬럼이 어느 룰로 들어가나

area_score = RA + RA_sus + RB + RB_fast + RC + RD + SLA + SORT + MAXCAPA×n area_score = min(50, 위 합) ← 50 점에서 자른다 · 자르기 전 원본은 area_score_raw 로 같이 남긴다 · 룰별 분해 점수는 pts_RA · pts_RB … 로 각각 남긴다 (조합 분석용)
왜 50점에서 자르나. MAXCAPA 는 바뀐 컬럼 수만큼 곱해지므로 한 영역이 무한정 커질 수 있습니다. 한 영역이 전체를 삼키지 않게 상한을 둡니다.

3-3. 판정에 창(window)이 왜 필요한가

룰보는 구간판정

R-A′ 지속최근 5분임계×0.67 이상인 분이 3회 이상

4. ALL 점수 unified_risk_score 가 만들어지는 과정

evaluate_unified() 가 영역 점수 합에 전체 관점의 가산을 더합니다. ALL 은 영역이 아니라 전체를 본 값이라, FAB 점수와 자·단위가 다릅니다.

layer1_total = Σ area_score (8영역 전부 더한다) flow_score = 흐름 노드마다 심각 +30 / 위험 +15 / 주의 +5 sla_score = SLA 켜진 영역 수 × 5 sorter_score = 소터 켜진 영역 수 × 3 mc_score = Σ (영역별 MAXCAPA 바뀐 컬럼 수 × 10) unified_risk_score = min(500, layer1_total + flow + sla + sorter + mc)
SLA·소터·MAXCAPA 는 두 번 셉니다. area_score 안에서 한 번(그 영역의 문제로), 융합에서 또 한 번(전체로 번질 신호로). 일부러 그렇게 둔 것이므로, ALL 점수를 FAB 점수 합으로 되계산하면 맞지 않습니다.

6. 영역분리 — FAB 파일에서 area_score 가 되는 과정

영역분리는 통합 파일을 FAB 별 파일로 나눕니다. 그 파일에서 그 FAB 의 점수가 area_score 라는 이름으로 들어갑니다 (통합 파일의 {FAB}_score 와 같은 값입니다).

통합 파일 {날짜}_발동이벤트.csv unified_risk_score = 전체 점수 M14_score = M14 영역 점수 │ │ 영역분리 ↓ FAB 파일 {날짜}_발동이벤트_M14.csv unified_risk_score = 전체 점수 (그대로 실려 온다) area_score = M14 영역 점수 ← 이 FAB 의 값 area_level = M14 영역 등급

6-1. 관제가 받는 순간 자리를 바꾼다

FAB 파일에는 전체 점수와 그 FAB 점수가 같이 들어 있습니다. 관제가 그대로 읽으면 M14 화면이 전체 점수로 등급을 매기고 케이스 영역이 M16HUB 로 찍힙니다. 그래서 jupyter_csv._fab_rows() 가 받는 순간 한 번만 자리를 바꿉니다.

받은 그대로 → 정규화 후 unified_risk_score = 전체 all_score = 전체 (원본 보존) area_score = M14 unified_risk_score = M14 ← 자리 이동 unified_risk_level = 전체등급 all_level = 전체등급 area_level = M14등급 unified_risk_level = M14등급 hot_area = 전체기준 all_hot_area = 전체기준 hot_area = M14
왜 한 자리에서만 바꾸나. 그래프·예보·기여도·리포트·정확도가 모두 unified_risk_score 와 hot_area 를 읽습니다. 받는 자리에서 한 번 바꿔 두면 하위 모듈을 하나도 안 고치고 FAB 화면이 자기 데이터를 봅니다. 원본은 all_* 로 남겨 전체와 비교할 수 있게 둡니다.

6-2. 그래서 화면의 두 값은 이렇게 정리됩니다

화면보는 값자뜻
ALLunified_risk_score0~5008영역 합 + 전체 관점 가산
FABarea_score
(정규화 뒤 unified_risk_score 자리)		0~50그 영역의 룰 배점 합
두 값을 같은 자로 비교하지 마십시오. ALL 은 0~500, FAB 은 0~50 입니다. 관제 화면은 이 둘을 각각 0~100 으로 눈금을 맞춰 등급을 매깁니다 — 자세한 것은 docs/FAB별_위험도_스코어.html 를 보십시오.
