5. 성능 평가

무엇을 채점한 값인가. 이 표는 룰 자체의 성능이 아니라, 그 분의 상태를 두고 LLM 이 내린 판단(“지금 대응이 필요한 진짜 이상인가 — 예/아니오”)이 이후 데이터와 맞았는지를 잰 값입니다. 룰의 성능은 예측 잡 쪽에서 냅니다. 두 값을 같은 표에 섞지 마십시오.

5-1. 판정 정의

판정뜻계산에서
적중이상이라 했고 실제로 이상이었다TP
과다탐지이상이라 했는데 아니었다FP
누락아니라 했는데 이상이었다FN
조치효과맞게 잡았는데 운영자 조치로 회복됐다분모에서 제외
정탐 / 오탐사람이 화면에서 직접 누른 판정자동 채점과 따로 셉니다

조치효과를 오탐으로 세면 조치를 잘할수록 성능이 나빠 보입니다. 그래서 분모에서 뺍니다 (accuracy.py 와 같은 규칙).

5-2. 계산식

Precision = 적중 / (적중 + 과다탐지) Recall = 적중 / (적중 + 누락) F1 = 2 · Precision · Recall / (Precision + Recall) · 분모가 0 이면 '—' 로 둡니다. 0.000 으로 적지 않습니다 (표본이 없는 것과 성능이 0 인 것은 다릅니다)

‘채점 대기’ 는 LLM 이 판단은 했으나 검증 창이 아직 차지 않아 판정이 비어 있는 행입니다. 오늘 날짜를 넣으면 이 값이 커지고 성능이 실제보다 나쁘게 보이므로, 이 문서는 어제까지만 봅니다.

6. 이 문서가 말하지 않는 것

  • 룰 자체의 성능이 아닙니다. LLM 판단의 성능입니다 (5장 머리말).
  • 룰 제작 데이터 기간은 이 시스템이 모릅니다. 예측 잡에서 받아야 합니다 (3-1).
  • 판정에 룰 버전 도장이 없습니다. 지금은 날짜로만 구분할 수 있습니다 — 룰 변경일을 받아 기간을 자르십시오.
  • 표본 수를 반드시 함께 보십시오. 표본이 적으면 소수 몇 건에 값이 크게 흔들립니다.
  • 재현 검산은 하루 전체가 아니라 고르게 뽑은 표본 지점입니다 (4장에 지점 수를 적었습니다).
