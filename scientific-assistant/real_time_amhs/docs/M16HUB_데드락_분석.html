0. 한 줄로

PIO 를 FAB 점수에 넣으면 세 사건 중 2건이 장애보다 먼저 뜬다 — 선행 9/12 오후 데드락 123분 · 9/14 오후 데드락 91분. PIO 는 이미 세고 있고 점수까지 매겨 두었는데 그 점수가 FAB 점수에 더해지지 않을 뿐이다.
특히 9/14 오후 데드락 — 지금은 15:50 에 처음 뜨는데 PIO 를 넣으면 15:21 로 29분 앞당겨진다.
다만 경보가 이어지지 않는다. PIO 는 10분 창이 지나가면 가산이 사라져서, 첫 경보부터 장애까지가 10 · 1 · 13 조각으로 쪼개지고 최장 59분씩 끊긴다. 한 번 끊기면 운전원에게는 '지나갔다' 로 읽힌다 — PIO 가 첫 경보를 앞당기고, 이어짐(continuity)이 그 사이를 메워야 비로소 '계속 떠 있었다' 가 된다.

4. 왜 점수가 안 올랐나 — 세 가지

㉠ PIO 는 이미 세고 점수까지 냈는데, FAB 점수에 안 더해진다가장 큰 것

룰 원본을 보면 PIO 는 ALL(전체 시스템) 룰 표에만 있고 M16HUB 룰 표에는 없다 (fab_score.ALL_RULES 에 있고 WATCH[M16HUB] 에 없다).

날짜PIO 10분 합 최대예측기가 매긴 PIO 점수그 점수가 M16HUB_score_raw 에 들어갔나
09-12134개+2 / +4 / +7 / +9 / +11아니다 — 1440분 전부 룰 배점 합과 정확히 같다
09-1494개+2 / +4 / +7 / +9 / +11아니다 — 1440분 전부 룰 배점 합과 정확히 같다
값은 다 있다. 더하기만 안 한다. pio_10min_cnt(건수)도 pio_score(가산점)도 분마다 적혀 있는데, M16HUB_score_raw 는 룰 배점 합과 한 분도 안 어긋난다 — PIO 가 한 번도 안 더해졌다는 뜻이다. 새로 만들 것이 아니라 이미 있는 수를 FAB 쪽으로 연결하는 일이다.

㉡ 그날 켜진 룰만으로는 천장이 낮다

M16HUB 에 걸린 룰은 9개, 배점을 다 더하면 83(화면 100점)다. 그런데 SLA·분류기·용량변경은 두 날 모두 한 번도 안 켜졌다 — 남는 여섯 룰의 합은 45(화면 64점)가 끝이다.

초위험 은 그 두 날 구조적으로 못 나온다. 초위험 컷 72에 닿으려면 룰 합이 51 이상이어야 하는데, 실제로 켜진 여섯 룰의 합은 45가 최대다. 나머지 38점은 용량변경·SLA·분류기 쪽에 묶여 있고, 데드락에는 그것들이 안 걸린다.

데드락은 이 룰 표가 보는 고장이 아니다 — 그래서 PIO 가 필요한 것이다.

㉢ 사건 추적이 어떤 날은 돌고 어떤 날은 안 돈다

continuity_min 이 101 까지 올라가는데 점수는 그대로다. 1분째나 101분째나 같은 점수다 — 얼마나 오래가 점수에 전혀 안 들어간다. 그리고 refire_count 는 두 날 모두 계속 0 이라 '또 터졌다' 를 셀 수가 없다. 게다가 한쪽 날은 추적이 아예 안 열렸다 — 같은 장치가 날마다 다르게 동작한다.

여기가 PIO 만으로 안 되는 자리다. 10분 창이 지나가면 가산이 사라져 경보가 조각난다. 한 번 끊기면 운전원에게는 '지나갔다' 로 읽힌다. continuity_min 이 이미 101분까지 세고 있으니(4장 ㉢) 그 값을 점수에 얹으면 조각이 이어진다.

5-3. 두 가지 더하는 방식을 나란히

지어낸 배점이 아니라 예측기가 이미 쓰고 있는 구간표를 그대로 쓴다(pio_10min_cnt→pio_score 를 자료에서 읽었다): 16개↑ +2 · 26개↑ +4 · 41개↑ +7 · 63개↑ +9 · 81개↑ +11.

PIO 만 더해도 초위험 에 닿는다 — 9/12 오후 데드락 80점. 지금 룰만으로는 천장이 화면 64점이라 절대 못 가던 자리다 (초위험 컷을 72 로 놓았을 때 — 7장 참고).

다만 PIO 가 0 인 분이 127분 / 167분이다 — 10분 창이 지나가면 가산이 사라져서, 사건이 이어지는 동안에도 점수가 떨어졌다 올랐다 한다. 한 분이라도 끊기면 운전원에게는 '지나갔다' 로 읽힌다. 이것이 다음 항(이어짐·재발)이 필요한 이유다.

6. 제안 — 무엇을 어떻게 바꿔야 하나

아래는 이 문서가 자료로 확인한 것만 적는다. 배점 값은 정하는 자리가 따로 있으니 여기서는 무엇을 연결해야 하는지까지만 적는다.

#고칠 것근거효과
1PIO 를 FAB 룰 표에 넣는다값(pio_10min_cnt)도 점수(pio_score)도 이미 있는데 M16HUB_score_raw 에 안 더해진다세 사건 합 21분의 등급이 오른다
2continuity_min 을 점수에 넣는다1분째와 101분째가 같은 점수다 — 얼마나 오래가 점수에 안 들어간다끊겼다 붙었다 하는 것이 이어진다
3refire_count 를 실제로 센다두 날 모두 계속 0 — '또 터졌다' 를 셀 수가 없다재발을 점수로 올릴 수 있다
4사건 추적이 날마다 다르게 도는 것을 먼저 본다한 날은 68·101분씩 열렸는데 다른 날은 하루 종일 IDLE 이다위 둘의 전제가 된다
5데드락용 룰이 따로 필요한지 본다지금 룰만으로는 천장이 화면 64점이다 — 남은 배점이 용량변경·SLA·분류기에 묶여 있는데 데드락엔 그게 안 걸린다PIO 없이도 천장이 올라간다

7. 이 문서가 말하지 않는 것

  • 등급 컷 — M16HUB 컷을 43 / 57 / 72 로 놓고 적었다. 자료(2875분)만으로는 경계 40~43 · 위험 54~57 까지만 좁혀지고, 초위험 은 두 날 한 번도 안 떠서 못 정한다. 운영 중인 값을 주시면 --cut 으로 다시 뽑는다.
  • 배점 값 — PIO 를 몇 점으로 할지, continuity 를 어떻게 얹을지는 이 문서가 정하지 않는다. 지금 예측기가 쓰는 구간표를 그대로 적용해 본 것뿐이다.
  • 데드락 자체의 원인 — 이 문서는 왜 점수가 안 올랐나만 본다. 무엇이 데드락을 만들었는지는 설비 쪽 자료가 따로 있어야 한다.
