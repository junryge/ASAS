## 두 가지를 따로 본다

AMOS 의 이상 감지는 **반송 이상**과는 별개의 두 축이다.
반송이 멀쩡해도 여기가 깨지면 화면의 숫자 자체를 믿을 수 없게 된다.

| 기능 | 무엇을 보나 | 무엇을 잡나 |
|---|---|---|
| MES-MCS-MCP 통신 이상 감지 | 시스템 간 통신 상태 | **응답 지연**, **통신 단절** 등 비정상 상태 |
| 서버 리소스 이상 감지 | 서버의 CPU · Memory · Disk | 설정된 **임계치 초과** |

## MES-MCS-MCP 통신 이상 감지

**MES · MCS · MCP** 세 시스템 사이의 통신 상태를 **지속적으로** 확인한다.
응답 지연이나 통신 단절 같은 비정상 상태를 감지해서,
운영자가 신속하게 확인할 수 있게 한다.

세 시스템이 무엇인지는 USER GUIDE 에 풀어 적혀 있지 않다.
약어의 뜻을 물으면 **문서에 없다고 말한다**.

## 서버 리소스 이상 감지

AMOS 운영에 쓰이는 **서버**의 CPU · Memory · Disk 등 주요 리소스 상태를
모니터링한다. **설정된 임계치를 초과하면** 이상 상태로 감지한다.

임계치의 구체적인 값은 문서에 없다 — [[AMOS Alarm 과 연락처]] 의
**Alarm 설정**에서 운영 환경에 맞춰 정하는 값이다.

## 왜 이 둘을 먼저 보나

- 통신이 끊기면 **화면의 값이 갱신되지 않는다.** 반송이 멈춘 것이 아니라
  값이 안 오는 것일 수 있다 — 둘은 완전히 다른 사고다.
- 서버 리소스가 임계를 넘으면 **수집·표시가 늦어진다.** 지표가 튀는 것처럼
  보여도 원인이 설비가 아닐 수 있다.

이상이 이상하게 보일 때, 반송을 파기 전에 이 두 화면을 먼저 확인한다.
