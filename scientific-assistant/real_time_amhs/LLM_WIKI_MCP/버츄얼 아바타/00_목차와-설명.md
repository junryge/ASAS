# 버추얼 아바타 지식 — 무엇을 왜 이렇게 넣었나

서윤·서햄터가 아는 지식은 **전부 여기서** 온다. 스킬이나 프롬프트에 박아 두지
않는다 — 두 벌이 되는 순간 위키를 고쳐도 옛 것을 말하고, 어느 쪽이 맞는지
아무도 모르게 된다.

담당(도메인)은 **버추얼 아바타** 하나다.

> 이 글은 **위키에 안 올린다.** 머리말(`--- title: … ---`)이 없어서 페이지가
> 되지 않고, 되어서도 안 된다 — 등록 절차나 트리거 낱말은 서윤이 알 지식이
> 아니라 우리가 볼 안내문이다.
> 등록 절차의 더 자세한 것(ingest 범위·이미지 소스)은 `00_등록방법.md`.

## 등록하는 법

1. 위키 웹앱(`app.py` · 기본 **:8100**)을 연다
2. 담당을 **버추얼 아바타** 로 고른다
3. 소스 업로드에서 **`md는 페이지로`** 체크를 켠 채로 둔다 (기본 켜짐)
4. md 를 한 번에 다 올린다
5. 활동 로그에 **`page-import`** 로 찍히면 성공

### 여기서 한 번 샜다

`소스 N건` 으로 찍힌 적이 있다. 소스로 들어간 것이다.
위키에서 **페이지와 소스는 읽는 도구가 다르다**(`readPage` · `readSource`).
서윤은 페이지만 읽고 있어서 "위키에 그런 내용이 없어요" 라고 답했다 —
멀쩡히 올려 뒀는데.

원인은 둘 중 하나다.
- 3번 체크가 꺼져 있었다
- 머리말(`--- title: … ---`)이 없었다 → 제목을 지어낼 수 없어 소스로 넣는다

### 담당 이름은 안 고쳐도 된다

프론트매터의 `domain:` 은 **코드가 읽지 않는다.** 담당은 업로드 화면에서
고른 것이 정해진다 (`upload()` 이 폼의 `domain_id` 로 넣는다).
화면에 `Virtual_Avatar` 로 보이든 `버추얼 아바타` 로 보이든, 화면에서
그 담당을 고르기만 하면 된다.

### 두 번 올려도 된다

같은 제목이면 **고친다**(upsert). 쌍둥이 페이지가 안 생긴다.

## 글을 쓸 때 지킨 것

- **호기명·컬럼명은 원문 그대로.** `6ABL60~` 를 "6ABL 계열" 로 뭉개면
  검색(BM25)에서 못 찾는다.
- **가이드에 없는 것은 없다고 적는다.** AMOS 세 장에 `가이드에 안 적힌 것`
  절을 따로 뒀다 — 임계값·색 기준·갱신 주기·Alarm 등급·통보 수단은 USER
  GUIDE 에 없다. 짐작해서 답하는 게 제일 나쁘다.
- **AMOS 는 화면 설명이지 지금 수치가 아니다.** 개요에 이 줄을 박았다.
  안 그러면 "AMOS 가 Site 이상을 보여 준다" 가 "지금 이상이 있다" 로
  둔갑한다. 현재 수치는 관제(real_time_amhs) 실시간 데이터로 답한다.
- **[[링크]]는 실제 있는 제목만.** 없는 페이지를 가리키면 죽은 링크가 된다.

## 확인하는 법

```
python wiki_진단.py
```

"등록은 했는데 서윤이 못 찾는다" 를 눈으로 가른다. 갈릴 수 있는 곳이 넷이다.

1. 웹앱(app.py)이 보는 `wiki.db` ← 등록이 들어간 곳
2. MCP 서버가 보는 `wiki.db` ← 서윤이 읽는 곳
3. 그 DB 에 페이지가 정말 있나
4. 그 낱말로 검색하면 나오나

**1과 2가 다르면 등록은 성공하고 서윤은 못 찾는다** — 제일 헷갈리는 모양이다.
`app.py` 는 자기 파일이 있는 폴더의 `data/wiki.db` 를 쓴다. `mcp_server.py`
를 다른 폴더에서 띄웠으면 둘은 다른 파일이다.
