# 등록 방법 — M16 HUBROOM 반송 지식 (담당: 버츄얼 아바타)

## 담당은 `버츄얼 아바타`

네 쪽 모두 프론트매터를 `domain: 버츄얼 아바타` 로 맞춰 뒀다.
화면에서 담당을 고를 때도 **버츄얼 아바타**를 고른다.

> ★**담당은 업로드 화면에서 고른 것이 정해진다.** 프론트매터의 `domain:` 은
> 사람이 보라고 적어 둔 이름표일 뿐, 코드가 읽지 않는다
> (`upload()` 가 폼의 `domain_id` 로 넣고, `upsert_md_page()` 는
> `meta['domain']` 을 보지 않는다).
> 그러니 화면에 `Virtual_Avatar` 로 보이든 `버추얼 아바타` 로 보이든
> **화면에서 그 담당을 고르기만 하면 된다.** 프론트매터는 안 고쳐도 된다.

### 이렇게 둬도 괜찮은 이유 (코드로 확인함)

- **질문·검색은 담당을 안 가린다.** `ask()` 가 담당 필터 없이 전체에서 찾는다.
  어느 담당에 있든 서윤이 찾아 쓴다.
- **나중에 옮길 수 있다.** 페이지 수정에서 담당을 바꾸면 이전 경로의 파일까지
  정리된다.

### 딱 하나 기억할 것

**ingest 의 관련 페이지 탐색은 기본이 담당 안(`scope=domain`)이다.**
나중에 M16HUB 담당에 새 자료를 올려 ingest 하면, 여기 있는 페이지들은
갱신 후보로 안 뜬다.
→ 그때 ingest 화면에서 **범위를 `전체`로** 바꾸면 된다 (고르는 칸이 있다).

## 순서

### 1. 페이지 4개를 먼저 만든다

담당 노트북(**버츄얼 아바타**) → **[양식으로 작성]** → 아래 파일 내용을
붙여 넣는다. 프론트매터(`---` 사이)는 화면의 제목·타입·태그·한줄요약 칸에
나눠 넣고, 그 아래 본문만 본문 칸에 넣는다.

| 파일 | 제목 | 타입 |
|---|---|---|
| `01_M16-HUBROOM-개요.md` | M16 HUBROOM 개요 | concept |
| `02_반송-장치-종류와-역할.md` | 반송 장치 종류와 역할 | concept |
| `03_FAB-간-연결-경로.md` | FAB 간 연결 경로 | concept |
| `04_M16-HUBROOM-유의-지표.md` | M16 HUBROOM 유의 지표 | concept |
| `06_AMOS-개요와-메뉴.md` | AMOS 개요와 메뉴 | concept |
| `07_AMOS-모니터링-화면.md` | AMOS 모니터링 화면 | concept |
| `08_AMOS-이상-감지.md` | AMOS 이상 감지 | concept |
| `09_AMOS-Alarm-과-연락처.md` | AMOS Alarm 과 연락처 | concept |
| `10_AMOS-AI-Agent-Chatbot.md` | AMOS AI Agent Chatbot | concept |

**개요부터** 만든다. 뒤 페이지들이 `[[M16 HUBROOM 개요]]` 로 링크하기 때문이다.

### 2. 이미지를 소스로 올린다

소스 업로드 → 연결도·배치도 이미지(png/jpg/gif/bmp/webp)

**설명란은 비워 두면 안 된다.** 이미지는 텍스트 추출이 안 돼서, 그림만
올리면 LLM 이 아무것도 못 읽는다. `05_이미지-설명란-붙여넣기.txt` 의 글을
그대로 붙여 넣는다.

### 3. Ingest 실행 → 검토 → 적용

소스 상세 → **[Ingest 실행]** →
① 소스 요약 페이지가 생기고 ② 위 4개 페이지의 **갱신안**이 나온다 →
**체크한 것만** 적용한다. LLM 이 자동 반영하지 않는다.

### 4. 린트

**[린트]** 를 돌려 고아 페이지·깨진 링크·빈 요약을 확인한다.

## 설비 entity 는 지금 안 만든다

`4AFC3201`, `4ABLD~` 같은 호기별 `entity` 페이지는 **나중에** 만든다.
「고아 페이지 금지」 규칙이 있어서, 링크될 데 없는 호기 페이지를 미리
만들면 린트가 잡는다. 지금은 [[FAB 간 연결 경로]] 안에 호기명을 적어 두고,
그 호기에 대해 할 말이 쌓이면 그때 분리한다.

## 지킨 것

- **수치·호기명은 원문 그대로** — `6ABL60~` 를 "6ABL 계열" 로 뭉개지 않았다.
  검색이 BM25 라 정확한 토큰을 잡는데, 뭉개면 못 찾는다.
- **1주제 1페이지** — 개요 / 장치 / 연결 / 지표로 나눴다.
- **상호참조** — 네 페이지가 `[[…]]` 로 서로 링크된다. 고아가 없다.
- **한줄요약** — 전부 채웠다. 검색과 LLM 컨텍스트 선별에 그대로 쓰인다.

## 확인해 주실 것 하나

주신 4-9 항목이 **"왜 그런가"가 빠져 있다.**

> M16A(6F)와 R4(6F)는 같은 층에 있지만 이동시 FAB간 반송으로 간주한다
> (중간에 OHT명 변경)

지금은 **사실로** 적어 뒀다. 만약 이게 시스템상 그런 것이 아니라
**운영 관례**라면 `(관례)` 를 붙여 주셔야 한다. 나중에 이 문서로 판단할
사람이 헷갈린다 — 「사실과 추정 구분」이 품질 기준에 있다.

## AMOS 문서 (06~10) — 가장 쉬운 길

AMOS USER GUIDE 를 다섯 쪽으로 나눠 뒀다. 다섯 개 다 머리말이 붙어 있어서
**업로드 한 번으로 페이지가 된다.** 양식에 손으로 옮겨 적을 필요 없다.

### 순서

1. 위키 웹앱(`app.py` · 기본 **:8100**)을 연다.
2. **담당을 `버추얼 아바타`** 로 고른다 — 화면에 뜨는 이름 그대로면 된다.
3. **소스 업로드** 칸에서 `md는 페이지로` 체크를 **켠 채로** 둔다 (기본 켜짐).
4. `06_` ~ `10_` md 다섯 개를 한 번에 올린다.
5. 활동 로그에 **`page-import`** 로 찍히면 성공이다.
   `소스 N건` 으로 찍혔으면 3번 체크가 꺼져 있었다는 뜻이다.

### 두 번 올려도 된다

같은 제목이면 **고친다**(upsert). 쌍둥이 페이지가 안 생긴다.
문서를 손보고 다시 올리면 그대로 갱신된다.

### 서윤·서햄터가 언제 이걸 찾나

`avatar_2d/avatar/config.py` 의 위키 트리거에 AMOS 말들을 넣어 뒀다 —
`AMOS` · `Site 모니터링` · `Layout 모니터링` · `Custom 모니터링` ·
`FAB 상세` · `통신 이상` · `MES` · `MCS` · `서버 리소스` · `CPU` ·
`Alarm 설정` · `알람 이력` · `연락처` · `AI Agent` · `챗봇`.

**낱말 `알람`·`모니터링` 만으로는 안 건다.** 그러면 "지금 알람 떴어?" 같은
관제 질문마다 위키를 뒤진다. `MCP` 도 뺐다 — 아바타 자신의 MCP 설정 질문이
걸린다.

### ★AMOS 는 화면 설명이지 지금 수치가 아니다

이 다섯 쪽은 **AMOS 가 무엇을 보여 주는가**를 적은 것이다.
지금 점수·건수·등급은 관제(real_time_amhs) 실시간 데이터로 답한다.
문서 안에도 그 줄을 박아 뒀다 — 섞이면 "AMOS 가 Site 이상을 보여 준다" 가
"지금 이상이 있다" 로 둔갑한다.

### 가이드에 없는 것은 없다고 한다

USER GUIDE 는 **각 메뉴가 무엇을 하는가**까지다. 임계값·색 기준·갱신 주기·
Alarm 등급 체계·통보 수단은 문서에 없다. 각 쪽에 `가이드에 안 적힌 것`
절을 두고 그렇게 적어 놨다 — 짐작해서 답하면 그게 제일 나쁘다.
