# 02. 카파시톤 — 왜 이 룰인가 (1차 원리)

> 답을 외우지 말고, "정상 분포의 어디에 임계가 있는가" 부터 다시 짚어 판단하라.
> 본 문서는 LLM 이 "왜 이 룰을 적용해야 하는가" 를 이해하기 위한 배경.

---

## Lecture 0 — 무엇을 보는가

반도체 FAB OHS (반송 시스템). FOUP (웨이퍼 통) 이 OHT 를 타고 장비 간 이동.
중심 허브 = **M16HUBROOM**. M14 / M16 모든 FOUP 이 통과.

허브가 막히면 → 전체 라인 정체. 목표: **"M16HUB 가 막힐 징조를 매분 잡아라"**.

## Lecture 1 — R-A (반송시간) 의 1차 원리

**왜 측정**: 1분 평균 반송시간 = OHT 효율의 직접 지표. 트래픽 가중치 자동 반영.

**왜 영역별 임계 다른가**: 영역마다 baseline 다름.
- M16HUB 는 본래 느림 (허브, 환승)
- M14 는 단순 입구 (빠름)
- M16B 는 멀리 위치 (조금 느림)

**왜 두 단계 (RA + RA_sus)**:
- RA = 절대 임계 (1회 spike)
- RA_sus = 지속 (5분 중 3~4회)
- "9분 한 번"보다 "6분이 3번"이 더 무섭다 — 만성 정체 신호

**왜 추천값이 v4.1 보다 높은가**:
- v4.1 임계는 정상 분포 p95 근처 → false positive 많음
- 추천값 = p99 + 마진 → 정상 흡수, 사건만 잡음
- 예: M16B 정상값 2.5~3.0분. v4.1 3.5 = 정상의 끝. 추천 6.0 = 진짜 정체

---

## Lecture 2 — R-B (큐 누적) 의 1차 원리

**왜 큐를 보는가**: 큐가 누적된다 = 생산 ≫ 처리. 데드락 전조.

**왜 30분 / 10분 두 윈도우**:
- 30분 = 만성 누적 (큰 추세)
- 10분 = 급증 (폭주)

**왜 영역별 임계 다른가**:
- M16HUB.M14TOM16 = 허브 자체 누적 (100 정도면 위험)
- M14.3F_TO_HUB_JOB = 입구 누적 (80 위험)
- M14B 는 천천히 (150 까지 정상)

---

## Lecture 3 — R-C (리프터 역증가) 의 1차 원리

**왜 단순 임계 X**: 리프터 큐는 정상도 0~30 변동.

**왜 "역증가" 개념**: 전체 합이 감소하는데도 일부 리프터만 증가 = **균형 깨짐**.
한쪽 리프터 고장 → 다른 리프터로 몰림 → 그 리프터만 큐 폭발.

**왜 20분 윈도우**: 리프터 큐는 변동 폭이 커서 짧은 윈도우는 노이즈.

**왜 임계 12 (추천)**: 정상 시 평균 1~5대만 역증가. p99 = 10. 12 = 마진.
v4.1 의 2 = 너무 낮음 (정상 패턴도 잡음).

---

## Lecture 4 — R-D (Fab 적체) 의 1차 원리

**왜 두 신호 (FAB / STB)**:
- FAB = 전체 저장률 (창고 차오름)
- STB = STB 영역만 (특정 포인트)

**왜 STB 임계 101 (사실상 해제)**:
- ★ STB 가 98~100% 인 게 **정상 가동의 정점**.
- 허브가 정상 가동할 때 STB 는 거의 항상 포화 상태 (운영 효율 ↑).
- v4.1 99% 임계는 "정상의 정점" 을 잡아 매분 false positive.
- 추천 101% = STB 룰 사실상 해제 + FAB/OHT 만 사용 → 정상 흡수.

**왜 OHT 95%**: OHT 가동률 95% 이상 = 거의 풀가동. 큐 증가 임박.

---

## Lecture 5 — SLA (4분 초과율)

**왜 4분**: 회사 약속 (Service Level Agreement) — FOUP 4분 이내 도착.
초과 시 생산 라인 대기 발생.

**왜 영역별 임계 차이 큰가**:
- M16HUB 는 통과만 (5% 면 위험)
- M14 는 입구 + 자체 처리 (25~28% 까지 정상)
- M16A/M16B 는 멀리 (M16A 13~20%, M16B 18~45%)

**왜 M16B 추천 임계 45**:
- 정상 분포 자체가 11~17% 인데 가끔 50% 스파이크 (장비 특성).
- v4.1 18 = 정상의 정점 잡음. 추천 45 = 진짜 비정상만.

---

## Lecture 6 — Sorter (LOT 대기)

**왜 측정**: Sorter 가 막히면 다음 단계 (Load Port) 도 막힘.

**왜 M14 추천 임계 420**:
- ★ M14 Sorter 정상 부하 p50 = 243 LOT (정상 평균).
- v4.1 100 = 정상 절반 수준 → 매분 위반 (false positive).
- 추천 420 = 정상 max (≈300) + 마진.

---

## Lecture 7 — 통합 단계 (S1/S2/S3) 의 논리

**왜 단순 합산 X**: 룰 1개 발동으로 S3 = 거짓 알람 많음.

**S3 확정 조건 (모두 동시)**:
- R-A (반송시간 비정상)
- AND (R-D 또는 SLA 또는 R-C) — 진짜 부하 신호
- AND (R-B 또는 Flow 위험) — 큐 누적 증거

→ "느리고 + 저장소 차고 + 큐 쌓이면" = 진짜 정체.

**S2 / S1 은 부분 신호**:
- S2 = R-B 만 (큐 누적, 잠재)
- S1 = R-A 만 (반송 느림, 조기)

---

## Lecture 8 — 추천값 vs v4.1 결정의 1차 원리

**왜 추천값을 만들었나**: v4.1 임계 = 2026-03~04 학습 데이터 p95 기준.
실제 운영해 보니 정상가동의 정점 (p99 근처) 을 잡아 false positive 폭주.

**추천값 = 정상 p99 + 마진**.
- 정상 흡수율: 0% → 81%
- 사건 탐지: 유지 (5/8 사건 등 진짜 위험은 그대로 발동)

**핵심 통찰**: 임계는 정상 분포의 **정점 위** 에 있어야 함.
정상의 정점에 임계 = 매분 발동 = 알람 무용지물.
