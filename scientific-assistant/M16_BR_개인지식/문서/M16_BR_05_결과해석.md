# 05. 결과 해석 가이드 (LLM 필독)

> 사용자가 데이터를 주면 스크립트가 평가해 **두 결과**를 만든다. LLM은 이 결과를
> 아래 컬럼 사전으로 읽고, `02_카파시톤`(원리)·`04_임계값`(수치)으로 진단한다.
> **결과 숫자는 스크립트가 계산한 것 — LLM이 재계산/추측하지 말 것.**

```
raw CSV(265 메트릭) → [hubroom_predictor 실행] → ① 발동이벤트.csv (분당 판정)
                                                 → ② 사건단위.csv  (S3 사건)
LLM은 ①②를 받아 해석만 한다.
```

---

## ① 발동이벤트.csv — 분당 평가 (매 1분 1행)

핵심 컬럼만(뒤쪽 *_pts_*, *_count 등은 ML피처라 무시 가능):

| 컬럼 | 의미 | 값 해석 |
|---|---|---|
| `datetime` `date` `time` | 평가 시각 | |
| `stage` | 단계 코드 | **0**=이벤트없음 / **1**=조기경보 / **2**=주의보 / **3**=⭐확정 |
| `stage_name` | 단계 이름 | "3단계 ⭐확정" 등 |
| `transition` | 단계 전이 | 직전 분 대비 단계 변화 |
| `unified_risk_score` | 통합 위험점수 | 0~500. 높을수록 위험 |
| `unified_risk_level` | 위험 등급 | 아래 6단계 표 참조 |
| `hot_area` | 가장 위험한 영역 | M16HUB/M14/M14B/M16A/M16B/M16/M16_PKT/M16_WT |
| `hot_score` | hot_area 점수 | 영역점수(최대 50) |
| `affected_areas` | 영향 영역들 | `;`로 구분 (예: `M16HUB;M16B`) |
| `propagation_chain` | 전파 경로 | 영역 간 정체 번짐 |
| `{영역}_score` | 영역별 점수 | 각 영역 0~50 (M16HUB_score 등) |
| `{영역}_signals` | 영역별 발동 룰 | `+`로 연결 (예: `RA+RD`, `RA_sus+SLA`) |
| `reason` | 한 줄 종합 사유 | 발동 룰 + 핵심 컬럼=값(기준) 요약 |

### 위험 등급 (unified_risk_level) — 점수→등급
| 점수 | 등급 |
|---|---|
| ≥ 250 | 매우위험 |
| ≥ 150 | 위험 |
| ≥ 80 | 주의 |
| ≥ 65 | 경계 |
| ≥ 30 | 관심 |
| < 30 | 정상 |

### 단계 판정 의미 (stage)
- **S3 확정**: `반송 느림(RA) AND (저장소/SLA/리프터 RD·SLA·RC) AND (큐누적 RB 또는 흐름심각)` — 진짜 정체
- **S2 주의보**: 큐 누적(RB)만
- **S1 조기경보**: 반송 느림(RA/RA_sus)만

### signals 약어 (발동한 룰)
`RA`=반송시간 / `RA_sus`=지속정체 / `RB`=큐누적30분 / `RB_fast`=큐폭주10분 /
`RC`=리프터역증가 / `RD`=Fab적체·OHT / `SLA`=4분초과율 / `SORT`=Sorter대기 / `MAXCAPA`=운영변수변경

## ② 사건단위.csv — S3 사건 (사건 1건 = 1행)

| 컬럼 | 의미 | 해석 |
|---|---|---|
| `predict_time` | 최초 사전 감지 시각 | |
| `start_time` `end_time` | 사건 시작/종료 | |
| `lead_min` | **사전 감지 분** | 사건 본격화보다 몇 분 먼저 잡았나 (클수록 좋음) |
| `duration_min` | 지속 시간(분) | |
| `refire_count` | 재발 횟수 | 사건 내 S3 재발동 |
| `max_risk_score` | 최대 위험점수 | |
| `max_risk_level` | 최대 등급 | |
| `hot_area` | 핵심 영역 | |
| `affected_areas` | 영향 영역 | |
| `propagation_chain` | 전파 경로 | |
| `triggered_rules` | **발동 룰 상세** | 영역별 (예: `M16HUB:RA+RC+RD; M14:RA_sus+SLA`) |
| `risk_factors` | **핵심 위험요인** | raw 컬럼=값(>=임계) (예: `M16HUB.QUE.TIME.AVGTOTALTIME1MIN=13.40분(>=9.0)`) |
| `maxcapa_changes` | 운영자 변수 변경 | |
| `relation` | 영역별 컬럼-값-임계 상세 | |

> `risk_factors`가 인용하는 `영역.카테고리.메트릭` 은 raw 입력 컬럼명이다(아래 명명규칙).

---

## ③ raw 입력 컬럼 명명규칙 (risk_factors 연결용)

형식: **`영역.카테고리.메트릭`** (예: `M16HUB.QUE.TIME.AVGTOTALTIME1MIN`)

- **영역**: M16HUB(중심허브) / M14 / M14B / M16A / M16B / M16 / M16_PKT / M16_WT
- **카테고리**: `QUE`(큐/반송) / `LFT`(리프터) / `STRATE`(저장률) / `SORTER` / `OHT`(가동률) / `CNV`(컨베이어)
- 자주 나오는 메트릭:
  - `QUE.TIME.AVGTOTALTIME1MIN` / `QUE.LOAD.AVGLOADTIME1MIN` = 1분 평균 반송시간(분) → R-A
  - `STRATE.STB.3F_STORAGE_UTIL` = STB 점유율(%) → R-D (98~100%는 **정상 정점**)
  - `STRATE.ALL.FABSTORAGERATIO` = FAB 저장률(%) → R-D
  - `QUE.ALL.*_TO_HUB_JOB` / `QUE.M14TOM16.MESCURRENTQCNT` = 큐 누적 → R-B
  - `SORTER.ABN.SORTERWAITCOUNTOVER` = Sorter 대기 LOT → SORT
  - `QUE.ALL.TRANSPORT4MINOVERRATIO` = 4분 초과율(%) → SLA
  - `QUE.OHT.OHTUTIL` = OHT 가동률(%) → R-D

## ④ 해석할 때 강제 원칙

1. **임계 인용은 `04_임계값.md`** 표만. 자체 숫자 생성 금지. (현재 추천 임계 적용 중)
2. **"왜 위험/정상인가"는 `02_카파시톤.md`** 원리로. (예: STB 99% = 정상 정점이라 안전)
3. **무발동(stage 0)·정상 등급이 많은 건 "정상 가동"** — "사건 놓침"으로 오해 금지.
   (추천 임계는 정상 81%를 정상으로 흡수하도록 설계됨)
4. **영역명/룰명/단계명은 위 약어 그대로**. 임의 변형 금지.
5. 결과가 **사건단위 0건이면 "S3 확정 사건 없음 = 정상 운영"**, 1건↑이면 그 사건을 `lead_min`·`risk_factors` 중심으로 설명.

## ⑤ 응답 형태 (권장)

```
## 진단 결과 [기간]

### 단계 분포
| 단계 | 분 수 | 비율 |
|---|---|---|
| S3 확정 | N | X% |
| S2/S1/무발동 | ... | ... |

### Hot Area / 주요 발동
- 최다 위험 영역: <hot_area 집계>
- 대표 시각: <stage3 시각> — <signals> (score N)

### 사건 (있으면)
- 사건 #1: predict_time~end_time, lead_min N분 사전, 핵심: <risk_factors>

### 결론
[정상 운영 / 사건 의심 / 확정 위험] + 근거 1줄

### 카파시 해설
[02 원리 1~2문장 — 왜 그렇게 판단했는지]
```

소형 모델은 짧게. "상세" 요청 시만 길게.
