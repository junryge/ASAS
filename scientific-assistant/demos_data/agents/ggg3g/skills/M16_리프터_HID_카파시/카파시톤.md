# 카파시톤 — 리프터 HID 근처차량수 해석 원리 (왜·어떻게)

> 이 문서는 **계산이 아니라 "해석"** 을 위한 지식이다.
> 일반 스크립트(`count_lifter_inout.py`)가 뽑은 **근처차량수 데이터**를 받아서,
> "왜 이걸 보는지 / 어느 리프터가 왜 붐비는지" 를 사람이 이해하게 설명하는 데 쓴다.
> (SK하이닉스 M16A_BR OHT 반송)

---

## 1. 왜 이걸 보는가 (목적)

리프터는 OHT 반송에서 **층·구간을 잇는 길목(병목 지점)** 이다.
리프터 바로 옆 HID4 구역에 차량이 몰리면 → 리프터로 **진입·진출이 밀리고** →
그게 쌓이면 **반송 지연, 심하면 데드락**으로 번진다.

그래서 **리프터 근처 HID 구역에 1분마다 차량이 몇 대 있었는지(근처차량수)** 를 보면,
**"어느 리프터 주변이 언제 붐볐는지"** 를 데이터로 짚을 수 있다.
→ 이게 설비 증설·경로 조정·스케줄 개선의 **근거**가 된다.

---

## 2. 입력 데이터 (일반 스크립트 결과)

`시각, Lifter, FAB, 근처HID, 경계mm, 근처차량수`

| 컬럼 | 뜻 |
|------|----|
| 시각 | 1분 단위 (YYYY-MM-DD HH:MM) |
| Lifter | 리프터 ID (`6ABL*`=M16, `4ABL*`=M14) |
| FAB | M16 / M14 |
| 근처HID | 그 리프터에 경계가 가장 가까운 HID4 구역(1~37) |
| 경계mm | 리프터–HID 경계 거리 (작을수록 더 밀착) |
| **근처차량수** | **그 1분에 그 HID4 를 거친(진입 TO 또는 진출 FROM) 고유 차량(VHL_ID) 수** |

- 같은 HID4 를 근처로 두는 리프터들은 **같은 값** (HID 단위 집계라서).
- HID_INOUT 로그가 HID4(1~37)만 기록하므로 HID4 기준이다.

---

## 3. 어떻게 해석하는가 (판단 규칙 — 이 문서의 핵심)

근처차량수를 읽고 **왜 그런지**를 다음 관점으로 설명한다.

- **근처차량수 높음** = 그 1분에 그 HID4 구역으로 차량이 많이 몰림
  → 그 리프터 **주변이 붐빈다 / 진입·진출 정체 의심**. (유입이 처리량보다 많다는 신호)
- **특정 1분만 급등(스파이크)** = **순간 병목**.
  차량이 잠깐 몰렸다 풀린 것 — 일시적. (예: 특정 시각만 튐)
- **여러 분 연속으로 높음** = **만성·구조적 혼잡 지점**.
  그 리프터/HID 는 상시 붐비는 곳 → 우선 개선 대상.
- **근처차량수 낮음/0** = 한산. 정상 흐름이거나 그 시간 트래픽 없음(죽은 라인 가능).
- **경계mm 작은데(밀착) 근처차량수 높음** = 리프터가 그 혼잡 HID 에 바짝 붙어 있어
  **영향을 직접 받는다** → 더 주의.
- **시간대 비교** = 분별 추이를 훑어 **peak 시간대**(가장 붐빈 분/구간)를 짚는다.

---

## 4. 무엇을 보고하는가 (결과물)

데이터를 읽고 아래를 글로 정리한다.

1. **어디** — 근처차량수 상위 리프터/HID (가장 붐빈 곳)
2. **언제** — peak 시간대, 순간 스파이크가 난 분
3. **왜** — 유입 과다 / 순간 몰림 / 만성 혼잡 중 무엇인지 (위 규칙으로 판단)
4. **영향·권장** — 반송 지연 위험, 경로·스케줄 조정 또는 모니터링 제안

---

## 5. 주의

- 이 데이터는 **"개수(근처차량수)"** 만 본다. **용량 대비 포화도**(꽉 찼는지)는 **별도 스킬**이 판단한다.
- 트래픽이 계속 0 인 라인(죽은 라인)은 해석 대상에서 제외한다.
- 근처차량수는 FROM∪TO 기준 **고유 차량 수**다 (같은 차량 중복 안 셈).
