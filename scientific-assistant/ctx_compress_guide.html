01 / 왜 이걸 쓰나

컨텍스트가 터지기 전에 접는다

에이전트가 툴을 돌리면 JSON 응답, 빌드 로그, 검색 결과가 컨텍스트에 쌓인다. 이 원문 대부분은 반복이거나 노이즈다. ctx_compress는 내용 타입을 판별해 알맞은 방식으로 접고, 정보가 살아있는 부분만 남긴다.

single file
파일 하나로 끝
파이썬 표준 라이브러리만 사용. pip 설치 없이 파일 복사만 하면 동작한다.
air-gap ready
폐쇄망 그대로
외부 네트워크·모델 다운로드 없음. 텍스트 파일이라 반입도 복사 한 번.
reversible
가역 복구(CCR)
버린 원본을 해시로 보관하고 마커를 남긴다. 필요하면 원본을 그대로 꺼낸다.
type-aware
타입별 압축
JSON·로그·코드·검색·diff·텍스트를 각각 다른 안전한 전략으로 처리한다.
02 / 빠른 시작

세 줄이면 붙는다

파이썬 3.10 이상. ctx_compress.py를 프로젝트에 두고 임포트한다.

# 압축 + 복구맵 받기
from ctx_compress import compress, retrieve

compressed, refs = compress(tool_output)
# compressed: 압축된 문자열 (안에 <<ccr:ID>> 마커가 있을 수 있음)
# refs: {ID: 원본조각} 복구용 딕셔너리

# LLM이 원본이 필요하다고 하면 마커 ID로 되찾기
original = retrieve("a7ca41b8", refs)

압축이 손해면(오히려 커지거나 줄일 게 없으면) 엔진이 알아서 원본을 그대로 돌려준다. 짧은 입력(기본 50토큰 미만)은 건드리지 않고 통과시킨다. 안전한 기본값이다.

04 / 처리 방식

내용을 보고 알아서 나눈다

입력이 들어오면 먼저 타입을 판별한다. 순서는 JSON → diff → 검색결과 → 로그 → 표 → 코드 → 일반텍스트이고, 각각 신뢰도 점수로 갈린다. 판별된 타입에 맞는 압축기로 보낸다.

  • JSON 배열 — 같은 스키마의 딕셔너리 배열을 컬럼형으로 접어 반복 키를 없앤다. 행이 너무 많으면 정보량 기준으로 자르고 버린 행은 CCR로 보관한다.
  • 로그 / 빌드 출력 — 줄마다 중요도 점수를 매긴다. ERROR·FAIL은 최상위, 스택트레이스·요약줄은 가산점. 첫 에러와 마지막 에러는 항상 남기고, 반복 경고는 꼬리 숫자만 정규화해 묶는다.
  • 소스 코드 — 파이썬은 AST로 함수·클래스 시그니처와 독스트링 첫 줄만 남기고 본문을 접는다. 다른 언어는 정규식으로 선언·시그니처 줄을 추린다.
  • 검색 결과 — grep/ripgrep 형식(file:line:)을 정보량 기준으로 상위만 남기고 나머지는 개수로 표시한다.
  • git diff — 헤더와 변경(+/−) 줄은 유지하고 컨텍스트 줄만 축소한다.
  • 일반 텍스트 — 연속 빈 줄을 하나로, 완전 중복 줄을 제거한다. 룰 기반이라 외부 모델을 부르지 않는다.

압축 강도 조절 (bias)

# bias=1.0  통계 신뢰 (기본)
# bias>1.0  보수적 — 덜 압축, 더 보존
# bias<1.0  공격적 — 더 압축
compressed, refs = compress(data, bias=0.7)  # 세게 압축
05 / 가역 복구

버려도 잃지 않는다 (CCR)

압축의 공포는 "정보가 영영 사라지는 것"이다. ctx_compress는 버린 원본을 해시로 보관하고, 압축본에는 참조 마커만 남긴다. LLM이 그 마커를 보고 원본이 필요하다고 판단하면 언제든 꺼낼 수 있다. 그래서 겁 없이 세게 압축해도 된다.

1
300행 JSON에서 정보량 판단 후 41행만 남기고 259행을 버린다.
2
버린 259행은 원본 그대로 refs에 해시로 저장. 압축본 끝에 {"_ccr_dropped": "<<ccr:a7ca41b8 259_rows_offloaded>>"} 마커를 남긴다.
3
LLM이 마커를 보고 "원본 필요"라고 하면 retrieve("a7ca41b8", refs)로 259행 전체를 그대로 복구한다.
# 압축본에서 마커 뽑아 복구하기
from ctx_compress import compress, retrieve, find_markers

compressed, refs = compress(big_json)
ids = find_markers(compressed)      # ['a7ca41b8', ...]
if ids:
    original = retrieve(ids[0], refs)  # 원본 그대로
06 / 공유와 배포

다른 사람도 쓸 수 있나 — 그렇다

이 엔진의 강점이 배포다. 무겁게 설치할 게 없어서 파일 하나만 넘기면 누구든 바로 쓴다.

  • 파일 복사만. ctx_compress.py 하나를 상대 프로젝트에 두면 끝. pip install 불필요.
  • 폐쇄망끼리도 그대로. 외부 의존성이 없어 base64 반입 같은 절차 없이 텍스트 파일 복사면 된다.
  • 단 하나의 조건 — 파이썬 3.10 이상. 최신 타입 힌트 문법을 쓴다. 상대 환경의 파이썬 버전만 확인하면 된다.
  • 패키지화도 가능. 원하면 나중에 사내 pip 패키지나 스킬로 감쌀 수 있다. 지금 구조 그대로도 충분하다.
3.9 이하 환경이라면
str | None 같은 표기를 Optional[str]로 바꾸는 소규모 수정이 필요하다. 대상 환경이 구버전이면 백포트 버전을 따로 만들어 두는 편이 낫다.
07 / 파이프라인 통합

컨텍스트 조립 직전에 한 줄

스킬 라우터나 에이전트가 만든 툴 출력을 컨텍스트에 넣기 직전, 그 지점에서 compress()를 통과시킨다. 라우터 로직은 건드리지 않는다. 

# 툴 출력을 컨텍스트에 넣기 전 압축
def assemble_context(tool_outputs, session_refs):
    parts = []
    for out in tool_outputs:
        compressed, refs = compress(out, bias=0.9)
        session_refs.update(refs)   # 세션에 복구맵 누적
        parts.append(compressed)
    return "\n\n".join(parts)

# 나중에 LLM이 마커로 원본 요청하면 session_refs에서 retrieve

복구맵(refs)은 세션 단위로 들고 있으면 된다. 프로세스 전역 상태가 없어서 여러 세션이 섞이지 않는다.

08 / API 참조

공개 함수

compress(content: str, bias=1.0) → (str, dict)
간편 진입점. 압축본 문자열과 복구맵을 튜플로 돌려준다. 대부분 이거면 충분하다.
retrieve(ref_id: str, refs: dict) → str | None
마커의 ref_id로 원본을 복구한다. 마커 문자열 전체를 넘겨도 알아서 파싱한다. 없으면 None.
find_markers(text: str) → list[str]
압축본 안의 모든 CCR ref_id를 뽑는다.
compress_detailed(content: str, bias=1.0) → CompressResult
메타데이터까지 필요할 때. 타입·전략·토큰 수·드롭 수를 포함한 결과 객체를 준다.
CompressEngine(bias=1.0, min_tokens=50, log_config=None)
엔진 인스턴스. 설정을 고정해 재사용할 때. .compress(content) 호출.

CompressResult 필드

필드의미
text압축된 결과 문자열
refs복구용 {ref_id: 원본} 딕셔너리
content_type판별된 타입 (json_array, build, source_code …)
strategy사용된 압축 전략명
