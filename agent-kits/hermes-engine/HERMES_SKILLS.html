🔮 헤르메스 스킬 Hermes Skills

헤르메스 스킬은 2종류 — ① 빌트인(공통·자동) + ② 자기학습(사용자별·동적). 순수 프롬프트 기반 · 폐쇄망/GGUF/API 무관.
※ 데모스 공용 388개 스킬은 별개(데모스 자산).

1. 빌트인 스킬 4종 공통 · 자동 주입

질문에 키워드가 맞으면 점수 상위 2개가 시스템 프롬프트에 자동 주입. (hermes/builtin.py)

🧭 task-planning
복잡한 작업은 먼저 단계 계획을 세우고 실행
만들구현설계프로그램코드연구분석계획파이프라인단계아키텍처builddesignresearch
복잡·다단계 요청이면 바로 답하지 말고:
1) 목표를 한 줄로 정의
2) 3~6단계 실행 계획 제시(각 단계 산출물 명시)
3) 계획대로 실행/작성
4) 마지막에 빠진 단계가 없는지 자가점검
🐞 systematic-debugging
오류는 재현→가설→최소수정→검증 순서로
오류에러버그디버안돼실패exceptiontraceback고장errorbugfix
오류 해결 순서:
1) 증상/재현 조건 명확화
2) 원인 가설 2~3개
3) 가능성 높은 것부터 최소 변경으로 검증
4) 환경 의존(패키지/권한) vs 코드 문제 구분
5) 수정 후 재현 절차로 검증
📊 structured-data-analysis
데이터는 컬럼/단위 확인 후 가설→통계→시각화
데이터분석통계반송FAB로그수율OHTOHSCSV엑셀컬럼추세이상dataanalysis
데이터 분석 절차:
1) 컬럼명·단위·기간을 먼저 확인(추측 금지)
2) 분석 질문을 가설로 정의
3) 기술통계 → 이상치 → 상관/추세 순
4) 실제 값/컬럼만 인용(없는 값 만들지 말 것)
5) 결론 + 표/차트 시각화 권고
✅ answer-verification
최종 답 전 자가검증(근거·누락 확인)
보고서결론정확검증요약reportverify
최종 답 직전 자가검증:
1) 인용한 수치·컬럼·함수가 실제 컨텍스트에 있는가?
2) 단정 대신 근거를 붙였는가?
3) 요청을 빠짐없이 다뤘는가?
불확실하면 추측임을 명시한다.

2. 자기학습 스킬 사용자별 · 동적

에이전트가 스스로 만드는 개인 스킬. 처음 0개 → 작업하며 누적. (hermes/skills.py)

저장demos_data/agents/<user_id>/skills/<이름>/SKILL.md
생성재사용 가치 절차 발견 → ```hermes:skill 블록 → 사용자 승인(확인형) 후 저장
회상질문 관련 시 BM25 상위 2개 본문 자동 주입 (인덱스는 이름+설명만)
관리🔮 헤르메스 → 📚 배운 스킬 탭 — 보기 / 📌pin / 삭제
이름 규칙소문자-하이픈(2~40자), 일회성/날짜 이름 거부
큐레이터30일→stale, 90일→archived (pinned 면제, 자동삭제 없음)
액션create · patch(find→replace) · edit · delete

3. 데모스 연계 — 🧭 헤르메스 작업스킬 조합

빌트인 4종 ↔ 실제 scientific-skills 매핑. 스킬조합 드롭다운에서 수동 선택(헤르메스 안 켜도 사용).
