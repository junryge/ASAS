# 🔮 헤르메스 — 기억(Memory) vs 스킬(Skill) 로직 설명

> 고객 질문: *"'기억'이 포함되면 해당 내용을 기억하는데, skill 같은 경우는 어떤 로직인가요?"*
>
> 한 줄 답: **메모리는 *사실/선호*라 한 문장으로 즉시 자동 저장**되고,
> **스킬은 *재사용 절차*라서 모델이 가치 있다고 판단할 때만 → 검증·사용자 승인을 거쳐 저장**된 뒤,
> 이후 관련 질문에 **검색(BM25)으로 본문을 골라 주입**됩니다.

---

## 1. 메모리 vs 스킬, 무엇이 다른가

|  | 🧠 **메모리 (memory)** | 📚 **스킬 (skill)** |
|---|---|---|
| **본질** | "무엇을 안다" — 사실·선호 | "어떻게 한다" — 재사용 절차·해법 |
| **예시** | "M16 FAB OHT 반송 정체를 분석한다" / "표로 답변 선호" | "OHT 정체 원인 추적 절차 1→2→3" |
| **형태** | 선언형 **한 문장** | 여러 줄 **본문(단계 절차)** |
| **저장 시점** | **즉시 자동 저장** (승인 게이트 없음) | **검증 + 사용자 승인 후** 저장 |
| **컨텍스트 주입** | 매 턴 **전체** 주입 | 평소 **이름만**, 관련될 때 **본문**만 주입 |
| **저장 형식** | `MEMORY.md` / `USER.md` 의 한 줄 | `skills/<이름>/SKILL.md` 파일 |

> 판단 기준 한마디: **사실이면 메모리, 방법/절차이면 스킬.**

---

## 2. 스킬 로직 — 4단계 생애주기(Lifecycle)

```
 ① 생성 판단        ② 검증 + 승인          ③ 회상/주입            ④ 관리
 (모델이 결정)  →   (게이트 통과)    →    (질문에 맞게)     →    (유지보수)
 재사용 가치        이름규칙·인젝션         인덱스 항상 +          patch/edit/
 있는 절차 발견     검사 + 사용자 OK        본문은 BM25 매칭시      delete/archive
```

### ① 생성 판단 — "언제 스킬로 만드나"
모델이 판단합니다. **단순 사실**이면 메모리로, **재사용 가치 있는 "절차/해법"**
(다단계 작업 완료 · 까다로운 오류 해결 · 비자명 워크플로)을 발견하면 답변 끝에 블록을 냅니다.

````
```hermes:skill
action: create
name: oht-jam-triage          # 소문자-하이픈 클래스명
when: OHT 반송 정체 원인 추적 시   # 언제 쓰는지 한 줄
body: |
  1. 구간별 큐 길이 확인
  2. 병목 구간 OHT 가동률 비교
  3. ...
```
````

### ② 검증 + 승인 — 메모리와 **가장 큰 차이**
스킬은 **자동 저장이 안 됩니다.** 아래 게이트를 통과해야 함 (`hermes/skills.py`):

- **이름 규칙**: `oht-jam-triage` 처럼 *재사용 가능한 클래스명*만 허용.
  `test` · `fix-1` · 날짜(`2026-06-09`) · `temp/오늘` 같은 **일회성 이름은 거부**.
- **인젝션 검사**(`looks_injected`): 악성·프롬프트인젝션 의심 본문 차단.
- ⭐ **사용자 승인 필수**: `pending_skills` 로 빠져나오고, 사용자가 **OK 해야** `confirm_skill()` 로 실제 저장.
  (메모리는 바로 저장, 스킬은 **승인 한 단계 더** — 이게 핵심 차이)
- **저장 위치**: `<data>/agents/<user>/skills/<이름>/SKILL.md` (프론트매터 + 본문)

### ③ 회상/주입 — "저장된 스킬을 어떻게 꺼내 쓰나"
- 매 질문마다 **인덱스(이름: 설명)만** 시스템 프롬프트에 **항상** 주입 (`index_text`).
- 질문과 관련되면 **BM25 검색**(`recall`)으로 **상위 2개 본문**까지 주입.
  → 토큰 절약을 위해 *관련될 때만* 본문을 넣음 (전부 넣지 않음).
- 사용할 때마다 `use_count` / `last_used` **사용 통계** 기록.

### ④ 관리 — 유지보수 액션
| 액션 | 설명 |
|---|---|
| `create` | 신규 스킬 생성 |
| `patch` | 본문 일부만 치환 수정 (`find`→`replace`) |
| `edit` | 본문 전체 교체 |
| `delete` | 스킬 삭제 |
| (자동) `archived` | 오래 안 쓰면 회상에서 제외 |

## 3. 전체 흐름 한눈에

```
[사용자 발화]
     │
     ▼
모델 답변 생성 ──► 답변 끝에 블록을 냄
     │
     ├─ hermes:memory ─► (사실/선호)  ─► 즉시 자동 저장 ─► MEMORY.md / USER.md
     │
     └─ hermes:skill  ─► (재사용 절차) ─► 이름·인젝션 검증
                                             │
                                       사용자 승인? ──No──► 폐기
                                             │Yes
                                             ▼
                                    skills/<이름>/SKILL.md 저장
                                             │
                          [다음 질문] ─► 인덱스 항상 주입 + BM25로 관련 본문 주입
```

## 5. 자주 묻는 것

- **Q. 왜 스킬만 승인을 받나요?**
  메모리는 한 문장 사실이라 틀려도 영향이 작지만, 스킬은 *앞으로 계속 적용될 절차*라 잘못 학습되면 반복적으로 영향을 줍니다. 그래서 사용자가 한 번 확인합니다.
- **Q. 스킬이 매번 다 끼어들면 토큰이 너무 커지지 않나요?**
  아니요. 평소엔 **이름·설명 한 줄(인덱스)**만 들어가고, **질문과 관련된 스킬 본문 2개**만 BM25로 골라 넣습니다.
- **Q. 메모리에 절차를 적으면 안 되나요?**
  지침상 메모리는 **선언형 한 문장**만 — 절차·방법은 메모리가 아니라 **스킬**로 저장하도록 모델에게 안내합니다.
