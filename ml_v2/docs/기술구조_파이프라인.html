왜 1개인가

먼저 단일 신호로 목표를 달성하는지 확인하는 단계입니다. 선행지표를 예측 입력(covariate)으로 넣는 것은 lead 를 더 늘리려 할 때의 다음 카드입니다.

시점 t

매 1분, 90분을 보고 30분을 내다봅니다

# detect.py — 시점 t 의 입력은 t 까지의 평활값 90개
ctx = sm[t - context + 1 : t + 1]          # 90개
q   = chronos.predict_quantiles(ctx_3d,
          prediction_length=30,
          quantile_levels=[0.1, 0.5, 0.9])

확률로 바꾸기

분포를 "넘을 확률"로 환산합니다

예측은 값이 아니라 분포로 나옵니다(q10 · q50 · q90). 이 세 점으로 누적분포를 근사해 각 지평마다 임계를 넘을 확률을 계산합니다. 그러면 30분 길이의 확률 곡선이 하나 생깁니다.

판정

네 단계로 나눕니다

단계조건의미
3 이동평균 ≥ 임계 이미 정체 진행 중
2 확률 ≥ p_on 선제 경보 — 몇 분 뒤 넘을 것으로 예측
1 p_off ≤ 확률 < p_on 관찰 (경보 아님)
0 확률 < p_off 정상

켜짐(p_on)과 꺼짐(p_off) 문턱을 다르게 둡니다. 하나로 두면 문턱 근처에서 경보가 켜졌다 꺼졌다 반복하기 때문입니다. 

# detect.py — 히스테리시스
if best_p >= p_on:   active = True
elif best_p < p_off: active = False
# 그 사이 구간은 이전 상태를 유지 → 요동 억제

정답과 채점

무엇을 "맞췄다"고 보는가

매칭 규칙

  • 감지 — 경보 구간이 [사건시작 − pre, 사건종료] 와 겹치면 인정 (--pre 기본 35분)
  • 사전 감지 시간 — 사건 시작 시각 − 가장 이른 경보 시작 시각
  • 헛울림 — 어떤 사건과도 겹치지 않는 경보 구간
  • 연속 경보는 gap 분 이내면 하나의 경보로 병합 (같은 사건에 대한 반복 계수 방지)

신뢰성

미래를 훔쳐보지 않도록 세 가지를 지킵니다

  1. 임계는 학습기간에서만 산출합니다. 평가기간 데이터로 임계를 정하면 성적이 부풀려집니다. (4~6월로 정하고 7월에 그대로 적용)
  2. 이동평균은 과거만 봅니다. 중심이동평균을 쓰면 미래 값이 섞여 들어갑니다.
  3. 예측 입력은 t 시점까지로 잘립니다. 배치로 여러 시점을 한 번에 계산해도 각 시점의 입력은 독립이라 인과성이 유지됩니다.

속도 설계

시점을 하나씩 호출하면 호출 준비 비용이 계산 비용을 압도합니다. Chronos-2 가 다계열 입력을 받으므로 256 시점을 한 번에 묶습니다 — 44,471 시점이 174 회 호출로 처리됩니다.

실행

명령 세 개

# 1. 학습 — 기준을 뽑아 model_config.json 에 저장
python main.py learn --train "RAW/M16A_HUBROOM_PR_202604*.CSV" \
    "RAW/...202605*.CSV" "RAW/...202606*.CSV"

# 2. 스윕 — 모델 1회 실행으로 p_on 값들을 비교
python main.py sweep --config model_config.json \
    --eval "RAW/M16A_HUBROOM_PR_202607*.CSV" \
    --model chronos_2 --device cuda --horizon 30

# 3. 확정 — 고른 p_on 으로 최종 실행
python main.py all --config model_config.json \
    --eval "RAW/M16A_HUBROOM_PR_202607*.CSV" \
    --model chronos_2 --device cuda --horizon 30 --p-on 0.30 \
    --out-actions actions.csv --out-report report.csv
