# 명령어 (순서대로)

## ① 학습 — 4~6월 (한 번만)
```bash
python main.py learn --train "RAW/M16A_HUBROOM_PR_202604*.CSV" "RAW/M16A_HUBROOM_PR_202605*.CSV" "RAW/M16A_HUBROOM_PR_202606*.CSV" --out-config model_config.json
```

## ② 스윕 — 7월 평가 + p_on 최적값 찾기 (모델 1회 실행) ⭐
```bash
python main.py sweep --config model_config.json --eval "RAW/M16A_HUBROOM_PR_202607*.CSV" --model chronos_2 --device cuda --horizon 30 --stride 3
```

나오는 표에서 최적 p_on 을 고른다:
```
  p_on   Recall  Precis   평균lead   ≥10분   5~9분   <5분    헛울림    /일
  0.30    100%     40%     14.2       3      1     0     12   0.4
  0.40    100%     52%     11.5       2      2     0      8   0.3
  ...
```
- `actions_best.csv` / `report_best.csv` 자동 저장 (recall→≥10분전 기준 최고값)
- 느리면 `--stride 5 --batch 512` 추가

## ③ 확정 — 고른 p_on 으로 최종 실행
```bash
python main.py all --config model_config.json --eval "RAW/M16A_HUBROOM_PR_202607*.CSV" --model chronos_2 --device cuda --horizon 30 --p-on 0.4 --pre 35 --out-actions actions.csv --out-report report.csv
```
(`--p-on 0.4` 를 ②에서 고른 값으로 바꿔서)

## ④ 실시간 — 매분 자동 판정 (운영) ⭐
수집기가 매분 덮어쓰는 `predict/M16A_HUBROOM_PR.csv`(직전 90분)를 감시한다.
```bash
python realtime.py --config model_config.json --input predict/M16A_HUBROOM_PR.csv --model chronos_2 --device cuda --p-on 0.30
```

결과는 **`ml_predict/{날짜}_ml_chronos_2.csv`** 에 매분 한 줄씩 쌓인다.
```
datetime,raw_value,smoothed,stage,stage_name,prob,lead_min,threshold,reason
2026-08-18 06:48:00,12.927,9.613,2,선제경보,1.0,7,10.257,약 7분 뒤 임계 초과 예상
```

| stage | 뜻 | 화면 |
|---|---|---|
| 0 | 정상 | (표시 없음) |
| 1 | 관찰 — 상승 조짐 | `· 관찰` |
| 2 | **선제경보** — N분 뒤 초과 예상 | `⚠ 선제경보` |
| 3 | 정체 진행중 (이미 초과) | `🚨 정체 진행중` |

먼저 한 번만 돌려서 확인:
```bash
python realtime.py --config model_config.json --input predict/M16A_HUBROOM_PR.csv --once
```

경보 시 외부 연동(메신저·Logpresso 등):
```bash

```
`notify.py` 는 환경변수로 값을 받는다 —
`ALERT_TIME` `ALERT_STAGE` `ALERT_PROB` `ALERT_LEAD` `ALERT_SMOOTHED` `ALERT_THRESHOLD` `ALERT_REASON`

# 참고

## 지금까지 결과 (7월, 4~6월 학습)

| 지표 | baseline | Chronos-2 (p_on 0.6) |
|---|---|---|
| Recall | 100% | **100%** (4/4) |
| Precision | 33% | **67%** |
| 헛울림/일 | 0.3건 | **0.1건** |
| 평균 lead | 9.2분 | 2.2분 |

Chronos-2 가 정확해서 예측구간이 좁고 → 확실할 때만 울린다(헛울림 3분의 1).
대신 늦게 울리므로 **p_on 을 낮춰 lead 를 되찾는 것**이 ② 스윕의 목적.
precision 67% · 헛울림 하루 0.1건이라 문턱을 낮출 여유가 크다.

## 확인할 것
- `backend=chronos_2` (baseline 이면 모델 폴더 못 찾음 → `--model /경로/chronos_2`)
- `[모델 호출 형태] inputs 3-D ...` 가 뜨면 정상

## 속도
- 배치 처리로 모델 호출이 시점 수의 1/256 로 줄어든다
- `--stride N` = N분마다 예측 (N배 빠름, lead 해상도만 거칠어짐)
- `--batch 512` = GPU 메모리 여유 있으면 더 빠르게

## 튜닝 다이얼
| 옵션 | 기본 | 효과 |
|---|---|---|
| `--p-on` | 0.6 | 낮추면 lead↑ recall↑, 헛울림↑ |
| `--horizon` | 30 | 예측 지평. 크게 = 더 일찍 감지 가능 |
| `--context` | 90 | 모델이 보는 직전 이력(분) |
| `--min-duration` | 10 | 심각 사건 최소 지속. 크게 = 큰 것만 |
| `--pct` | 0.99 | 임계 분위수. 높이면 사건 수↓ |
