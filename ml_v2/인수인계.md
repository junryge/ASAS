# 인수인계 — 필요한 것과 실행법

반송 정체를 **미리** 감지하는 시스템. 4~6월로 기준을 배우고 7월로 검증했다.
심각 정체 4건을 모두 감지, 평균 9.8분 먼저 알렸다.

---

## 1. 필요한 것

### 환경
| 항목 | 요구 | 비고 |
|---|---|---|
| Python | 3.9 이상 | 검증 환경 3.13 |
| GPU | **선택** | 없어도 됨. 있으면 `--device cuda` |
| RAM | 8GB 이상 | CPU 추론 시 기준 |

### 패키지 — 딱 2개
```bash
pip install "chronos-forecasting>=2.0" torch
```
| 패키지 | 언제 필요 |
|---|---|
| `chronos-forecasting>=2.0` · `torch` | **예측할 때** (없으면 내장 baseline 으로 돌아가며 경고 표시) |
| `oracledb` | DB 에서 과거 데이터를 직접 받을 때만 (`aws_idc_history_downloader.py`) |

> `pandas` 는 **필요 없다.** `data.py` · `evaluate.py` · `main.py` 는 표준 라이브러리만 쓴다.

### 모델
`amazon/chronos-2` 가중치 폴더가 필요하다.

- **인터넷 되는 곳**: 첫 실행 시 자동 다운로드
- **폐쇄망**: 인터넷 PC 에서 받아 복사
  ```bash
  pip install "huggingface_hub[cli]"
  huggingface-cli download amazon/chronos-2 --local-dir ./chronos_2
  ```
  받은 `chronos_2/` 폴더를 코드와 같은 위치에 두면 자동으로 인식한다.
  다른 경로면 `--model /경로/chronos_2` 로 지정.

### 데이터
분당 1행 CSV. **최소 2개 컬럼만 있으면 동작한다.**

| 컬럼 | 필수 | 설명 |
|---|---|---|
| `CRT_TM` | ✅ | 시각 (`YYYY-MM-DD HH:MM:SS`) |
| `M16HUB.QUE.TIME.AVGTOTALTIME1MIN` | ✅ | **예측 대상** — HUB 평균 반송시간 |
| 그 외 263개 | ❌ | 현재 예측에 쓰지 않음 (확장 대비 정의만) |

- 파일은 날짜별로 나뉘어 있어도 되고 한 파일이어도 된다 (글롭으로 병합, 시각순 자동 정렬)
- 결측은 직전 값으로 채워 처리한다
- **학습용**과 **평가용 기간이 겹치지 않아야** 성적이 정직하다

## 2. 파일

| 파일 | 역할 | 없으면 |
|---|---|---|
| `data.py` | 로딩 · 이동평균 · 사건(정답) 정의 · 학습결과 저장 | 동작 불가 |
| `detect.py` | Chronos-2 예측 → 초과확률 → 단계 판정 | 동작 불가 |
| `evaluate.py` | 사건 단위 채점 | 동작 불가 |
| `main.py` | 진입점 (`learn` / `sweep` / `all`) — **학습·평가** | 동작 불가 |
| `realtime.py` | **실시간 러너** — 매분 수집 CSV 감시 → 판정·경보 | 운영 불가 |
| `aws_idc_history_downloader.py` | (보조) DB → 날짜별 CSV | 데이터가 이미 있으면 불필요 |
| `docs/` | 설명 자료 HTML 2종 (고객용·기술용) | 실행에 무관 |

산출물
| 파일 | 언제 |
|---|---|
| `model_config.json` | 학습(①) — 임계·이동평균 창 등 판정 기준 |
| `actions.csv` · `report.csv` | 평가(②③) — 분당 판정 / 사건별 표 |
| **`ml_predict/{날짜}_ml_chronos_2.csv`** | **실시간(④) — 매분 한 줄씩 누적** |
| `realtime_state.json` | 실시간(④) — 재시작 대비 이력·경보상태 |

## 3. 실행 — 학습 → 평가 → 실시간

```bash
# ① 학습 — 기준을 뽑아 저장 (한 번만, 모델 불필요)
python main.py learn \
    --train "RAW/M16A_HUBROOM_PR_202604*.CSV" \
            "RAW/M16A_HUBROOM_PR_202605*.CSV" \
            "RAW/M16A_HUBROOM_PR_202606*.CSV" \
    --out-config model_config.json

# ② 스윕 — 모델 1회 실행으로 민감도(p_on) 비교
python main.py sweep --config model_config.json \
    --eval "RAW/M16A_HUBROOM_PR_202607*.CSV" \
    --model chronos_2 --device cuda --horizon 30

# ③ 확정 — ②에서 고른 값으로 최종 실행
python main.py all --config model_config.json \
    --eval "RAW/M16A_HUBROOM_PR_202607*.CSV" \
    --model chronos_2 --device cuda --horizon 30 --p-on 0.30 \
    --out-actions actions.csv --out-report report.csv

# ④ 실시간 — 운영. 매분 수집 CSV 를 보고 자동 판정 (Ctrl+C 로 종료)
python realtime.py --config model_config.json \
    --input predict/M16A_HUBROOM_PR.csv \
    --model chronos_2 --device cuda --p-on 0.30
#   → ml_predict/{날짜}_ml_chronos_2.csv 에 매분 한 줄씩 누적
```

**정상 동작 확인 두 줄** — ②③ 실행 시 아래가 보여야 실모델이다.
```
[모델 호출 형태] inputs 3-D (n_series,n_variates,history)
채점 — ... (backend=chronos_2)        ← baseline 이면 모델을 못 찾은 것
```

### 속도
| 상황 | 옵션 |
|---|---|
| CPU 라 느림 | `--stride 5` (5분 간격 평가, 5배 빠름) |
| GPU 메모리 여유 | `--batch 512` |
| GPU 메모리 부족 | `--batch 64` |

## 4. 현재 성적 (7월, 학습 미사용 기간)

| 설정 | 놓친 정체 | 평균 사전감지 | 10분+ 먼저 | 헛울림 |
|---|---|---|---|---|
| **민감** `--p-on 0.30` | 0건 | **9.8분** | 3건 / 4건 | 2~3일에 1번 |
| 균형 `--p-on 0.50` | 0건 | 3.8분 | 0건 | 8일에 1번 |
| 보수 `--p-on 0.60` | 0건 | 3.8분 | 0건 | 한 달에 1번 |

세 설정 모두 **놓친 정체 0건**. 설정은 "얼마나 미리 알리느냐"를 바꾼다.
데드락은 놓치면 손실이 크므로 **민감(0.30) 권고**.

## 5. 알아둘 것

**핵심 설계** — 순간값이 아니라 **10분 이동평균**으로 판정한다.
순간값으로 세면 "정체"의 78%가 1분 만에 사라지는 노이즈였고, 그것 때문에
이전 시도가 실패했다. 이동평균으로 바꾸자 657건 → 23건(평균 52분 지속)만 남았고
그중 83%가 사전 징후를 가져 예측이 가능해졌다.

**못 하는 것**
- 갑자기 터지는 정체(17%)는 원리적으로 미리 못 잡는다 → 즉시 감지로 대응
- 7월 검증 사건이 4건뿐이라 표본이 작다 → 5·6월 교차검증 권장

**실시간(④) 동작**
- 수집기가 `predict/M16A_HUBROOM_PR.csv` 를 매분 덮어쓴다 (직전 **90분** = `--context 90` 과 정확히 일치)
- 러너는 매분 `00초 + 8초`(`--offset`)에 읽는다 — 수집기 쓰기가 끝나기를 기다리는 것
- 읽은 시각이 직전과 같으면(아직 갱신 전) 2초 뒤 재확인 → 중복 판정 없음
- 자체 이력을 `--history 600`분 유지 + `realtime_state.json` 에 저장 →
  **재시작해도 10분 이동평균이 끊기지 않는다**
- 모델은 시작할 때 1번만 로드한다 (매분 로드 아님)

| stage | 뜻 | 조치 |
|---|---|---|
| 0 정상 | — | — |
| 1 관찰 | 상승 조짐 | 지켜보기 |
| **2 선제경보** | N분 뒤 임계 초과 예상 | **사전 조치** |
| 3 정체 진행중 | 이미 임계 초과 | 즉시 대응 |

**남은 작업**
1. 5·6월 교차검증 (사건 수 확보) — 명령 ②③에서 `--eval` 만 바꾸면 됨
2. 실제 사건 이력과 대조해 정확도 재검증
3. `--on-alert` 로 메신저·Logpresso 연동 붙이기

## 6. 막힐 때

| 증상 | 원인 / 해결 |
|---|---|
| `backend=baseline` | 모델 폴더를 못 찾음 → `--model /경로/chronos_2` |
| `모든 호출 형태 실패` | chronos 버전 문제. 출력된 에러 4줄을 확인 |
| `CSV 없음` | 글롭 경로에 따옴표 필수 — `"RAW/*.CSV"` |
| 너무 느림 | `--stride 5 --batch 512` |
| 사건이 0건으로 나옴 | 평가기간이 조용했거나 임계가 높음 → `--pct 0.97` 로 재학습 |
| 실시간에서 `입력 오류` | 수집기가 아직 안 돌았거나 경로가 틀림 → `--input` 확인 |
| 실시간 결과가 안 쌓임 | 수집기 파일의 마지막 시각이 안 바뀜(수집기 정지) |
| 실시간 첫 줄만 나오고 멈춤 | `--once` 를 뺐는지 확인 |
